# 多人章节回放背景时钟

TH10 四面与 TH11 六面的多人章节恢复对齐连续游玩的背景脚本和镜头插值时钟。恢复在 STD 第一个 opcode 3 初始化镜头插值后执行，使后续背景指令按对应帧推进。

TH10 接入 THPrac `th10_rep_st4bg_fix`（原入口 `4040cd`）的 29 帧校正。入口绑定在多人录像检查点和观战章节恢复；从头连续播放、正常游戏以及其他关卡保持现有时钟。

TH11 接入 THPrac `th11_rep_st6bg_fix`（原入口 `404663`）的双时钟校正规则。多人章节初始化器记录来源的背景脚本帧，恢复时使用该帧设置背景与镜头时钟，覆盖过场节奏产生的偏移。初始化器 schema 推进到 4，编码与解码共同校验新增字段。

TH11 已保存多人录像选关继续从第一帧重建全部前序输入。章节帧标记进入换面时，追帧会持续到目标关卡完成原生激活；逐帧定位保留精确帧边界，录像结束可正常退出追帧。

## 原生验证

TH10 使用实际 STD 解释器，对比连续推进 29 帧后的阶段与直接章节恢复后连续 120 帧的脚本时钟、镜头时钟、镜头位置和背景指令位置；同时检查重放同一初始状态、其他关卡与正常流程。

TH11 使用实际 Stage、STD、ANM 和回滚组件，覆盖 0、1、5、29、31 五组来源时钟，各推进 120 帧并比较脚本、镜头与指令位置；同时检查负一帧偏移、初始化器往返、旧长度数据和越界时钟拒绝。组件共通过 7 组、5,151 项检查。

新增用例分别在原实现中复现时钟不一致，在修复实现中通过。TH10 多人录像归档回归、TH11 选关激活边界、25 万帧归档与浏览器元数据检查及两作多人正式构建一并验证。结构化产物身份和目录来源证据见 [verification.json](verification.json)。
