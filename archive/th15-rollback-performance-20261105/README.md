# th15 MP 回滚性能

分支 `perf/th15mp-rollback` 基于 `3855650cf5812801fe6790d147e42908f173a606`。验收以每个实际推进帧的 P95 耗时为准：连续日志使用 4x CPU 限速，每帧强制纠正五帧使用 2x，两项预算均为 16.67ms。

## 实现

ANM 值状态与动态几何分离，快照采用每页 64 个 VM 的稳定存储并复用深层复制容量。子弹将逐帧运动、变换运行时和变换程序分开，图集、插值程序及分席位擦弹状态按单调版本刷新。公开可变引用使用完整捕获，复杂动画沿所有权图恢复。

基础演算省去已结束的变换调用、空闲插值扫描及远距离精确碰撞查询。受控 ANM 的停止指令使用独立等待路径，复杂状态交由完整解释器执行。道具沿槽位顺序更新，整页空槽直接跳过。历史 Draw 执行持久写入，最终画面再打包顶点，多人擦弹视图复用原有 VM 的临时绘制字段。

子弹更新复用玩家几何边界，整体范围之外直接拒绝，范围内再检查各席位。命中和宿主回调使缓存失效，精确判定读取实时状态。存档编码块与道具空槽按版本复用，公开记录、活动道具和道具动画逐帧复制。

参考 [th11 issue #7](https://github.com/Ritosa2333/th11/issues/7) 的稀疏写入思路，以及 [th09 世界状态](../../ports/th09/web/cpp/multiplayer/WorldState.hpp)的值状态与固定页结构。五帧纠正会重复支付基础更新成本，因此捕获与原生更新一起测量。

## 测量

驱动为 [`th15-rollback-performance.mjs`](../../tools/ports/th15-rollback-performance.mjs)，使用开发构建中的实际多人帧循环。每组采样 600 个推进帧，2 倍渲染、60Hz 呈现、BGM 关闭，音效设备与音频泵正常运行。CPU 限速由 Chromium CDP 设置。耗时包含音频泵、日志、恢复、历史重演、新帧推进及绘制提交，等待下一次显示机会的时间单独留在测量区间外。

测试使用种子 417、固定射击输入与碰撞保护，使所有席位持续参与演算。一面使用 Normal，Extra 使用对应难度。含布尔字段的结构按逻辑字段计算指纹，填充字节不参与比较。

每个样本都必须推进一帧、记录快照并提交画面。日志场景要求零次纠正；强回滚场景要求每个样本恰好一次五帧纠正。测量结束后补齐确认输入，与另一份从起点使用完整输入的执行比较规范世界指纹、确认录像输入和 canvas。实际 RTC 传输由正式 Runtime 的联机回归覆盖。

[机器记录](verification.json)保存机器、浏览器、素材、驱动和 WASM 身份，以及逐场景统计、工作计数与端点一致性。实关矩阵覆盖一面和 Extra 的双人／三人，并补测三人较晚的帧区间。人工近满池场景额外发射 1932 颗慢速子弹，单独记录预算结果。

复现步骤与环境变量见[开发指南](../../ports/th15-mp/docs/DEVELOPMENT.md#回滚与运行诊断)。
