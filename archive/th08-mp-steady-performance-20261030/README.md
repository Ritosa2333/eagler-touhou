# TH08 多人常态弹幕性能

多人回滚在不放 B 时也需要每帧更新弹幕、绘制动画并保存快照。本轮在 `ports/th08-mp` 减少远处子弹的目标排序、视口判定中的扩展精度运算，以及尚未使用的消弹动画复制；快照回收后复用录像和练习键位监视器的容器容量。

## 原生耗时

[测量数据](measurements.json)记录普通关卡和 Extra 的五组不放 B 场景。每组按 A/B/B/A 顺序切换本轮优化，先预热两种策略，再从同一原生状态各执行 8 轮、每轮 6 个逻辑帧。两人机体为 `[0, 1]`，三人为 `[0, 1, 2]`；密集场景叠加指定数量的静止子弹，原关卡脚本和玩家射击继续正常执行。

测量使用 Chromium、D3D11、原生 GPU，并设置四倍 CPU 节流。下表为原生 Update 与 Draw 的毫秒／逻辑帧，快照列为单份检查点字节数。各列直接对应同一诊断构建中的策略对比。

| 场景 | 基线耗时 | 优化耗时 | 基线快照 | 优化快照 |
| --- | ---: | ---: | ---: | ---: |
| 普通，两人，原生弹幕 | 4.071 | 3.582 | 602,170 | 601,494 |
| 普通，三人，叠加 1000 发 | 9.983 | 6.824 | 2,912,109 | 2,235,433 |
| Extra，三人，原生弹幕 | 3.953 | 3.958 | 686,561 | 685,885 |
| Extra，两人，叠加 600 发 | 6.722 | 5.215 | 1,973,774 | 1,567,498 |
| Extra，三人，叠加 1200 发 | 11.066 | 6.876 | 3,388,961 | 2,577,085 |

三组密集弹幕的更新与绘制耗时下降 22%～38%，快照体积减少 21%～24%。原生弹幕场景覆盖未叠加子弹的执行路径；收益随实际弹幕负载变化。

## 状态与边界

远处子弹排除要求所有有效玩家的命中框或擦弹框都无法接触子弹，并且没有活动消弹区域。边界附近、异常坐标及消弹区域活动时继续使用原判定。被省略调用的奖励类型重置保留原语义。

消弹动画 VM 在首次进入更新或绘制写入之前捕获，覆盖同一检查点内扩展帧、先绘制再更新、出生及槽位复用。快照池按历史窗口复用拥有独立存储的深拷贝，换面清理时释放。

五组 A/B/B/A 的恢复哈希、六帧重算哈希和游戏区像素哈希一致。视口比较与内部弹幕可见性在三种精度、四种舍入模式下分别执行 49,152 项原判定对照；整池字节恢复检查覆盖消弹动画首次写入。

两人、三人的射击、低速 B、非低速 B 和原生死亡共 8 项世界回滚回归通过；两人、三人的全部 5 个本机座位通过迟到输入恢复、音频路由及纹理恢复检查。测量范围为原生模拟、绘制与状态恢复。
