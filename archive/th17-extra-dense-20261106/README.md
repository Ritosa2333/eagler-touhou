# TH17 Extra 密集弹幕压测 · 2026-11-06

原版 TH17 1.00b DATA 在桌面 Chromium 的双人、三人 WebRTC 房运行。浏览器启用 2 倍 CPU 限速，来宾的二进制输入及补发包增加 145 ms 单向延迟和 0–20 ms 抖动。两版使用同一套实时输入脚本，各场在房间内比对已确认帧。密集组取最近确认帧在场敌弹达到 256 颗的回调，耗时和活跃堆在战斗画面内采样。

| Extra 房间 | 房主活跃 Wasm 堆采样峰值 | 密集组房主纠错 P95 | 优化版一致的确认帧 |
| --- | ---: | ---: | ---: |
| 双人 | 442.3 → 256.5 MiB | 16.1 → 10.7 ms | 4203 |
| 三人 | 489.7 → 283.4 MiB | 16.4 → 11.1 ms | 4201 |

双人房在关卡计时 2449 帧有 443 颗敌弹，在 3893 帧有 417 颗。三人房在 3323 帧有 422 颗，在 3448 帧有 656 颗。基线和优化版按相同弹量阈值汇总各自实战回调。双人密集纠错样本为 13 和 58 个，三人为 35 和 43 个。优化版两场的 Wasm 线性内存高水位均为 318.6 MiB。[基线](baseline.json) · [优化版](optimized.json)

运行时按条目读取原版 DATA，启动索引读取 3269 字节。流式读取和内存读取的 256 个条目逐字节一致。ANM 贴图上传后释放源像素，动画槽按页分配并保留稳定句柄。每轮发射共享一份变换程序，敌机改写单颗弹幕的变换时生成独立程序。动画快照记录回收槽，道具快照按实际存在的 VM 打包。
