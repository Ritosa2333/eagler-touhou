# TH14 原生安装离开与真实失焦恢复

当前独立预览补齐两项实际浏览器行为：原生字体安装中离开后可以重新启动；按住方向键切出后输入会释放，回来仍能继续游戏。没有修改游戏或启动器代码，沿用已验证的 `4f99e4da` 前端和普通运行代 `fdb227a6`，全程静音。

## 原生字体安装中离开

全新独立 Chrome 上下文明确关闭 Service Worker，使这次请求与此前的 SW 字体缓存下载区分。只在请求来自实际 TH14 iframe 时挂起其 `fonts/cp932.bin`；记录的发起文档为固定运行代的 `th14.html`，请求不属于 SW。

挂起期间刷新网页，回到启动器后重新点击启动，实际进入原生标题并正常 Quit 返回。四项流程检查通过，页面和原生错误为空，三个音量控件均为 0。安装阶段取消按钮隐藏，因此验收动作是页面导航离开，并非点击安装取消按钮。字体请求没有独立的 requestfailed 中止事件，不能据此宣称已经量测原生写入原子性、释放时刻或字体请求的 AbortError；没有覆盖音乐安装取消。

## 真实失焦释放按键

最初独立无头／有界面样本均未产生真实失焦事件，原始失败保留。本机 Playwright 的 `lib/coreBundle.js` 默认发送 `Emulation.setFocusEmulationEnabled {enabled:true}`。新的独立有界面浏览器在源页面及测试页关闭这项模拟，再通过另一个自有页面取得焦点，没有向游戏派发合成失焦事件。

普通第一关的方向输入从 0 变为 128；切出后原生输入为 0，游戏 iframe 记录真实浏览器 blur，document.hasFocus 为 false。返回后输入仍为 0，游戏从第 56 帧推进至 87 帧。源页面的 ArrowRight 抬键仅在这些断言之后发送。随后正常暂停 87 帧保持、恢复至 132 帧、返回标题及 Quit 全部通过。

60 个实际代码响应与已验证的当前包逐一匹配。页面脚本错误为空。静态预览缺少 `/api/ready`、资源路由发现端点和非 TH14 封面等 HTTP 404 仍保留，不宣称全站健康通过。

## 隐藏分支仍开放

本次切出时 document.visibilityState 仍为 visible，只计真实失焦和输入释放通过。另对自有窗口执行最小化，浏览器报告窗口状态为 minimized，页面仍报告 visible；移除三个后台相关默认启动参数的独立最小夹具同样如此。默认动画帧轮询和计时器轮询两份隐藏等待均保留失败，没有向页面伪造 hidden 或将最小化当成隐藏暂停通过。本轮停止重复这个无法产生 hidden 的方法，继续其他明确行为分支。
