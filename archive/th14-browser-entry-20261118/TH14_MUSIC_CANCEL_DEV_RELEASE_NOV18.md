## 音乐安装中的退出

源码确认 TH14 的音乐由启动器校验后直接写入现有游戏 FS，不使用字体安装的 iframe fetch 通道。因此改为在实际 OGG 的 SHA-256 已经计算完成、尚未返回给安装调用者时挂起。使用真实 1,917,229 字节 OggS 数据，返回原始摘要，不更改游戏字节、摘要、参数或会话状态；只控制异步完成时刻并旁观 FS 写入。

实际标题可操作后，按 Escape／Z 走原生 Quit，启动器关闭游戏，再放行迟到的摘要。回调确实返回，但旧游戏 FS 没有继续写入音乐。随后重新点击启动，进入原生标题并再次正常退出。五项检查通过，页面错误为空；游戏代码无需变更。这验证现有异步哈希后的会话检查能够拒绝旧会话写入，不代表全部设备音频时序或原生字体写入原子性通过。

首份 fetch 探针没有命中 TH14 音乐实际传输入口；另一份驱动在标题动画期间发送退出，未等待交互状态 2。两份失败均保留，不能当作游戏缺陷。正确驱动等待真实可操作标题后再执行退出。所有测试浏览器强制静音，三个音量控件均为 0。

通过写时复制准备目录，再用原子目录交换激活，原 `th14-site` 服务 PID 443019 和配置保持，没有重启游戏服务。源站 169 个已声明运行／前端响应通过。Windows 客户端经 Cloudflare 读取全部 68 个当前运行文件、两个前端模块及两份发布元数据，共 72 个响应，长度、SHA-256、隔离头全部匹配，Runtime 的 no-transform 保持。旧完整目录保留，可原子回滚；没有复制原作资产到 GitHub。

首次公网验证失败时已自动恢复旧包。随后 Windows 访问旧包同样返回 Cloudflare 530；隧道日志有出口不可达。仅针对已有 `th14-wth` 连接尝试 IPv4／HTTP2，TLS 握手失败后撤销临时设置；恢复原 QUIC 配置并重新连接后公网回到 200。最终没有保留传输配置变更，也没有修改凭据、域名路由或其他隧道。Arch 到公网的检查失败没有改写为成功；最终公网文件证明来自实际 Windows 客户端。
