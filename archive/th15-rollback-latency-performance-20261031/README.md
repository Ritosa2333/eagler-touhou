# TH15 多人回滚快照与本机呈现

子弹池用单调递增的内容身份复用快照中的空闲槽位，并分别保存每帧变化的运动、计时器、链表与发射时绑定的变换指令。18 段变换指令及动态载荷在身份相同时直接复用；回到旧快照后产生的新未来获得新身份。通过可变指针公开的槽位保持完整复制，支持调用方长期持有引用。章节恢复重新登记槽位身份，确认输入、游戏 RNG 与录像格式沿用原有规则。

本机回滚角色及其创建的从属动画使用最新原生 Draw 姿态，移除补帧时混合上一帧位置的视觉滞后。键盘输入在当前逻辑帧生效，改向也在当前帧生效。本机姿态随 60 Hz 逻辑更新，其余呈现继续使用已有高刷流程。

同一游戏核心与采样方法下，对照全池、全指令复制路径，四组普通场景平均快照耗时从 0.813 ms 降至 0.350 ms，降低约 57%；四组密集场景从 3.098 ms 降至 2.722 ms，降低约 12%。普通场景每组 960 帧，密集场景每组 480 帧，覆盖两人、三人、一面和 Extra；密集场景最高 2000 发子弹、约 12000 个动画节点。前后逐帧重演摘要均一致。数据见 [results.json](results.json)。

15 项原生检查覆盖动画所有权、冷槽、敌机、激光、完整战斗重演、网络回滚、预测边界和多人资源规则。附加回归覆盖不同未来中的冷槽与动态载荷、长期持有可变槽位引用、各席即时移动及当前帧网络输入的重演。浏览器通过真实 RTC 核对所有席位确认输入一致，并在补帧比例 0、0.25、0.5、0.75、1 下核对本机提交始终等于当前 Draw，游戏状态保持不变。

浏览器性能采样包含两人常规与三人 Extra、CPU 四倍降速。三客户端共用同一浏览器渲染进程，采样分别记录逻辑推进、实际呈现与回滚补算，指标保留在机器记录中。压力驱动保留真实 WebRTC 通道，与当前禁用 WebSocket 游戏输入回退的运行时一致。
