# TH12 多人 RTC 通道生命周期与可靠发送

公共浏览器传输为每个回调绑定玩家实例、主路径实例和具体 DataChannel。替换通道后，旧通道迟到的错误、关闭、打开和消息事件不能修改新通道；切换接收窗内的旧主路径消息继续进入选路模块的顺序与去重规则。当前通道的真实关闭或错误沿现有恢复与终止流程处理。

已接受的可靠控制包在浏览器拒绝发送后进入重发队列，并保留原序号。即使 TURN 备用路径尚未就绪，当前路径的定时重发也能继续交付该包；后续控制包等待重发完成，接收序列保持连续。

错误报告包含最近八条当前通道事件、RTCError 的 `errorDetail`、`sctpCauseCode`、TLS 告警字段、连接状态、发送缓冲和选路队列快照。报告不采集 SDP、ICE 地址或 TURN 凭据。

## 缺陷证据

以 `25bdb1b082d97a661c9c86289bf248ec9df5a6e4` 为修复前基线：同一连接内替换通道后触发旧通道事件，可以使健康替换通道被判为断线或接收旧消息。测试从实际 `EM_JS` 入口提取生产代码，在隔离环境执行。新守卫同时保留当前通道失败和自适应交接的处理。

另一用例在双方完成选路能力协商、备用路径尚未就绪时，让可靠发送首次抛错。基线已返回接受却没有安排重发，后续包跨过缺失的序号。修复后同一路径交付两条消息各一次，累计确认清空未确认队列。

用户提供的三人报告在正常推进至第五面后记录 `RTC peer P2 control channel error`，旧报告缺少浏览器底层错误字段。这两个确定性缺陷已经复现并修复；该报告中具体 SCTP 失败的触发原因需由保留完整错误字段的新报告判定。
