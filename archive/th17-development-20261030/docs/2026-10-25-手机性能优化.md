# 鬼形兽 WEB 1.0.5：手机掉帧排查与优化

本轮针对三、四面持续掉帧，以及魔理沙符卡、阶段结束消弹时的突发卡顿。保留默认 1280×960、640×480 切换、原版震屏、加载动画、透明混合、雾化和深度处理。没有通过减少弹幕、降低逻辑更新率或省略绘制效果提速。

## 确认的开销与修改

1. 三面等场景的世界精灵虽然使用相同的纹理和几何，但各自的纹理矩阵不同，原来的合批条件会因此拆开批次。共用渲染器现在将世界矩阵、纹理矩阵和颜色放入实例数据；仅相邻且其他状态完全兼容的四边形合并。透明物体仍按原来的顺序绘制，视图、投影、深度、目标和混合状态发生变化时仍分批。
2. 大量二维精灵仍重复上传没有使用的矩阵。现在二维路径跳过这些矩阵；实例路径从实例属性取得矩阵和颜色；雾化关闭时不提交无用雾化参数。网页每批仍用 `glBufferData` 替换缓冲存储，保留针对部分安卓驱动的处理。
3. 密集弹幕逐个设置材质时，原来会复制和比较整个管线状态。现在只比较并更新精灵实际控制的材质字段，保留外部控制的深度、雾化等状态及必要的刷新时机。
4. 魔理沙矩形消弹和阶段全场消弹原来逐次扫描整个弹幕池。现在用占用位图跳过空槽，矩形的旋转与范围参数每次查询只计算一次，空池直接返回。保留原版按存储槽位递增处理的顺序、特殊消弹阶段、保护标记、道具生成及随机数消耗；没有改用顺序不同的活动链表替代。

## 验证方式

- 原版组件对照：弹幕池分配、回收、饱和与复用；8,192 个区域消弹用例；真实弹幕场景；九种机体的战斗消弹；精灵、世界精灵、投影精灵和形状的原版绘制提交。
- 共用渲染器像素对照：分别绘制与实例合批的世界精灵，覆盖独立纹理变换、颜色、雾化、透明、深度和中途状态切换；风神录与永夜抄的既有像素样本同时回归。
- 短场景比较：七关各 900 帧普通场景与 360 帧符卡场景，实际执行 SDL3 / WebGL2 更新、绘制和呈现，记录绘制批次和真实矩阵提交次数，每 60 帧比较状态，并比较指定帧截图。
- 长流程比较：同一组固定输入、魔理沙＋野狼、显式无敌保护，完整运行 Lunatic 一至六面关卡练习以及 Extra，三次实际符卡输入，覆盖关底、阶段切换和真实退出。每 120 帧比较自机、得分、两组随机数及敌人、弹幕状态散列，并比较每关两张 1280×960 截图。它是新版与上一版的回归，不等同于全流程原版逐帧证明。
- 原版三个演示录像另外执行 20,461 帧逐帧对照。加载流程、九种角色／动物组合震屏、暂停与恢复、实际发布启动器、音频及存档分别检查。

机器上的浏览器为桌面环境，CPU 采样、GPU 查询和同时运行的任务会影响耗时。这里的命令计数、状态和像素比较用于验证改动；不能将桌面耗时或手机视口模拟换算成真机帧数，也不能保证每一款手机始终 60 FPS。

实例数据增加了每个世界四边形的纹理矩阵，因此上传字节数不一定下降；收益主要是减少小批次、状态切换和 Wasm 到 WebGL 的调用。不同场景的瓶颈和改善幅度不同。

完整压力流程合计 283,515 帧，另有 8,820 帧短场景；新版和旧版的上述状态采样与指定帧截图全部一致，未记录到 WebGL 错误。三面完整流程平均批次由 130.40 降至 83.35（约 36%），五面由 90.24 降至 36.86（约 59%）。四面达到过 2,000 发弹幕的池容量上限，仍通过相同的状态对照。数据表示这些固定输入下的工作量变化，不是手机 FPS 提升百分比。
