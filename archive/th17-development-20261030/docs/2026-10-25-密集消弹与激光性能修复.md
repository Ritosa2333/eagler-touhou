# WEB 1.0.8：密集消弹与六面激光（2026-10-26）

用户反馈 1.0.7 在四面消弹仍降到约 30 帧，六面线形「リニアクリーチャー」持续掉帧。本轮继续使用同一份原版 `Th17_ud0134.rpy`，检查四面第 14,760 帧起 540 帧及六面第 18,300 帧起 1,500 帧。默认 1280×960，真实音频输出，不减少弹幕、动画、随机数调用或逻辑更新。

## 定位和实现

上一版减少了上传次数，但相同的加法混合精灵与无纹理拖尾仍交替提交，留下大量绘制调用。拖尾还继承了上一个精灵实际不参与其着色的纹理和颜色因子。

- 无纹理、仅使用顶点颜色的形状和拖尾显式解除纹理绑定，统一未使用的颜色因子。
- TH17 单独启用密集加法混合合批：仅限归一化 8 位颜色目标、不读取已有深度、不启用抖动、不使用独立 Alpha 混合，目标系数为 One、源系数为 One 或 SourceAlpha 的加法绘制。每个区段最多允许一组兼容的深度写入绘制，保留这一组内部的原始先后顺序；遇到不兼容的深度写入时切开区段。普通透明混合、其他混合公式、依赖已有深度或更换目标均形成边界。组内保留每一条线段及每一个精灵；小于 16 个提交的区段保持原路径。其他游戏默认不启用。
- 合批后重用顶点和实例缓冲，只上传实际引用的数据，避免同时上传合并前后的两份数据。保持完整缓冲替换，不引入 WebGL bufferSubData。
- 激光圆形／矩形消弹扫描在函数局部使用最多 256 个样本的固定缓冲。原来的长度上限为 4096、样本间隔为 16，保持边界判断、扫描顺序、拆分、奖励与随机数调用，避免反复堆分配。
- 一个精灵的六个三角形顶点一次扩容、整体写入，保留顶点顺序和数值。
- 构建启用 O3 与 LTO，保留 `-ffp-contract=off`，不启用 fast-math。可用 `TH17_OPTIMIZE=baseline` 构建旧优化级别以作对照。

同一台桌面设备、硬件 WebGL2、1280×960、实际音频、逐 RAF 播放，关闭 CPU profiler；基线和候选依次运行。每个测量帧的状态均与 1.0.7 一致。这里的 GPU/CPU 时间不是物理手机帧率，单次记录也不能排除调度和设备频率波动。

| 六面 1500 帧 | GPU 平均（ms） | 8.011 | 9.356 |

四面绘制调用显著下降，两个窗口 GPU 慢帧尾部改善，但**四面仍有超预算帧，CPU 最大值也未改善；六面 GPU 平均耗时反而增加**。因此不能把这些数据描述成所有场景性能都提升，更不能宣布“全程至少 55 帧”已经达标。报告中的 `passed` 表示测量身份、状态一致性和检查流程通过，不表示满足帧率门槛。
