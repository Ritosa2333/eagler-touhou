# 鬼形兽 WEB 1.0.6：用户录像三至六面掉帧复查

本轮使用用户实际在手机播放的 `Th17_ud0134.rpy`，没有用网页导出的 `th17_01.rpy` 代替。样本 SHA-256 为 `563ddc54fcb34cf7a7ad2428ee10437c154071c2775db25e8cbdb1e486158adc`，Lunatic、魔理沙／水獭。用户要求约 55 FPS 且不出现突然降至 30–40 FPS；本轮完成可测的渲染和音频开销优化，但没有用户物理手机的测量条件，不能把桌面 Chromium 或手机视口测试当成这个帧率指标已经达标。

## 本轮修改

### 顶点上传与渲染状态

1. 旧版每个绘制批次都会替换顶点缓冲存储。TH17 现在先记录同一区段的顶点和完整绘制状态，以一次 `glBufferData` 上传连续顶点，再按原顺序绘制各批次。仍使用完整缓冲替换，不改用分段 `glBufferSubData`。
2. 清屏、换渲染目标、截图、缩放和 CPU 修改纹理前先提交积累的绘制，防止跨越资源或场景边界。纯色图形和线条保持即时提交边界；测试中发现将它们一起延迟会影响血条填充，因此没有保留该做法。
3. 实例数据仍按批上传，并使用固定的顶点属性偏移；尝试把实例数据也集中上传会增加属性重设开销，因此最终版本保留较快的固定布局。绘制顺序、批次数、透明混合结果和深度精度不变。
4. TH17 省去结果恒等的深度测试和覆盖式混合，减少重复纹理单元、清屏和状态设置；清屏会正确更新实际深度状态缓存。默认关闭集中上传的其他游戏继续使用原有路径。
5. 顶点区段最多积累约 4 MiB，避免无限增长。缓冲提交减少会增加一次 CPU 复制，收益来自减少小块上传和 WebGL 调用，并非所有场景的上传字节数都降低。

### 音频峰值

音效与音乐均已在解码器转成引擎采样率，游戏也没有动态变调，因此关闭每个声部未使用的变调重采样。维持原有 6,144 帧音频安全队列和 1,024 帧混音块，改成逐帧少量补充，消除队列下降到低水位后一次集中补充多个块的常见峰值。初始化或长时间停顿后仍允许必要的补齐。音量、曲目、循环和游戏音效触发时序没有改动。

## 有节奏的桌面对比

同一台机器、硬件 WebGL2、1280×960、实际音频设备开启，每次 `requestAnimationFrame` 更新和绘制一帧；每关取同一份录像第 1,501–2,701 帧附近的 1,200 个输入。旧版与新版分开测量，游戏状态、随机数和绘制批次数一致。

| 关卡 | 每帧缓冲替换，1.0.5 → 1.0.6 | CPU P99 毫秒，1.0.5 → 1.0.6 |
| --- | ---: | ---: |
| 三面 | 113.66 → 23.31 | 7.65 → 5.82 |
| 四面 | 45.78 → 20.12 | 6.13 → 5.15 |
| 五面 | 43.72 → 18.79 | 6.46 → 5.22 |
| 六面 | 70.05 → 26.52 | 6.95 → 5.97 |

这些片段的缓冲替换减少约 56%–79%。桌面 GPU 耗时仍有波动，部分片段没有明显改善，不能据此推算手机 FPS。四面 CPU 平均值也没有改善；表中的 P99 描述较慢的一部分帧，并不是平均帧率。

## 验证范围

- 集中上传开／关：七个关卡各 1,800 帧，1280×960 的完整像素每 120 帧比较一次，共 105 组画面，同时检查游戏状态。两种提交方式合计执行 25,200 帧，全部一致；Extra 包含实际放符卡。
- 共用后端：风神录 6 个既有画面、永夜抄 4 个既有画面与 28 个合成场景回归通过；硬件 WebGL2 的世界精灵实例化对照通过。SwiftShader 的实例化精确像素对照仍有差异，因此不能声称所有渲染驱动均已逐像素验证。
- 音频：80 个音效、18 首 OGG、循环、声道、暂停和 SDL PCM 队列检查通过。
- 用户录像一至六面的独立选关、每帧游戏状态对照已经通过。该报告使用本轮较早的开发构建，其散列保留在报告中，没有改写为最终构建；游戏逻辑在本轮未修改。最后的 Retry 菜单冻结另行检查，未将其误认为正常游戏时钟。
- 最终构建三至六面完整录像执行 107,766 帧，1,772 个游戏状态检查点通过；Extra 完整执行 81,228 帧，全程状态散列与 1.0.5 相同，峰值 1,051 发弹幕。均无现场着色器编译或 GPU 像素读回，Extra 无 WebGL 错误，原版录像无音频队列错误。结果记录在 `sdl-full-replay-performance.json`。加速执行和与其他测试同时运行的耗时仅作压力记录，不能用来计算手机 FPS。
- 加载画面、震屏及真实发布启动器重新检查通过，覆盖 640／1280、各游戏入口与重开、暂停与恢复、实际音频、返回标题音乐和文件持久化。

Extra 没有用户原版录像样本，使用魔理沙／野狼、固定移动和三次实际符卡输入，并启用明确标注的无敌保护以覆盖完整关卡。该项比较与 1.0.5 的全程状态散列，不冒充原版录像无敌关闭的逐帧一致性验证。
