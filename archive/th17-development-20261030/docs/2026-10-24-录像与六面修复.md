游戏逻辑仍为具名 C++ 组件；共享 SDL3 / WebGL2 渲染后端及启动器源码未改动。原版执行器和 DLL 仅用于离线开发对照，不编入网页。

新网页录像以标准 USER 扩展块标记规则修订 2；原加密键盘流、触控扩展和原版读取方式保持各自格式。未知或重复规则标记会明确拒绝，避免按错误规则悄悄回放。没有标记的原版录像继续按原版处理，不能仅凭文件名或录制设备猜测其来源。

这份已确认的早期网页录像没有保存错误遗留的跨关对象池，兼容回放必须从一面连续播放；选关页会显示提示并禁用后续关卡的单独恢复。这一限制仅作用于该旧样本，不影响原版和新录像选关。

`stage-gameplay-original.test.mjs` 运行原版机器码并比较生产 StageGameplay 的自机、敌人、子弹、激光顺序与位置、道具、兽灵、暴走、符卡、HUD、动画和双方随机数流。原版检查点只缓存原版执行状态；恢复后 C++ 从头执行到相同输入位置，再继续逐帧比较。报告中的 comparedFrom 与 nativeComparedFrames 区分本次真正比较的区间，不将快进区间计作本次原版对照。

`application-recording-roundtrip-browser.test.mjs` 将输入送入实际实玩与录制路径，正常跨关后导出录像，重建应用并回放。该测试不使用无敌、不强制过关；它检查录制时与回放时的每帧状态，不等于穷尽所有输入或手机 GPU。

专项回归包括真实 GameBattle 中“普通复活保留、特殊复活清除、符卡结束清除、水獭屏障保留”的组合；激光生命周期、ECL 服务调用顺序及完整录像文件的字节导出也单独与原版对照。

## 本轮结果

原版样本的前五面已完成完整原版程序对照，六面经过分段定位与末段复查，不能合并成“最新构建每帧全量原版验收”。早期长跑报告工具曾在测试结束时读取磁盘上的 Wasm 哈希，期间重建会使其无法代表实际加载的构建；这些旧报告仅保留为定位证据。当前原版比较测试改为记录实际实例哈希。最新核心 `47762301358cd38d3c7a2c6fffbf11083a870d04a2dac5c3aad386693bf33fe9` 的六面复查真正比较区间为 40,000 至 41,105 帧，共 1,105 帧，报告明确记录 comparedFrom。

正常实玩输入的六面录制共捕获 135,039 条状态，导出后用全新浏览器和 Wasm 逐面重新打开，核对 134,659 个不同的战斗帧：13,646、14,623、19,893、23,016、22,756、40,725。原版在六面结算时直接打开录像结束菜单；实玩独有的 379 帧等待／淡出和 1 条切入结局后的状态不计入战斗对照，等待段除时钟外的被测状态均保持不变。重复暂停帧不会重复计数，录像提前停滞会导致测试失败。结果见 `sdl-recording-roundtrip-original-inputs.json`。

该六面录制捕获来自应用构建 `4559d35424aa31c788b197a30bdf9b79bf333a055f677a861ac451b2dfb89ef1`，重新回放使用当前构建 `2a0571804d6327bc6fbe9f0dbc5f55571b83a054c3a4c72d1ef5ee2912debdb0`，两个身份分别保留。当前构建另做实际新录像录制、规则标记与导出重放检查，见 `sdl-recording-roundtrip-current-rules.json`。这些往返检查验证自洽性，不替代独立原版程序比较。

旧网页版样本已在实际 SDL3 应用中连续跑通一至六面，五处换关得分、残机和道具与文件中的下一关头一致，最终内部得分 48,017,231（画面显示 480,172,310）、Miss 4、剩余额外残机 3。这个结果是历史网页版兼容验收，不是该录像与原版完全一致的证明。

最终发布构建身份、正式启动器、HTTPS 和浏览器检查记录于本轮验收报告及 `reference/release-acceptance.json`。桌面浏览器测试不能替代测试组手机真机复测，也不能证明没有其他未覆盖输入造成的问题。
