# WEB 1.0.2：高清文字修复

目标仍为鬼形兽日文原版 1.00b。本次处理 Stage Practice、Replay 及其他共用小字的清晰度。

## 原因与改动

应用的逻辑画面使用 640×480，共用 SDL3 / WebGL2 后端按所选 renderScale 输出。此前即使选择 1280×960，也始终上传 `ascii.anm` 的 256×256 字库图像，所以这些文字实际只有低分辨率细节。

1280 模式现在上传原版 `ascii_1280.anm` 中的 512×512 图像。它包含六套 ASCII 字形及游戏数字；同时检查单独的 loading 图像。高清资源的 293 个图块中，部分小数字、符号和图元重新排过位置，不能仅替换图片：应用在建立动画模板之前，按高清图块设置 UV，并将矩形归一到逻辑像素。640 模式继续加载自己的原版图像。

原版的逻辑动画脚本、文字间距、排版和输入时钟继续保留，模板只初始化一次。AnmManager 增加接收已解析资源的加载入口，字节加载入口复用相同的模板初始化流程。渲染后端、着色器、顶点提交和帧调度没有更改，也没有接入 D3D8/9 运行时。

同一资源的使用者一起生效：选关、录像列表、成绩、统计、部分暂停及保存界面小字、HUD 数字、浮动分数和帧数。对话、符卡名等动态日文字体走独立的 FontDevice 流程，继续使用原版测量字形。

## 验证

- `application-text-resolution-browser.test.mjs`：实际完整 SDL3 应用，分别以 640×480 和 1280×960 初始化。GraphicsDevice 持有的字库图像逐字节哈希与对应原版 THTX 位图一致，全部 293 个图块的 UV 和逻辑矩形与相应原版资源一致。1280 模式进入战斗和暂停后仍保留同一高清资源。
- 截图检查：两种分辨率的 Replay，以及 1280 模式的 Stage Practice、成绩、符卡统计、游戏 HUD 和暂停，共七张。路径见 `artifacts/cpp/verification/sdl-application-text-resolution.json`。
- `ascii-text.test.mjs`：原版程序独立对照 1,296 组，覆盖三个原版分辨率字库、六套字形、标点、换行、对齐、缩放、阴影、队列寿命及 CPU 顶点，共 38,016 个字形、349,920 项检查，通过。
- 正式包的文件哈希、源码身份、共用架构、HTTP 隔离，以及桌面和手机尺寸浏览器启动、选人、游玩、暂停、返回标题、音乐和存档检查，记录于 `release-integrity.json`、`production-launcher.json`。上线后的 HTTPS 检查单独记于 `public-http.json` 和 `production-launcher-public.json`。

这些检查验证原版字库来源、图块映射、排版和具体浏览器路径；不代表所有界面逐像素完全相同，也不替代测试组的手机真机验证。之前录像与游戏逻辑的长跑报告保留各自原始构建身份，本次不把它们改写成新构建的全量原版录像验收。

正式版本号、日期和本轮构建身份见 `reference/web-release.json`、`reference/release-acceptance.json`。启动器更新日志和左上角版本号同步为 WEB 1.0.2。
