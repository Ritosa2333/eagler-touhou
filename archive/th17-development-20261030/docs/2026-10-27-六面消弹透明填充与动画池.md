# 六面消弹透明填充与动画池复查

用户在 WEB 1.0.13 上用 `Th17_ud0134.rpy` 测试，六面线形造形术仍出现持续约 50 帧和 30–50 帧波动。本轮以这份录像为输入；桌面正常不能作为手机验收结论。

录像 SHA256：`563ddc54fcb34cf7a7ad2428ee10437c154071c2775db25e8cbdb1e486158adc`。

## 定位

六面世界帧 18286 有 12,722 个 `effect/etbreak.png` 精灵四边形，总逻辑覆盖面积约 20,809,000 像素。其 64×64 图块实际非零 alpha 占比约 2.3%–20.8%。原绘制仍对整块透明边缘执行片元工作。逐 draw GPU 计时用于定位，不作为帧率测量。

动画固定池的节点原来在战斗中逐个分配；超过 16,383 个槽位的节点还会反复申请、释放。每个等待中的 VM 还检查十二个插值器及重复计算未变化的旋转角。纯 2D 合成目标也存在不需要的深度附件绑定。

## 修改边界

- 仅对内嵌、尺寸和 UV 可验证的纹理记录透明外边界，保留邻接 texel 和两像素余量。裁剪仅作用于无梯度、标准 UV、开启非零 alpha 测试、不开深度写入的普通精灵。保留原 VM 四边形、继承颜色、材质顺序、动画和随机数。
- 高精度替换图集、动态更新纹理及渲染目标使透明边界缓存失效。
- 固定池改为一次分配连续节点；溢出节点复用但恢复新建 VM 状态，保持原槽位、句柄代数、释放和更新顺序。
- 按原浮点位模式缓存旋转正弦/余弦，仍执行父节点旋转归一化。缓存活动插值器，在指令和外部写入路径失效，仍执行每个活动插值器的原运算。
- TH17 已启用的延迟深度清空路径避免给纯 2D 目标创建无用深度附件；实际深度消费者仍按原先清空、共享和读取顺序执行。

默认仍为 1280×960。没有删弹、删特效、跳过游戏更新、改录像输入、伪造 FPS 或改变帧率上限。

同一段六面 17341–20041，真实浏览器 RAF、音频开启、1280×960、桌面 CPU 四倍限速，GPU 测量每 60 帧一次。构建、GPU 工作及压力测量串行执行。

## 图像与回归

透明边界裁剪会轻微改变 GPU 插值舍入，不能标为逐像素完全一致。先行三个六面点最大通道差为 3/255，未发现超过 4/255 的像素；广泛复查将全部差异和失败点保存在 `artifacts/performance/particle-final-pixels`，预先声明的范围是最大通道差不超过 4/255，平均差不超过 .02/255。

固定池/溢出复用、原版 ANM 解释、插值、模板、登记和四种绘图路径共 15 项测试已通过。6 组深度缓冲语义与即时清空对照的画面哈希完全一致。

全录像、Extra、最终候选、发布与公网状态以 `artifacts/performance/particle-final-verification.json`、`reference/release-acceptance.json` 的最终记录为准。本文件不把尚在运行的检查写成通过。

没有连接物理 Android 设备。手机最低 55 帧、手机持续约 50 帧消失两项验收仍未完成。

另测了将普通精灵分发与特殊形状绘制拆开的候选（`particle-draw-candidate`）：同段真实 RAF 平均 58.30 FPS，CPU 平均 9.58 毫秒，P95 18.06 毫秒、最大 45.67 毫秒，未比池优化候选取得稳定收益，因此未保留这项源码改动。正式候选仍是 `particle-pool-candidate`（`068812fea3ae8df71158e639941a504d7fc50bd2e1c9792cf2a28767a60e437c`）。

47 个图像点全部通过预先声明的舍入差异范围，最大通道差 4/255；所有捕获状态一致。四五六面 86,874 次更新、1,450 个检查点与原基准一致；Extra 81,228 次保护输入的完整摘要仍为 `29cc1179db215873f366b4e173dd0208679025373f0293bbd2f008eb4f2c4a72`。
