# TH08 键盘输入所有权

输入法组合输入、快捷键和编辑控件的按键交由启动器映射统一处理。映射层拒绝的按下事件沿同一输入边界结束，松键随对应所有者释放，支持方向键、Shift 和射击连续操作。

卡键来源是两条输入路径错配：被映射层拒绝的 DOWN 曾进入原始键盘路径，后续 UP 被映射层接收，原始路径因而一直保留按下状态。单人、多人使用同一修复规则，事件在原调用栈完成。

映射接入、撤下、epoch 失效或更换键位时，输入桥接先释放旧映射与原始路径保留的按键，再交接后续事件。相同映射持续处理输入时保留长按状态。

## 验证

- 41 项键盘所有权、映射、焦点、THPrac 契约测试通过。
- 单人 10／10、多人 9／9 源码检查通过。
- 生产运行时的浏览器回归覆盖单人、多人各自的旧版与修复版。旧版在组合输入、快捷键和文本编辑三种路径均复现松键后 C++ 键值仍为 128；修复版全部归零。
- 单人、多人分别验证映射接入、撤下、失效和更换键位四种交接；旧版保留值 128，修复后归零。
- 每个浏览器用例执行 90 次普通按下／松开，验证左右 Shift 独立释放、失焦清除、失焦后的旧重复事件及重新按下，并检查浏览器实际键盘事件。

浏览器夹具完成原生初始化后结束菜单计算，保留生产 SDL 轮询与 C++ 键盘表，核对 DOM → Launcher → shell → SDL → 原生键值的完整输入链。完整结果与生产 Wasm 身份见 [validation.json](validation.json)。

复现入口为 `ports/th08/portable/check-keyboard-browser.mjs`，多人源码接收同一夹具。使用环境变量提供原始游戏 DATA、共享字体和普通／多人运行目录；原始游戏资源独立保存。
