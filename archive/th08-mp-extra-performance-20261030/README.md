# TH08 多人消弹性能与 ECL 目标选择

源码范围为 `ports/th08-mp`。多人敌机脚本、子弹和激光采用同一套最近有效玩家规则；亡灵和死亡动画中的玩家退出瞄准候选，距离相同时按座位顺序选择。每个敌机 VM 在执行主脚本、异步脚本和移动之前保存自己的目标坐标，嵌套生成的敌机拥有独立目标。普通版源码保持原有行为。

消弹判定先用包含完整形状的宽松包围盒排除远处子弹，近处子弹继续执行原有圆形、矩形或旋转矩形判定。两个单位的边界余量覆盖常规坐标中的浮点舍入；超出常规数值域的输入直接执行原判定。消弹区域的顺序、命中计数和奖励归属保持一致。

回滚的主状态、敌机、道具、特效和动画资源在同步只读窗口中批量复制。窗口在游戏更新前关闭，首写钩子继续即时保存修改前状态。复制内容和恢复顺序保持一致。

## 原生耗时与恢复验证

[测量数据](measurements.json)记录同一诊断 Wasm 中的 A/B/B/A 对比。基线关闭本轮批量复制与消弹包围盒，优化组开启两项功能；每个窗口都先恢复同一份原生状态，并比较完整恢复哈希与重算结果。使用实际 Extra 脚本、1000 发静止弹幕、两人及三人机体组合，分别覆盖放 B 前、放 B 后 24 帧和后续 60 帧。

三人组合为 `[2, 3, 10]`，以下单位为原生 Update 与 Draw 的毫秒／逻辑帧：

| 场景 | 原判定 | 优化后 |
| --- | ---: | ---: |
| 非低速 B，生效窗口 | 2.653 | 1.460 |
| 非低速 B，后续窗口 | 5.461 | 1.829 |
| 低速 B，生效窗口 | 2.537 | 1.503 |
| 低速 B，后续窗口 | 5.411 | 1.751 |

测量环境为 Chromium、D3D11 和原生 GPU，指标为逻辑帧 CPU 耗时。12 个 Extra 窗口的基线与优化组恢复、重算哈希一致；圆形、轴对齐矩形及旋转矩形的保守排除检查通过。两人和三人的射击、低速 B、非低速 B、原生死亡共 8 项世界回滚回归通过，最终诊断构建另行复核三人低速 B。

ECL 目标检查覆盖两人和三人、P2 比 P1 更近、P1 死亡、P1 进入亡灵、P1 恢复可用，以及全部 9 个关卡编号。玩家坐标变量、角度和距离读取、追踪移动、发射保护距离及激光方向均使用各自 VM 的目标样本。

迟到输入使用当前网络会话封套重放，覆盖两人及三人的全部 5 个本机座位。预测、恢复、重算、原生音频路由和纹理恢复检查通过。
