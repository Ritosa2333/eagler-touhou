# TH17 Extra 关底全程回滚压测 · 2026-11-06

三席使用 TH17 1.00b DATA，在同一 Chromium 实例中分别运行 Wasm，并通过 WebRTC 数据通道交换输入。来宾席二的输入和补发注入 145 ms 单向延迟及 0–20 ms 抖动。两轮从第 9000 个确认帧起应用 2 倍 CPU 限速。独立诊断包提供固定输入与碰撞保护，原版 ECL 运行敌机、弹幕和符卡。

## 活跃堆与快照

上轮记录的 313.3 MiB 和 323.6 MiB 分别取自两轮独立采样的密集段峰值。本轮按模拟帧号、敌弹数、激光数、符卡号和保留的快照数配对。活跃堆使用 Wasm 分配器的 `uordblks`。快照数组容量统计记录本身，包含共享记录的引用，动态子对象和共享副本本体的内存计入活跃堆。冗余容量统计动画注册表与弹幕视觉数组的空位。第 14926 帧起作为关底后半区间，密集组从 256 颗在场敌弹起计。[上轮记录](../th17-extra-boss-20261106/README.md)

基线中，「鬼形的乌合之众」第 26728 模拟帧有 1979 颗敌弹，六份快照的数组冗余容量合计 6.06 MiB。绘制列表还可引用已退役动画，精确分配在把这些节点计入后预留快照容量。「鬼畜生之所为」第 27752 模拟帧的十二份快照含 31.47 MiB 闲置道具动画记录。回收槽在仍被快照引用时共享动画副本，复用槽会重新捕获动画状态。

## 快照与纠错耗时

房主密集区段每次快照平均耗时从 3.15 降到 2.68 ms。纠错回调中位数为 9.66 → 9.47 ms，P95 为 12.32 → 13.16 ms。实际绘制每次平均 1.19 → 1.25 ms，逻辑绘制每次平均 0.46 → 0.47 ms。两轮密集区段分别取到 1115 和 1146 个纠错回调。

正式普通版和多人版 Wasm 均通过构建。正式多人包的 Extra 双人、三人房分别核对 1055 和 1051 个确认帧，两房均发生迟到输入回滚。[正式包开房记录](production-smoke/room-report.json) · [正式包 RTC 路由](production-smoke/relay.log)
