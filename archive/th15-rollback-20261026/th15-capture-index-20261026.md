# TH15 多人快照：连续捕获索引

动画快照用保留容量的连续地址表定位节点，替代逐节点哈希索引与过期条目清理。索引每帧重置，保留第一次插入的位置；容量不足时自动扩容并重新登记已有键。父子关系、两组回调顺序、图层顺序与全部 VM 值继续完整保存。

基于 `552a24312` 的四组密集场景各做两轮交错 Release 测量，平均捕获耗时从 4.121 ms 降至 3.920 ms，节省约 4.9%。测得进程内存峰值从 851169280 字节到 849960960 字节。每组覆盖 480 帧、两人或三人、一面或 Extra、最高 2000 发弹幕与约 12000 个动画节点，精确重演全部一致。

检查覆盖索引碰撞、自动扩容、重复键、清除前帧键与容量复用，以及重复根、空根、已注册根和根顺序变化。全套 10 项原生回滚检查与生产配置浏览器多人验证一起核对句柄、嵌套所有权、冷槽和确认输入。

具名函数的独立分析构建提供调用栈线索：35 秒三人弱网 CPU 采样中，通用字节数组赋值函数约占 2.76 秒采样时间，记录表赋值约占 0.49 秒。调用栈落在多人主循环的内联路径，后续优先细分具体状态对象与复制频率。背景 VM 的重复快照和资源租约临时容器属于另外两处候选。性能对比使用交付构建，采样工件单独记录构建身份。

本轮交付构建 WASM 的 SHA-256 为 `0950eeb9d2d502dad36e2936ed20e41dfb2d9995ff00f72b26c4dacd363a4914`。

最终构建通过全部 10 项原生检查，以及三人 Extra 正常、CPU 六倍降速、弱网三组浏览器验证，各席确认输入一致。相邻慢 CPU 对照的推进帧率分别为 8.03 与 8.01 fps，当前测量没有显示整体帧率提升。
