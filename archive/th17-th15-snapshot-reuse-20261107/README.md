# TH17 多人快照缓冲复用 · 2026-11-07

TH15 的动画和弹幕快照保留容器容量，复用地址索引与槽位存储。TH17 沿用这一做法，让全房的快照槽借用已释放的动画与弹幕缓冲。采集仍保存动画节点、父子关系、绘制层、插值器和弹槽顺序。有效快照独立持有数据，释放后归还一份同类型缓冲。每类空闲缓冲的保留容量以 256 KiB 为限。[TH15 回滚性能](../th15-rollback-performance-20261105/README.md) · [TH15 快照容器](../th15-rollback-20261026/th15-rollback-allocation-20261026.md)

## 固定负载

原生驱动使用 256 个动画节点、108 发弹幕及 13 槽历史。先预热 130 帧，再采集 6,000 次。每 37 帧执行一次恢复，每帧释放五帧前的快照。两种实现交错各跑四轮。分配量为测量区间内 `operator new` 请求的累计字节数。

| 实现 | 分配次数 | 累计分配字节 | 总耗时中位数 |
| --- | ---: | ---: | ---: |
| 重新分配容器 | 90,000 | 2,040,966,000 | 330.965 ms |
| 全房共享缓冲 | 36,000 | 6,048,000 | 318.996 ms |

原生用例还覆盖相邻快照并存、释放后重新捕获、动画父子关系和弹槽顺序。[固定负载记录](shared-allocator-bench.json) · [逐槽复用对照](ring-allocator-bench.json) · [驱动](allocator-bench.cpp)

Windows 使用同一工作树中已经构建的 Clang、Ninja 原生多人测试目录。运行 `python archive/th17-th15-snapshot-reuse-20261107/build-allocator-bench.py <原生构建目录> <输出目录>`，交错执行生成的两个基准程序。脚本用同一编译参数分别链接旧快照实现和当前实现。
