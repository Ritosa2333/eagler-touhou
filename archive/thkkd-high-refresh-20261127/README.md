# 東方海恵堂高刷新率与插帧

本轮在 r7-final（`63a593f7`）基础上完善 normal 网页单机的高刷显示。游戏逻辑保持 60 Hz，额外画面使用相邻快照的运动向前预测最多一帧；精灵位置、旋转和缩放由 GPU 计算。当前图集帧按逻辑切换，移动继续平滑；出生、瞬移、图元分段和场景变化按各自边界重置。

新快照准备并上传一次顶点，额外呈现复用 GPU 缓冲。关闭高刷新率时使用原顶点布局。回放在暂停恢复、切速和定位时重新建立显示时刻，结束立即冻结画面；无 BGM 模式的定位与推进处理空音乐句柄。

## 验证范围与结果

| 项目 | 操作与结果 |
| --- | --- |
| 普通游戏帧循环 | 60、75、120、144、165、240、360 Hz，各测显示限频开关，14 个组合均执行 180 个逻辑步，状态摘要相同；显示次数随开关与刷新序列变化 |
| 原生录像 | 同一输入在模拟 60、120、144、240 Hz 下均执行 359 步并结束，最终状态相同；暂停、定位、恢复、EOF 及无 BGM 定位通过 |
| 原始画面 | 三种代表机体的实际逻辑帧与 r7 逐像素一致；九机体的子弹、激光、附属物和道具显示检查通过 |
| GPU 几何 | 旋转跨越 ±180 度、旋转与缩放组合、不同锚点，与目标几何逐像素一致；图集换帧、圆形分段变化及离散边界通过模块检查 |
| 辅助对象池 | 定点构造第 0、7、31 槽，在两个正式 C++ 绘制层检查连续移动、出生复用、瞬移与退出，共六个组合通过 |
| 额外绘制 | 固定画面重复呈现保持完整 WASM 内存不变；4952 条命令的快照额外呈现 240 次，顶点上传从 240 次降为 0 次 |
| 顶点与批次 | 1800 条命令、七个显示进度、4800 条精灵命令核对当前帧属性、Float32 精度内的位置、绘制顺序和 GPU 状态；小规模实际场景复核通过 |

浏览器使用独立后台 Edge 和专用数据。上述刷新率属于可重复的时间序列与后台浏览器检查，实体高刷显示器的体验继续保留在 DISPLAY-02、DISPLAY-08、REPLAY-07 验收项中。CPU 计时记录 JS 呈现调用开销，GPU 异步执行与实际显示器帧率分别观察。

## 测试选择与结果复用

生产 `src/` 文件与 normal WASM 均保持 r7 原字节。固定原版 60 用例、835289 逻辑步，以及 Omniverse 结算、输入、资源转换、存档和本地进度的相关记录复用 [r7 验收](../thkkd-adaptation-20261127/README.md)。本轮新运行显示边界、帧循环、GPU 像素、辅助池、无 BGM 定位与交付检查。

诊断构建提供定点设置状态的入口，浏览器驱动检查 normal 模块没有这些测试写入接口。两者分别保存构建身份；最终 Runtime 包含 normal 运行程序。

结构化数据见 [validation.json](validation.json)。复现命令见[开发指南](../../ports/thkkd/docs/DEVELOPMENT.md)，显示机制见[显示说明](../../ports/thkkd/docs/RENDERING.md)。
