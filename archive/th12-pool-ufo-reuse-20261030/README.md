# TH12 弹幕索引与 UFO 特效快照复用

普通版与多人版重建弹幕指针时，复用仍存活 ID 的索引节点，用交替标记删除本轮消失的条目。同步出生、重复 ID 的最后写入规则、物理槽位顺序、消弹效果缓存和分配游标保持一致。新增与退场仍按实际生命周期处理，稳定场景无需逐帧销毁并重新分配整张索引。

多人 UFO 特效快照复用同 ID 的独立状态对象，完整复制其数值并删除源快照已无的条目。回滚后继续按原来的动画回调执行，保留轨迹、顶点颜色、出生／到期顺序和随机数输出。普通版没有这条深复制快照入口。

| 1,000 次稳定操作 | 基线耗时 | 复用耗时 | 临时分配：基线 → 复用 |
| --- | ---: | ---: | ---: |
| 1,000 颗弹幕的索引重建 | 61.589 ms | 12.592 ms | 1,000,000 → 0 |
| 192 个 UFO 特效状态复制 | 34.487 ms | 3.940 ms | 384,000 → 0 |

基线为 `8a43de5c`，同一 Windows 主机采用 MinGW GCC 16.2.0、CMake Release（`-O3 -DNDEBUG`）构建，七轮交替运行取中位数。基线与新版使用相同夹具及运行库，链接时替换完整的基线组件实现。[performance.json](performance.json)包含逐轮测量，索引输出哈希为 `7c60c9e99f02e66e`，UFO 轨迹输出哈希为 `786c9a2270d7459b`。测量范围为两个 CPU 组件；整场帧率由设备、场景和网络共同决定。

两侧的 `tests/native/hostile-pool-storage.cpp` 使用旧版完整重建算法作参考，覆盖 2,000 个槽位、同步出生、重复 ID／槽位、零与最大 ID、空列表、失效条目、容器压缩和完整换批。多人额外覆盖双人／三人的世界回滚，恢复后逐槽核对指针、阶段、消弹缓存、游标和旧 ID 清理。

多人 `tests/native/multiplayer-ufo-storage.cpp` 覆盖快照独立性、对象身份复用、条目增删、自赋值、空快照，以及双人／三人恢复后的 70 帧动画、网格与随机数轨迹。原生检查普通版 2/2、多人版 6/6，接口检查 25/25，两侧生产 SDL Web 构建通过。[verification.json](verification.json)登记执行范围与构建身份。
