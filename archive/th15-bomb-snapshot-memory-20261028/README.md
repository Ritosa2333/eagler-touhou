# TH15 多人放雷快照内存峰值

动画快照使用稳定的小块存储，放雷消弹时直接增加所需 VM。13 帧回滚窗口保留完整状态、冷道具动画和生命周期映射，增长过程无需同时持有两整块 VM 数组。

用户报告为双苗机 Extra 关底五非放雷，WASM 从 911540224 字节扩到 1073741824 字节后退出。下载的正式包与报告 SHA256 一致；调用点 `0x13c666` 向 `operator new` 申请每元素 1496 字节的根快照数组，与同源码的 `RootImage` 布局相符。

## 验证

| 检查 | 结果 |
| --- | --- |
| 2048 根增加到 2049 根 | 原生旧实现申请约 4.7 MiB，新实现约 24 KiB；旧实现被新增内存边界检查拒绝 |
| wasm32，8193 根、13 份快照 | 保留数据 322279282 → 162981026 字节；最大单次申请 24510464 → 131072 字节 |
| 实际原生与 wasm32 战斗状态 | 各 432 次重演逐帧一致，包含双苗机 Extra、移动与放雷、12 帧错误未来回退 |
| 图与生命周期 | 句柄、父子关系、嵌套动画、冷道具 VM、RNG 和呈现身份检查通过 |
| 正式多人包 | Emscripten 6.0.9-git 完整构建通过 |

[机器记录](verification.json) 保存报告摘要、正式包身份、调用点与测试范围。[增长夹具](snapshot-growth-profile.cpp) 直接使用实际 `AnimationState`，测量 13 份动画快照；完整战斗对照从原生关卡主入口推进，不代替报告中第五非符的录像复现。

回归入口：`ports/th15-mp/portable/rollback/animation-state.cpp` 与 `battle-state.cpp`。普通版源码保持原有实现。
