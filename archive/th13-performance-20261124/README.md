# th13 热路径优化（2026-11-24）

每帧逻辑时间决定补帧和多人回滚的预算。此前没有按函数的耗时数据，优化只能凭直觉挑地方。这次给 WASI harness 做了带函数名的剖析构建，对录像逐函数计时，按数据定位并消除了逻辑帧里最大的一处纯冗余计算：旋转碰撞盒判定。普通版与多人版同步落地，三项回归摘要逐位不变。

## 方法

- **剖析**：`portable/build-harness.mjs` 的链接参数加 `-g`，`node --cpu-prof` 采样，回放 `th13_udWi11`（约 2.5 s）与 `th13_01`（约 8.0 s）。
- **计时**：交替 A/B——基线与改动版交替构建、交替运行 3 轮，取中位数。同一台机器在不同时刻的绝对耗时相差可达一倍，只有交替测量才能比较。
- **保留条件**：三项回归摘要不变、门槛无新增失败、交替 A/B 有实测收益，三条同时满足才进仓库。同一口径筛过弹幕排序的两个候选（交替 A/B 变化 0%），保持原实现。

## 改动

`shot_hits_enemy_box`（`web/cpp/game/StageBattle.cpp`）判断自机子弹与敌机碰撞盒是否相交。敌机带旋转角时，每次判定都要算 `sin`/`cos`，再把中心和两条边投影到子弹坐标系。弹幕密集时绝大多数子弹离敌机很远，这些三角函数是纯浪费。

现在先比较中心距离与保守界，够不着直接返回：界是双方包围盒之和的外接圆，半径平方留 0.01% 余量覆盖 `sin`/`cos` 的浮点误差。原判定命中的点必然落在界内，所以不会漏判；NaN/Inf 落入原判定。通过粗筛的子弹走原判定，代码未变。两侧函数逐字节一致。

## 构建与验证范围

测量对象是 `th13-dev` 容器内的 WASI harness 回放耗时，输入是外层工作区的两份录像。等价性覆盖三项回归摘要（10 份录像）与两个端口的全部套件，门槛结果见 [gate-summary.txt](gate-summary.txt)。
