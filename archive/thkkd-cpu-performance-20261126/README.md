# 海惠堂单机性能实测

本轮从本地单机交付包启动正式网站与 Runtime，在默认 60 Hz 显示限制下，分别测量正常 CPU 和浏览器 4 倍 CPU 限速。每组采样 900 个真实逻辑步，保留画面提交与逻辑步进两个独立计数。

设备为 Intel Core Ultra 7 155H（16 核、22 线程）、32 GB 内存、NVIDIA GeForce RTX 4060 Ti，Windows 11；浏览器为 Edg/158.0.4370.33，使用隔离的临时配置与无头模式。视口为 1280×900，游戏绘图缓冲为 640×480。4 倍设置通过 Puppeteer 的 Chromium 调试协议施加，GPU 设置保持一致。

| 场景 | CPU 档位 | 画面 FPS | 逻辑步/秒 | 样本秒数 | 核心调用平均 / P95 毫秒 | 呈现间隔 P95 毫秒 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 标题 | 正常 | 60.03 | 60.03 | 14.993 | 1.25 / 1.50 | 22.00 |
| 标题 | 4 倍限速 | 59.16 | 60.03 | 14.994 | 6.30 / 7.40 | 19.60 |
| 实际一面开场 | 正常 | 59.94 | 60.00 | 14.999 | 3.44 / 4.10 | 17.30 |
| 实际一面开场 | 4 倍限速 | 5.27 | 60.05 | 14.987 | 15.32 / 17.60 | 244.60 |
| EX 密集回放 | 正常 | 60.01 | 60.01 | 14.998 | 4.04 / 4.70 | 17.50 |
| EX 密集回放 | 4 倍限速 | 28.60 | 28.60 | 31.470 | 20.88 / 23.90 | 50.70 |

画面 FPS 按 Renderer.present 的实际 WebGL 提交次数除以墙钟时间计算；逻辑频率按 WASM 的 _thkkd_step 调用次数计算。核心调用包含本步游戏更新、原生显示计算及绘图命令生成。游戏场景另行核对 Replay 游标消费数量，每组均为 900。资源安装、计算校准、定位和预热位于采样窗口之外。

开场的 4 倍限速样本提交 79 次画面、执行 900 步逻辑，画面出现明显卡顿；其平均核心调用为 15.32 毫秒，主循环优先补逻辑后再提交画面。EX 的 4 倍限速样本提交 900 次画面、执行 900 步逻辑，总耗时 31.47 秒，实际播放速度下降。正常 CPU 的三组样本均约为 60 FPS、60 逻辑步/秒。

开场窗口为游标 120→1020；EX 使用已有授权录像的游标 50120→51020，敌弹从 460 个增至 563 个、绘图命令从 544 条增至 647 条。两档的开场与 EX 起止随机状态、玩家数据及活动对象摘要分别一致，测量期间原生场景保持游戏状态。原始录像保留在私有归档，交付包排除原始录像。

限速校准采用同一 iframe 内的固定 1200 万次整数计算。正常档中位耗时 14.30 毫秒，4 倍档 62.35 毫秒，实测比值为 4.36，两档计算结果一致。浏览器页面异常与非预期 Runtime/音频错误均为零；静态服务的地区、账号就绪和资源路由探测 404 保留在原始报告中，游戏使用本地 DATA 与 Runtime。
