# 回滚零输入延迟与 TH12 采集开销

回滚房间统一以 0 帧输入延迟开局。TH12 普通版与多人版同时减少画面采集分配；生产 Wasm 的同帧配对对比中，Boss 场景采集平均耗时由 0.924 ms 降到 0.839 ms，采样画面逐像素一致。

## 输入时序

删除 TH09 的 `manualRollbackDelay` 例外，启动器、房间开局请求和 relay 均将回滚输入延迟归零。关闭回滚时保留原来的纯延迟设置；重新开启回滚后，隐藏的旧设置不会进入开局参数。旧混合模式开局请求继续归一为直接回滚。历史回放格式及其解码保持原有语义。

## TH12 性能归因

单人运行已出现画面采集成本高于单次逻辑更新的情况。生产普通版 Wasm、真实六面 THPrac 分段 45、苗 B、锁定 60 Hz 呈现，4 倍 CPU 限速的独立采样呈现约 48.65 FPS，逻辑更新约 59.90 Hz；采集均值 6.04 ms、P95 13.0 ms，逻辑均值 4.28 ms、P95 10.6 ms。该场景不依赖高刷或多人传输即可超过呈现预算。

多人还承担预测快照开销。原生构建以真实六面 Boss、双人／三人苗 B 持续射击运行 1200 帧，保留 13 个状态槽，测试期内每 120 帧恢复并检查哈希；有无快照的最终世界哈希相同。

| 人数 | 回滚采样中的逻辑均值 | 快照均值 / P95 | 恢复均值 / P95 |
| --- | ---: | ---: | ---: |
| 2 | 0.548 ms | 0.410 / 0.860 ms | 0.956 / 2.130 ms |
| 3 | 0.813 ms | 0.520 / 1.216 ms | 1.160 / 2.473 ms |

这是当前源码的原生状态成本测量，不是浏览器联机帧率。三人每个预测帧的快照约增加相当于一次逻辑更新 64% 的 CPU 工作；发生输入纠正时，`Session::step` 还会恢复世界并执行最多 12 帧重演及一帧新模拟。共享采集／绘制与预测状态成本因此需要分别处理。此轮优化降低前者，没有改动模拟、碰撞、快照语义或回滚预算。

## 共用采集优化

- ANM 二进制读取改用三个类型视图，避免为每个姿态创建三个字段读取闭包。
- 复用采集临时 owner 集合，直接遍历姿态和网格填充。
- 将兼容绘制记录的导出移到所有元数据读取之后；在没有 Wasm 调用的循环里消费原始视图，直接把数值写入端点。省掉每次采集的整块字节复制，同时确保后续导出、内存增长和下一帧不会改写旧端点。

配对测量在同一页面、同一核心状态下交替执行基线与候选采集及绘制，预热 120 帧，测量余下 480 帧。四个采样点同时核对完整呈现端点与 RGBA 像素。

| 场景 | 基线采集均值 | 候选采集均值 | 基线 / 候选 P95 |
| --- | ---: | ---: | ---: |
| 六面 Boss，CPU ×1 | 0.924 ms | 0.839 ms | 1.70 / 1.40 ms |
| 六面 Boss，CPU ×4 | 16.648 ms | 15.804 ms | 33.30 / 29.60 ms |
| 苗 B 射击并放雷，CPU ×4 | 21.947 ms | 21.189 ms | 43.70 / 41.10 ms |

三组共 12 个采样点的端点一致、像素差异均为 0。CPU ×4 的配对运行会在每次逻辑更新后绘制两份画面，其耗时用于配对比较，不用于认定实际游戏 FPS。独立采样受到运行负载影响，`measurements.json` 保留所有运行结果，不以分开运行的前后 FPS 推断收益。浏览器为 Chromium 153.0.8010.12，GPU 为 RTX 5080 Laptop；这组数据用于定位及比较本机路径，设备上的最终流畅度仍需实际游戏验证。

## 验证与复现

- 普通／多人渲染、二进制 ABI、插值、图层、像素取整、绘制次序与内存增长回归：120 项通过。
- React 房间交互：44 项通过，包括 TH09 隐藏 1 帧设置不进入回滚开局、纯延迟恢复原设置。
- 启动器 Runtime 参数、TH11／TH15 策略及本地 relay 产品策略通过；启动器 UI 与工具类型检查通过。
- [结构化度量及生产核心哈希](measurements.json)、[原生状态采样](native-profile.txt)、[原生采样源码](native-profile.cpp)。

配对浏览器采样使用 `tools/ports/th12-byakuren-profile.mjs`：设置 `TH12_PROFILE_RUNTIME` 指向生产 `core.mjs`、`core.wasm` 及 `build.json`，`TH12_PROFILE_ASSETS` 指向本地提取的 TH12 资源，`TH12_PROFILE_COMPARE=1`，`TH12_PROFILE_FRAMES=600`。`TH12_PROFILE_CPU_RATE` 可设 1 或 4；`TH12_PROFILE_BOMB=1` 启用苗 B 射击及第 300 帧放雷。复现本记录时设置 `TH12_PROFILE_BASELINE_REF=654717ac6d7b0f9e28239e230d5c965025493434`，工具从该提交读取基线 renderer，当前工作树提供候选 renderer。

原生采样在 Windows 上执行：

```powershell
cmake -S archive/rollback-zero-delay-th12-performance-20261028 -B artifacts/th12-perf-native -A x64
cmake --build artifacts/th12-perf-native --config Release
& artifacts/th12-perf-native/Release/profile.exe '<本地 TH12 提取资源目录>'
```
