# TH12 多人回滚存储复用

回滚恢复复用现有敌人对象、ECL 上下文节点及脚本栈／调用栈容量。动画资源注册表由快照共享映射，在加载或卸载资源时复制映射，保持旧快照的资源绑定。

| 稳定阶段 1,000 次操作 | 基线 | 存储复用 |
| --- | ---: | ---: |
| 世界恢复 CPU 耗时中位数 | 76.904 ms | 42.746 ms |
| 世界恢复临时分配 | 403,000 | 0 |
| 动画资源注册表复制分配 | 14,000 | 0 |

基线为 `c7a2be6b1`。同一 Windows 主机、同一 CMake Release 配置和 MSVC 19.51 构建，七轮交替运行。测量使用 32 个敌人、每个敌人三个 ECL 上下文，预热后分别恢复／捕获 1,000 次；耗时衡量逻辑恢复组件。各轮状态输出哈希均为 `432792f128bb4690`。[完整测量](performance.json)包含逐轮耗时和分配数。

快照继续按共享所有权回收，持有中的快照不会进入空闲池。敌人恢复缓存最多保留 256 个对象，上下文缓存最多保留 128 个节点，每个空闲快照保留最多 64 个备用敌人槽位；原有快照池上限为 16。关卡／会话清理释放这些缓存。稳定捕获保留每次一个共享所有权控制块分配。

原生入口为 `ports/th12-mp/tests/native/multiplayer-world-storage.cpp`，通过 CTest 执行。测试覆盖双人／三人、敌人和上下文数量变化、空列表、脚本栈／调用栈容量复用、资源卸载与替换、共享快照及缓存清理。原版资源回归覆盖六种机体、普通／Extra、回滚重算的状态和随机数、所有换面与 UFO 关联恢复。

[验证记录](verification.json)包含原生 3/3、多人适配 9/9、生产 Web 构建、双人／三人真实 RTC 回滚、确认录像重建及双人观战定位。浏览器使用 25 ms 输入延迟实际触发回滚，暂停后的权威状态哈希保持一致。

本次修改归属多人目录；自动保存及 C++／JS 状态交换由 #164 维护。目录投影在隔离克隆刷新，标准多人子树导出的源码树、原仓库祖先和既有导出祖先均已核对。
