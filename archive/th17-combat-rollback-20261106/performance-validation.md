# TH17 回滚分帧压测 · 2026-11-06

两版生产 Wasm 在桌面 Chromium 内使用原版 TH17 1.00b DATA，经本地 Relay 建立 WebRTC 房间。Chromium 使用 2 倍 CPU 限速，来宾发出的二进制输入及补发包增加 145 ms 单向延迟和 0–20 ms 抖动。数据中的纠错耗时按房主浏览器回调统计，包含该回调内的快照、逻辑重演和 GPU 提交。

| 房间 | 纠错回调耗时 P95，优化前 → 优化后 | 优化版一致的确认帧 | 房主省去 GPU 提交的重演帧 |
| --- | ---: | ---: | ---: |
| 双人 | 76.3 → 7.7 ms | 1056 | 155 |
| 三人 | 45.4 → 8.1 ms | 1055 | 423 |

优化版按原顺序恢复弹池的活动与空闲列表，复用已回收弹槽的快照。中间重演帧执行战斗更新、绘制回调和符卡计时，最终帧提交完整画面。[基线数据](baseline-latency.json) · [优化版数据](bounded-replay-latency.json)

原生测试核对了确认阶段最多提前八帧采集、恢复战斗后按序消耗已发送输入，以及分批重演期间 Bomb 单次提交。生产包在 Extra 双人、三人房分别比对 1052 个确认帧，两种席位数均触发了回滚，双人房峰值敌弹数为 329。[Extra 房间数据](bounded-replay-extra.json)

Easy 双人房以 110 ms 单向输入延迟从一面打进二面，比对了 9141 个确认帧，其中二面 243 帧。房主在道中、Boss 非符和符卡分别纠正 151、16 和 8 次。双端同时通过 256 帧对话，并在切关后继续比较状态。[切关房间数据](bounded-replay-stage-two.json)

Normal 双人房使用同样的输入延迟，比对了 7963 个确认帧，包含 1802 帧 Boss 非符。两端都在进入符卡后触发纠错。[Normal 长测数据](bounded-replay-combat.json)

纯延迟模式使用 2 帧输入延迟，双人和三人分别比对 1055 和 1053 个确认帧。两组房间的回滚计数均为 0。[纯延迟房间数据](bounded-replay-lockstep.json)
