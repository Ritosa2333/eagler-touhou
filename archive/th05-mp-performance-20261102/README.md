# TH05 多人性能验收

原生多人弹池按点弹／图弹分别维护占用上界，跳过末尾空槽并保留原先 1,800／2,200 槽的容量、分配、碰撞与消弹顺序。回滚检查点使用公共日志的只读批量复制，音频记录按事件创建；输入账本按单个到期帧退休。多人画面按世界修订提交，网络等待复用上一帧，暂停菜单继续处理触控。

[交替采样](performance.json)在桌面 Chromium CPU 四倍节流下，使用三／四面 Lunatic 三人 Boss、满火力、相同输入与三轮前后交替，每轮 900 帧。[汇总](performance-summary.json)以各轮平均耗时的中位数计算：三面逻辑 0.112→0.046 ms，四面 0.103→0.053 ms；6 帧迟到纠正分别为 0.660→0.503 ms、0.551→0.406 ms，降低约 24%／26%。全部配对最终游戏状态一致。计时关闭音频，绘制项包含 CPU 提交；手机帧率由实机确认。

[七关逻辑对照](equivalence.json)覆盖两人／三人、七关、道中／Boss 共 28 组，每组 720 帧；[56 张画面对照](pixels.json)包含正常场景与爆炸效果，游戏区域逐像素一致，排除右下角依赖墙钟的 FPS 行。

[长回滚](rollback.json)覆盖两人／三人七关 40 组、每组 1,200 帧，迟到／逆序输入纠正后的密集世界字节与音频事件序列等于完整真实输入。[生命周期边界](boundaries.json)验证 Boss 创建退场、四面分支、换面、重开、死亡与幽灵救援。

帧时序测试覆盖 60／75／90／120／144 Hz 屏幕、新世界帧、纠正终点、输入等待与暂停菜单。生产房间测试注入网络抖动和输入暂停，读取实际世界帧及原生绘制调用计数，并通过短触控暂停、滑动和返回房间流程。
