# TH12 多人回滚性能

基于已合并 PR #1 的 `6619b2266affbb6568169d46671f4346fe1fcfe5`，多人版保留显示、连续网格和音频优化，并减少回滚记录的构造成本。

- 完全确认的输入帧直接记录输入与音效；预测帧保留完整的回滚检查点。
- 动画检查点以连续节点数组、注册链 ID 和根节点关系保存。恢复时还原原有节点状态、注册顺序、子链、回调和随机数状态。
- 多人网格透明度在连续缓冲绘制阶段计算，保持顶点缓冲原值，并保留逐字节 ARGB 舍入结果。

## 对比

原生 Release 在相同世界中分别构造旧检查点和新检查点，保持最多 12 份记录。Extra 三人样本包含 1,932 发子弹和 2,385 个动画节点。

| 项目 | 原实现 | 优化后 |
| --- | ---: | ---: |
| 密集弹幕检查点平均耗时 | 3.61 ms | 2.40 ms |
| 浏览器双人回滚逻辑平均耗时 | 1.01 ms | 0.66 ms |
| 浏览器三人回滚逻辑平均耗时 | 1.20 ms | 0.86 ms |
| CPU 限速 6 倍、三人同时 Bomb 的逻辑 P95 | 22.2 ms | 13.2 ms |

浏览器采样包含输入采集、实际联机和录像自动保存，不执行逐帧完整世界哈希。原生回归另行核验迟到输入的恢复结果、RNG、六机体、Normal/Extra、飞碟和跨关状态；网格回归直接核验连续缓冲的最终绘制透明度。

该检查点格式由 MP 会话使用。普通版沿 PR #1 保留共用的显示和音频优化，多人预测帧的检查点管理独立维护。

## 检查点存储复用

后续优化复用已释放检查点的容器容量，以及回滚前后 ID 一致的动画节点、VM 和注册链存储。节点值、根节点关系、注册顺序和已删除节点仍按检查点完整恢复；仍被引用的检查点保持独立。空闲缓存最多保留 16 份，在跨关和退出时释放。

相对前一版，在相同的 1,932 发子弹、2,385 个动画节点样本上：

| 项目 | 前一版 | 存储复用后 |
| --- | ---: | ---: |
| 检查点平均耗时 | 2.15 ms | 0.89 ms |
| 恢复平均耗时 | 1.99 ms | 0.67 ms |
| 连续移动与 Bomb 压力下的逻辑 P95 | 48.77 ms | 37.37 ms |
| 同一压力下的绘制间隔 P95 | 450.10 ms | 337.47 ms |

浏览器压力条件为 CPU 限速 6 倍、同页三个 Extra 客户端、连续移动与同时放 B。两组压力运行均在结束后同步暂停并核验客户端状态与 RNG；WASM 线性内存均为 40,304,640 字节。原生回归额外保留一个共享检查点，连续复用其他缓冲并清理空闲缓存，验证保留状态、动画图和 RNG 的恢复结果。

## Extra 时符的状态生命周期

显示插值的 owner revision 按存活对象保留，每 120 逻辑帧回收一次退场对象记录。存活动画、敌人、子弹、道具、激光和固定界面 owner 均保留原 revision；已保存的回滚检查点独立持有其原始状态。该清理同时适用于普通版和多人版，不消耗 RNG，不修改游戏判断。

以 THPrac 的既有 ECL 跳转进入真实 Extra 第九符“平安京的恶梦”，使用三人、全灵力、相同种子和输入运行 4,200 逻辑帧。测试程序使用原版脚本与资源，保持自机无敌以覆盖符卡的多个阶段。

| 项目 | 清理前 | 清理后 |
| --- | ---: | ---: |
| 第 3,900 帧的 revision 条目 | 36,301 | 1,425 |
| 检查点平均耗时 | 1.30 ms | 0.56 ms |
| 恢复平均耗时 | 0.97 ms | 0.41 ms |

浏览器另用生产 WASM、三个实际联机客户端与同一时符核验共享暂停后的状态哈希；六种机体的真实中文 MSG 经过原生执行后逐条匹配语言覆盖表。重复执行“配置语言→房间预加载→配置语言→开局”时，当前语言对象始终启用，客机显示房主路线的汉化文本。

多人 Bomb 使用全队互斥规则：执行中的 Bomb 结束前，其余座位不能启动或扣除另一个 Bomb；同帧输入按共享座位顺序处理。双人、三人、死亡窗口和回滚恢复均覆盖该规则。
