## 修改与验证

[`BrowserRuntime.cpp`](../../ports/th15-mp/web/cpp/sdl/BrowserRuntime.cpp) 复用公共待推进帧调度，收包可唤醒已经到期的更新。短时积欠在画面提交后继续执行，收包和续算只消费已有时钟额度。历史纠正复用缓存输入，并提交恢复后的完整端点。

新版控制测试停在 1845 帧，补包后在没有新 rAF 时推进至 1846；半个周期仍为 1846，完整周期后推进至 1847。停止循环后执行已排队的旧任务，帧号保持不变。收包钩子另验证关闭、重新启动后旧回调失效。

双人和三人各恢复七帧历史后，逻辑前沿与本地采样前沿均停在 247，世界指纹和确认录像输入与完整实际输入执行一致。三人暂停边界另将恢复游标阻塞在 240，采样前沿保持 247；剩余输入到达后完成历史，并只执行一次到期新帧至 248。

普通版对照和三组联机场景各采样 60 次键盘移动。180 次联机输入均在第一次实际推进时响应，未漏响应。DOM 到移动提交的计时受同机多客户端负载影响，只作为观测，不能据此宣称显示延迟与单机相同。

正式包通过双人／三人直接回滚、双人旁观、缺包停帧、确认录像及独立离线回放。60／120／144／165／240Hz 固定更新与呈现回归、作品检查 9/9 和文档检查通过，正式包不含开发探针。

## 性能与复现

沿用[回滚性能验收](../th15-rollback-performance-20261105/README.md)的 16 组场景，每组 600 帧。分组验收覆盖全部场景，世界、确认输入和 canvas 均与完整输入执行一致。最重的 4x 日志 P95 为 14.1ms，2x 五帧强回滚为 16.4ms。

一次长跑中出现超预算，结束时已记录 13 组。后台高占用与波动同时出现，[机器记录](verification.json)分别保存长跑、分组复核和对照统计，不将这轮长跑标为通过。同一浏览器按旧、新、新、旧交替对照的 P95 为 7.7、7.6、6.1、7.9ms；对照每组 120 帧。随后 600 帧对照中，新版再次出现尖峰；该场景最终在关闭并行检查后单独测得 P95 8.0ms。这些结果不能证明长时间负载下已稳定达标。

正式运行包已更新至[测试站](https://test.touhouonline.com/)。WASM 为 `409d5fccc8cc65ab0fc7d56b81f657a82b5df545a0cc83ae5efa1b4efc395444`，公开路径的 15 个文件均通过字节、类型和缓存检查。
