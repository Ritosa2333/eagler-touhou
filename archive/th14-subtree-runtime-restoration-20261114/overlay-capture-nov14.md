# TH14 练习界面与暂停截图分离

高级设置打开期间发生疮痍，原候选会把已经叠加 ImGui 的上一帧复制进暂停背景。随后关闭设置，设置文字仍留在成绩表和 Game Over 菜单下方。该问题已在实际浏览器中复现并保留截图。

修复在 ImGui 实际提交绘制前保留一张干净的游戏表面，后续即时暂停截图读取该表面。没有界面绘制时直接使用原屏幕路径；对话模式仍优先读取原有 text 中间表面。只维护一张可复用截图表面，不执行 GPU 到 CPU 的读回。修改限于 TH14 的 Application、GraphicsDevice 和 PracticeUi 接口与实现。

修复候选 `bd2e0463c54baac65d4291c02be5fedaafd9023c` 的浏览器 Wasm 为 `811dc8cb1ffd607f12b7ca23b8dc2b2aee76e5cdc8a0fbca72f7d08c2e542053`。编译器依赖检查覆盖 153 个单元，重编受影响的四个单元并核验复用的 149 个对象。关闭可选练习器后的三个相关普通版单元也通过正常访问权限的编译前端检查。

实际静音 WebGL2 中，灵梦 A Normal 在设置打开期间自然疮痍，关闭设置后的成绩表和 Game Over 菜单均不再保留设置残影。续关后的普通暂停、恢复、移动及再次暂停通过，第二次截图包含推进后的画面。私有预览的 32 个运行文件通过完整哈希与隔离响应头检查，音乐／音效均为零，OGG 使用流式解码。

最初依赖扫描的 Windows 路径解析失败产物已拒收，随后编译暴露的私有界面可见性函数调用也已修正；相关记录保留。最终实现直接在真实绘制边界判断有无绘制数据，不依赖私有可见性函数，也覆盖可绘制但不拦截输入的辅助显示。

本次证明声明的疮痍残影触发与普通暂停路径已通过。对话中的实际暂停截图、其余图形模式、完整练习工具与真实触屏继续验收，生产未切换，整作目标保持进行中。详见[机器证据](overlay-capture-nov14.json)及[核心验收说明](https://github.com/AdingApkgg/thp/blob/72e2bf73cec1823a4ef250935fc5497db81fbc50/docs/porting/TH14_OVERLAY_CAPTURE_NOV14.md)。
