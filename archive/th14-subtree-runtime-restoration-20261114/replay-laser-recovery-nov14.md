# TH14 同一录像重播保留激光修复编辑 · 2026-11-14

已复现恢复编辑模式的记录丢失：当前源码在重新打开同一份录像时无条件清空 `purple_laser.recovered`。实际 C++ 应用在魔理沙 A Easy 三面收集到两条恢复记录后，将第 2,935 帧修正选择为零，再经原生录像入口重开同一文件，两条记录均消失，修正效果随之丢失。

候选在打开前比较原始录像完整字节。同一文件保留恢复工作区；文件不同则开始新的工作区，避免把上一文件编辑带入另一录像。每次开始的关卡、帧及序号仍由现有流程重置。

| 实际流程 | 当前源码 | 候选 |
| --- | --- | --- |
| 首次播放三面至 3,600 帧 | 两条恢复记录，64,383,460 分 | 相同 |
| 编辑第 2,935 帧后重开同一文件 | 记录清空，修正丢失 | 两条记录及编辑保留 |
| 同一文件重播至 3,600 帧 | NaN 长度，64,383,460 分 | 长度 8，64,383,430 分 |
| 改开另一文件 | 工作区清空 | 工作区清空，64,383,460 分 |

另一文件仅增加一个未知 USER 块，游戏输入保持，但完整文件身份不同。测试通过明确的模式选择及记录编辑动作，再使用真实 C++ Application 的原生打开／播放流程，未覆盖 RNG 或经济状态。每个对照含三次 3,600 帧片段；全部资源释放并保持内存音频静音。

实际静音 WebGL2 也已完成普通启动器 → 游戏内 Replay 菜单 → 用户导入页 → 三面的流程。在高级设置选录像修复模式，实际捕获 1,280／2,935 帧两条记录，暂停后将第二条替代值改为零，再经游戏内“もう一度再生する”重播。游戏进度及 HUD 已回退，两条记录及第二条零值编辑仍可见。该 UI 验收使用浏览器自身的图形／帧时序，未将截图得分当作原生 3,600 帧精确终态。网页录像工作区的编辑快捷键未成功，浏览器不同文件切换、导出／读回和完整录像仍继续。

浏览器候选 Wasm 为 `df007888`，运行代 `0adcd12b`，只重编一个单元并校验复用 152 个对象，32 个 HTTP 运行文件及隔离响应头通过。当前验收范围为候选，生产保持。
