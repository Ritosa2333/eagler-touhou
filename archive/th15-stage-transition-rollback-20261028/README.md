# TH15 多人回滚换面输入节奏

每面结束后的原生过场需要确认输入，期间持续发送每秒 60 次、最多领先 8 帧的物理输入，维持网络流水线。可保存快照的战斗阶段消耗既有队列后再采样新输入。

换面会暂时保留上一面的背景，并等待新关卡启动。此前输入队列只对菜单、对话和已触发的边界开放，换面阶段每收到一个确认帧才发送下一帧，网络往返时间被逐帧叠加。现在队列许可与实际快照就绪条件保持一致。

## 验证

- 实际 `NetplayRuntime` 的 2P／3P、回滚／混合模式，单向延迟 2／4／6 帧：稳定窗口 180 个墙钟帧内均推进 180 个确认帧，原先逐帧等待的负对照推进 60／36／26 帧。检查全部输入席位、队列上限和战斗恢复后的排空。
- 原版资源 Chromium 夹具通过原生关卡完成入口从一面进入二面，调用实际 `sample_and_tick()` 观察队列许可。2P／3P 各有 180 帧尚未满足快照条件，其中保留旧背景 149 帧；修复后覆盖全部确认阶段，战斗恢复时关闭。此项由夹具推进游戏，网络延迟节奏由前一项独立验证。
- 正式多人 WASM 构建、wasm32 协议与 Replay 回归、共享启动协商、原生预测边界检查、7 项多人适配检查通过。正式包不含诊断导出。
