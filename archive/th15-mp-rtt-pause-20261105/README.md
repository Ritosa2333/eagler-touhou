# TH15 多人高延迟帧节奏

双人 Lunatic 一面使用实际 WASM 和两端 RTC 输入。在两端收包路径分别加入约 64 ms 延迟与小幅抖动，持续切换移动和低速输入。回滚会在迟到输入与预测不一致时重演战斗。暂停期间使用确认输入驱动菜单，等包和高刷回调会放大重复提交画面的开销。

暂停保留一帧等包补偿，画面按菜单实际更新提交。无新画面时，仅在 FPS 数字变化后重绘该区域。战斗快照确认后，将不再被历史帧引用的平面动画镜像放入有界缓存，供后续捕获复用。缓存最多保留 512 个镜像。

在 3× CPU 限速与 2× 渲染倍率下，以旧、新、新、旧顺序各运行 8 秒。128 ms 模拟往返延迟下，暂停菜单推进从 50.1–51.6 升至 55.7–58.7 帧/秒。两端均成功恢复战斗。零输入延迟的战斗结果随重演负载波动，旧版为 44.6–56.4 帧/秒，新版为 46.2–52.5 帧/秒。

正式修订的回滚使用 0 帧输入延迟。重演执行原版 Draw 的状态写入，跳过仅供当前画面使用的顶点、纹理状态和透明度副本。背景裁剪一旦从已投影的角点确认可见，就可以继续绘制该实例。需要投影坐标的诊断路径会计算全部 16 点。

固定八帧重演采用前、后、后、前顺序，每组 480 帧。双人一面的耗时 P95 由 7.9–8.6 ms 降至 5.8–6.2 ms。双人一面、三人四面和六面密集场景共 12 次采样，同场景的最终战斗指纹与截图字节一致。六面密集样本的帧耗时单独记录在机器报告里。

零延迟的双人 Lunatic 一面，使用 60 FPS 画面上限、2× 渲染倍率和 3× CPU 限速。模拟 128 ms 往返延迟时，18 秒战斗的平均推进为 58.2 FPS，画面中位数为 59.6 FPS，最慢一秒推进 50–52 帧。20 秒暂停样本平均推进 57.9–58.2 FPS，双方均恢复战斗。

## 输入缓冲对照

早期采样以 4 帧输入缓冲对照网络重演成本，画面上限为 60 FPS。从连接建立起在 RTC 收包路径注入延迟，两端同在一个 Chromium 标签页，使用 3× CPU 限速。以下为该实验的历史数据。

| 场景 | 渲染倍率 | 采样 | 平均逻辑推进 | 画面 FPS 中位数 | 最慢一秒的推进帧数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 双人 Lunatic 一面战斗 | 2× | 25 秒 | 59.74–59.87 | 59.76–59.97 | 54–56 |
| 双人 Lunatic 一面暂停 | 2× | 25 秒 | 59.35–59.43 | 59.76–59.78 | 57 |
| 双人 Lunatic 一面挑战模式暂停 | 2× | 35 秒 | 54.84–54.86 | 53.12–54.00 | 44–46 |
| 双人 Lunatic 一面挑战模式暂停 | 1× | 25 秒 | 59.62–59.67 | 59.86–59.92 | 57 |

战斗的单次回调耗时 P95 为 6.1–7.7 ms，推进间隔 P99 为 32.6–33.6 ms。挑战模式暂停样本逐帧核对了原生菜单状态，双端退出菜单后都继续推进。采样包含模拟延迟与抖动，链路走本地 RTC。
