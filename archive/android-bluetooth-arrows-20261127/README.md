# 外接键盘方向键与输入法标记

方向键在游戏区域按物理按键独立维护，可连续组成斜向并分别释放；输入框和文字组合输入继续由编辑器处理。

## 修复范围

基线：主仓库 `e5aa0a255`。关联：[issue #217](https://github.com/Ritosa2333/eagler-touhou/issues/217)。

启动器 `player-keyboard` 和共享 `keyboard-input-bridge` 原先无条件拒绝标记为 `isComposing` 的按下事件。改键页面没有同样的过滤，因此这一输入形态会出现设置能识别、游戏区域无法按下的差异。

修复允许具有明确 `ArrowUp/Down/Left/Right` 身份的事件通过组合输入过滤。优先使用 `code`，缺失或为 `Unidentified` 时使用 `key`；不根据 `229` 猜测方向。编辑目标检查始终有效，其他文字组合按键保持原策略。共享运行时覆盖普通与联机入口，TH06、TH07 的内嵌桥同步同一判断，不改变游戏逻辑或联机协议。

## 验证

- 修改前，新增的 IME 方向键测试在第一个按下事件失败，实际返回 `false`。
- 修改后，共享输入及练习工具键盘契约测试 21 项通过；TH06、TH07 的现有键盘释放检查分别通过。
- 启动器 `player-keyboard` 与 `keyboard-mapping` 测试 35 项通过。
- 测试覆盖原生/转发路径、真实映射器、已知/缺失物理 code、组合标记、先左后上的斜向、重复按下、逐键释放、输入框隔离，以及内嵌桥。
- 启动器测试使用容器 Bun 1.4.4 / Vitest 5.0.5，独立配置选择上述两个现有测试文件，保留仓库运行时校验。共享测试使用容器 Node 22.23.3。

本次是可复现事件形态的修复。尚未取得反馈者的浏览器事件记录，也没有在其安卓蓝牙键盘上复测，因此不能把输入法标记认定为该设备的已确认根因。真机验收需检查四方向、先左后上、按住射击同时移动、松键停止，以及改键和聊天输入框中的方向键。
