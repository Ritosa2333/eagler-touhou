# TH14 网页录像结束后的完整分数动画 · 2026-11-15

修复 Extra 录像结束时 HUD 停在通关奖励滚动中途的问题。同一份灵梦 B Extra 原始输入在实际静音浏览器仍自然结束于 46,936 帧，现完整显示 **732,411,200**，与档案分数一致；原候选冻结显示为 423,091,300。擦弹仍为 12,484，Power 4.00，点值文本 61,590。[机器证据](th14-replay-end-presentation-nov15.json)。

## 原因与实现

原生 `GameSession` 在结束菜单中仍调用 priority17 的 HUD 分数更新；查看器收到强制结束菜单状态后却立即暂停整个运行循环。通关奖励已经由游戏正常结算，显示尚未滚完就被停止。

修复只改变 `Application::hosted_replay_status` 的结束就绪判断：已进入原生结束菜单后，等待 HUD 显示追上实际分数，再通知网页冻结。期间使用原有菜单／HUD 更新，托管分支仍只提供零输入，录像 Player 游标不会因此增加。Normal 的 ending control 已停止此 HUD 回调，保留其原有结束状态，不等待不可运行的动画；提前 Game Over 仍保留实际游标。

没有写入分数、回放输入、RNG、库存或预设通关结果，没有新增按文件识别的特例。补丁见[源码差异](TH14_REPLAY_END_PRESENTATION_NOV15.patch)。本次仅重编 Application 单元，152 个其他对象哈希核对后复用；387 份源码及 25 份公共绑定核验，18 个核心文件组装为 32 个浏览器运行文件，全部完整响应哈希及隔离头通过。
