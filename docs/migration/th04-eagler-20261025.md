# TH04 来源子树与主项目适配

`ports/th04` 以本目录来源代码和外部资源为构建输入，来源仓库为 [IxinorTyan/th04-coop-lab](https://github.com/IxinorTyan/th04-coop-lab)。本次导出使用的来源提交是 `a6eca059e09ac99c1958189e48069c2ccf83d413`，由 `ports/th04/scripts/build-eagler.mjs --assets=../th04-coop-lab/web` 生成 `ports/th04/build-eagler` 与 `ports/th04/content/th04.data`。

接入层采用主项目 Runtime 协议：启动器负责资源包、存档文件、房间成员、准备与开始；TH04 运行时负责原版 DOSBox-X/PC-98 模拟、画面、音频、输入采样、确认帧和校验。普通版入口和联机入口共用 `managed-shell.mjs`，联机适配把主项目已认证的成员地址接入原有可靠控制与快速输入通道；WebRTC 不可用时由主 Relay 传输，并为 TH04 增加认证发送者信封。

原版存档使用 `GENSOU.SCR` 与 `MIKO.CFG`，普通版保存在 `/savesth04/`，多人版文件命名空间为 `/savesth04mp/`。两者采用主项目 IDBFS v21 `FILE_DATA` 格式，供主项目录像列表直接读取；单人局同步从原生磁盘提取分数与配置。TH04 Replay 使用 `replay/<filename>.th04r`。资源包包括 runtime directory manifest 和受校验的 PC-98 DATA；构建器会记录输入文件哈希和上游提交，不能把生成的 WASM 目录当作原仓库源代码历史。

当前接入验证包含真实 Chromium 中的主启动器单人安装与启动、主大厅双人建房至开局、真实双人 WebRTC、三人 Relay、回滚模式、音频资源请求、原版存档同步、主项目键盘映射后的真实角色移动、原生暂停菜单同步退出，以及同一房间的第二局。房间标题在原生画面呈现后保持，开局前释放隔离的预览 Worker。

原生退出在全员结束屏障完成后释放传输：每个实例完成本地确认退出，再交换可靠结束消息及回执，避免较快的端提前关连接。独立传输测试覆盖双人和三人屏障，真实 WASM 测试覆盖双人 WebRTC 与三人 Relay 回滚模式的同步退出。


TH01、TH02、TH03 后续分别建立来源记录并沿同一 Runtime/房间接口接入。TH02 可参照本次普通版 attempt 与多人房间适配；TH01 采用原生 WASM 多球内核；TH03 采用双人对战配置，保留各自玩法与同步实现。

## 来源与维护

原仓库 [`th04-coop-lab`](https://github.com/IxinorTyan/th04-coop-lab) 的 `main` 提交 `a6eca059e09ac99c1958189e48069c2ccf83d413` 及该分支截至此点的全部 58 个原始提交均保留为当前仓库的祖先；作者、时间、说明与原始提交 ID 均保留。主站适配提交的目录投影与原仓库通过合并连接，当前目录由标准 Git subtree 导出。

首次连接提交为 `c7dc06f0e6175a4c6547ba7a7dd448fe377070aa`，导出基点为 `1bd7ae65ab4c9385fbe8ecc74fa3fb2afd5f6e91`。原仓库 README 保存在 [README-UPSTREAM.md](../../ports/th04/README-UPSTREAM.md)。源文件与运行资源的划分记录在 [source-import.json](../../ports/th04/source-import.json)。

在 monorepo 根目录运行 `node ports/th04/scripts/build-eagler.mjs --assets=../th04-coop-lab/web`，从本目录代码和外部资源生成 Runtime 与 DATA。`--source=<完整原仓库>` 保留独立来源对照构建入口。开发脚本默认读取相邻原仓库的资源目录，也可通过 `PC98_ASSETS_DIR` 指定。

历史查询、subtree 导出、后续同步与 PR 合并步骤见 [TH01–TH04 子树维护](pc98-subtree-20261026.md)。
