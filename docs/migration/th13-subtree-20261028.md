## 构建与 Launcher

```sh
node ports/th13/portable/build-eagler.mjs
node launcher/scripts/prepare-th13-content.mjs --raw=/path/to/extracted --original=/path/to/game --output=/path/to/assets-ogg
```

以上命令在既有容器环境中运行。设置 `EAGLER_TH13_CONTENT_DIR` 指向准备后的私有资源目录。代码发布包为 `ports/th13/build-eagler/`，`runtime-files.json` 记录各文件字节数及 SHA256。

资源准备保留原版 `thbgm.fmt` 与完整连续 Vorbis `thbgm.ogg`，通过 `TH13PK01` 包装资产，运行时挂载为 `/assets/`。源码仓库不携带该包。作品采用 `testOnly: true`，接入范围及未验证项见 [适配表](../../ports/th13/ADAPTATION.md)。

## 生产隔离与测试站点接入

`th13` 同时设置 `testOnly: true` 与 `buildOptIn: true`：前者控制作品展示，后者控制构建资源的显式接入。默认作品选择、正式 release 输入和未指定作品的开发 Manifest 均排除 th13，因此原生产构建不新增 th13 数据、音乐、Runtime 或封面要求。已有隐藏作品的生产策略保持不变。

Runtime Release 默认不要求 `--th13-build`，已有不含 th13 的 Runtime Release 仍符合默认作品集合；提供 `--th13-build=/path/to/ports/th13/build-eagler` 时才将其加入发布包。

开发测试站点可明确选择作品：

```sh
EAGLER_DEVELOPMENT_GAMES=th13 EAGLER_TH13_CONTENT_DIR=/path/to/assets-ogg npm --prefix launcher start
```

复用现有测试站点组装命令时，追加 `--games=th13 --test-build=1 --profile=web-validation-th13`，指定独立输出目录、th13 Runtime/私有资源和该测试 origin 对应的前端产物。这里是参数增量，不替代上游 React 前端及共享字体等既有前置要求。也可在显式作品列表中将 th13 与已有作品一同选择。

`package-server.mjs` 拒绝在未开启 `--test-build=1` 或使用生产 release profile 时选择 opt-in 作品。不要复用或覆盖线上目录，不更改现有生产部署、service worker、域名或 CI 发布目标。

上述隔离为本轮静态实现，未运行构建或测试，不能宣称生产零回归已经得到实测证明。

## 合并及往返

该作品 PR 必须使用 **Create a merge commit**，不 squash、不 rebase；否则会切断独立来源父链。

```sh
git subtree split --prefix=ports/th13 -b export/th13
git merge-base --is-ancestor ca705e2339622348611590bb325dd013a95aa9a2 export/th13
git rev-parse HEAD:ports/th13 export/th13^{tree}
python tools/ports/check-history.py --base upstream/main
```

向独立仓回推使用导出的端口分支，不推送整个 monorepo。更新连接点时同步机器登记，并按上游贡献规则复核祖先及树。
