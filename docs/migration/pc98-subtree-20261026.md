## 平时开发

在 monorepo 的功能分支修改 `ports/<作品>` 并正常提交。构建使用本目录代码，通过 `--assets` 指定外部资源目录：

```sh
node ports/th02/scripts/build-eagler.mjs --assets=../th02-coop-lab/web
```

开发服务默认使用相邻原仓库的资源目录，可用 `PC98_ASSETS_DIR` 覆盖。`--source=<完整原仓库>` 用于独立来源对照，显式选择时才使用外部代码。

主仓库构建入口也登记了四作的组装配方：

```sh
npm run build:runtime -- --game=th02 --variant=multiplayer --assets=../th02-coop-lab/web
node ports/th02/scripts/build-eagler.mjs --print-inputs
npm run ports:check -- --game=th02 --variant=both --check-status
```

`--print-inputs` 输出源码清单，用于无游戏资源的 CI 检查；`--print-package-inputs --assets=…` 输出包含外部资源的组装清单。配方复用已有预编译核心，本目录的普通版与多人版共用运行时代码，通过入口参数选择模式，存档继续使用各自命名空间。适配表区分源码检查、实际构建和设备验收。

## 核对历史和导出

在 monorepo 根目录执行，下面以 TH02 为例：

```sh
python tools/ports/check-history.py --base upstream/main
git subtree split --prefix=ports/th02 --branch=th02-subtree
git merge-base --is-ancestor 5b5d583faddfd837b423cbeb705c3e0504f18c1f th02-subtree
git rev-parse HEAD:ports/th02
git rev-parse th02-subtree^{tree}
```

祖先检查返回 0，最后两个树 ID 相同。导出的历史包含来源仓库贡献与后续适配修改。需要独立导出另一作时，替换目录、分支名和来源提交。

## 同步原仓库更新

先在功能分支或临时克隆更新，使用不压缩历史的 subtree pull：

```sh
git subtree pull --prefix=ports/th02 https://github.com/IxinorTyan/th02-coop-lab.git main -m "同步th02来源更新"
```

原仓库是独立发行布局。同步后检查 `README.md`、`README-UPSTREAM.md`、`.gitignore`、`source-import.json` 与资源清单，保留主项目适配入口；新增游戏资源继续作为外部构建输入。同步完成后核对实际输入哈希、构建、行为和源码发布检查，再按迁移 JSON 的字段登记新的导出与连接节点，并运行来源历史检查。

## 提交 PR

将功能分支推送到自己的 fork，PR 的 base 选择项目主仓库目标分支，compare 选择该功能分支。正文链接四作迁移记录并列明检查结果。完整检查见 [贡献指南](../../CONTRIBUTING.md)。作品目录 PR 使用 **Create a merge commit**，保留来源与适配父链。
