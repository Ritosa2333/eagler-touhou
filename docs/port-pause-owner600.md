# 暂停控制器的异步退出保护（599–602）

暂停菜单在等待音频、声音收据或画面准备时，页面可能已退出或换成下一局。旧控制器原先仍会继续打开原生菜单、提交动作或调用继续游戏/返回标题/重开回调；已经失效的错误也可能显示到新页面。

本次在生产 OriginalPauseController 的等待点重新检查关闭状态，保持已关闭对象不可重新激活；旧对象的迟到错误停止向外传播，当前对象的真实错误仍保留。生产 openOriginalNativePause 在等待结束后重新核对模块、动作、关卡选择和控制器身份，避免覆盖后继页面状态，也不清除后继对象的 pending 标记。

## 验证

- **599：真实生产代码复现。** 22项断言中16项失败；包括9个精确等待点、5个迟到错误和2个页面身份变化。此前DSH错误设置的第二次画面回调等待点没有参与本次证明。
- **600：同一组22项全部通过。** 保留当前对象四种菜单动作、错误传播和正常状态显示。
- **601：交付回归首轮失败，记录保留。** 暂停22项通过；两项旧声音测试仍假设 play 立即播放并使用 StereoPanner，与早已采用的排队/flush和左右声道增益方式不符。GameSoundQueue在595与600间字节相同，该失败归为旧测试契约问题。
- **602：修正测试后55项通过。** 暂停22、声音队列2、EX生命周期6、EX收据身份20、Main松键接管5；没有跳过项。

声音测试现在明确验证“排队时无播放节点、flush后才发声”、原生音量、左右增益、指定声音的平移/停止和清理。产品声音队列与音频门本次没有修改。

## 范围

测试直接运行完整生产控制器和提取出的完整页面打开函数；原生、音频和DOM接口为模拟边界。本次未启动World、浏览器、原版程序或编译原生核心，也没有重跑598、六线或EX成功流程。

此修复覆盖控制器等待结束后的调用与页面状态传播。实际 MenuAudioGate 内部的异步上下文清理，以及已经进入的Replay/画面消费者回调自身的身份检查，仍需独立复现和修复；本项不宣称整个音频设备生命周期或所有暂停并发场景通过。不得为清理伪造不存在的原生 pause-close 接口。

暂停原生对象可能已在等待声音收据之前打开；测试断言的是关闭控制器后不再新增调用，不表示该原生对象从未创建或已完成退休。独立DSH只读审阅确认本次控制器和页面状态修复无阻塞问题，同时保留这些范围限制。

候选600从595完整继承，仅改变 `site/play.mjs` 与 `site/runtime/sound.mjs` 的暂停相关代码；private100及公开运行目录保持原字节。
