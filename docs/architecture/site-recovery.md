# 网页入口回退

已完成 App Shell 安装的浏览器，优先从当前 Origin 的缓存打开启动器。主入口连接失败时，Service Worker 按部署配置中的顺序补齐启动器与 Runtime 文件，地址栏、存档和设置继续使用原来的 Origin。

主域名的首页与大厅文档直接返回，海外静态资源通过边缘节点分发。全部作品共用这套加载层，版本与存档继续沿用原来的产品边界。

## 发布配置

部署目录可提供 `site-network.json`：

```json
{
  "schema": "eagler-touhou/site-network/1",
  "mirrors": ["https://second.example/", "https://third.example:8443/"]
}
```

地址按优先级排列，使用独立的 HTTPS 入口，最多三个。每个入口直接提供同一发布版本的文件，并允许跨域 GET。构建器将配置、站点清单、Release Catalog 和其 Package Descriptor 纳入 App Shell 的 SHA-256 清单。配置保存在本站缓存中，浏览器重启后可以直接使用。域名与 IP 由部署和 DNS 管理，通用源码只定义协议。

## 请求与版本

缓存缺失时，先访问主入口，再按配置顺序访问备用入口。每次连接和传输停顿的等待上限为 2.5 秒，收到文件数据后重新计时。近期失败的入口退后一分钟，其他文件复用可达入口。文件内容不符合当前版本的校验值时继续尝试下一个入口；完整校验后才写入缓存。Runtime 继续使用完整代际事务，未下载完成的版本不会成为可用运行包。

镜像响应转换为本站响应，模块相对路径继续以本站解析。备用站不接收本站 Cookie。401 和 403 终止本次请求，访问限制继续生效。

`runtime-manifest.json` 优先获取可达入口的最新清单，离线时读取当前 Worker 随发布保存的完整清单。`/_eagler/resource-routes` 可以通过备用入口获取下载候选，响应不缓存，每个入口的停顿上限为 1.5 秒。该发现地址使用 Origin 根目录，支持启动器挂载在子目录。游戏 DATA、音乐、语言包继续由资源分流器和资源节点提供。WebSocket、TURN、用户数据写入与注册接口使用各自的服务路径。

## 部署与验收

发布时同步完整发布清单及其中的文件，校验后原子切换每个镜像。备用站直接提供字节，保留正确 MIME、CORS、Range 和访问地域规则。新增入口先完成证书与文件核对，再将配置随主站发布。旧入口域名保持可达，使使用旧缓存的浏览器能继续取得对应版本。

运维可用 `launcher/scripts/apply-site-network.mjs --site=未启用的发布候选目录 --config=配置文件 --worker-contract=编译后的运行包协议文件` 为候选包应用独立配置。该命令核对输入发布清单，重建 Worker 与发布身份，再核对全部文件。发布流程在启用候选目录之前运行它，自动同步器按最终发布清单同步。

浏览器验收包含完成安装后主入口不可达、第二入口也不可达、备用文件校验失败、完整离线刷新和本地存储保留。首次访问需要先连接一个可用主入口来安装 Service Worker。Service Worker 自身的更新由浏览器从注册入口获取，恢复连接后继续正常更新。
