## 可审查的验收方法

每项先确认输入和方法，再记录本次实际执行范围。原版参考维护、候选比较和报告验证分别有独立职责，详见[原版对照测试](../testing-oracle.md)。

### VERIFY-01 | 全部内置 Demo

- 从本作登记清单取得全部 Demo，核对样本与原版来源。逐份执行同一输入的候选／原版对照，比较逻辑帧和声明状态，要求每份到达自己的原版确认结束点。
- 反例：少跑一份、缩短尾部或把一份结果重复计入，必须在清单及终点核对中失败。
- 当前入口：本作 Replay verifier 与已登记的 Demo／world 对照。frozen-oracle 登记 th09、th11 普通版／MP、th15 普通版／MP 五个源码目录，其他作品使用本作入口；结果明确样本和完整帧范围。

### VERIFY-02 | 长回放

- 对登记的 Lunatic、Extra 等长样本逐份校验哈希，再完整执行对照。记录所有覆盖阶段、帧数、终止原因和末状态，使用原版实际终点或经审核的固定参考判断。
- 反例：设置较短帧上限但保留成功退出，必须由终点断言检出。
- 当前入口：本作 external-replay、world-replay／campaign 及 Replay verifier。单段、检查点尾段和完整多阶段回放各自注明范围。

### VERIFY-03 | 输入与参考身份

- 核对 Replay、原版 EXE、资源、轨迹及参考数据的来源记录和 SHA-256，检查相同路径下的实际字节。首次登记或替换来源时人工审查来源与采集方法，重复校验自动执行。
- 反例：替换一个样本字节或使用另一个版本 EXE，要求预检拒绝。
- 当前入口：原版 `target.json`、私有输入凭据和 frozen-oracle 预检；构建与包身份由正式 Runtime 验收入口核对。

th11 normal／MP 的历史核心对照从私有 receipt 读取基准文件位置与 SHA-256，并绑定 `reference/` 下独立的来源文件；`referenceSource` 记录来源路径、SHA-256 和来源说明，来源文件进入完整 `acceptedReference` 前后快照。world-prefix 对照同时核对捕获目录 `state.json.identity.coreSha256`。报告列出基准、来源与当前 `artifacts/cpp/game-core-test.wasm` 的路径和 SHA-256；规范路径、realpath 与文件身份检查拒绝候选产物别名。若字节相同，报告同时保留独立来源绑定供审查。th15 normal／MP 的 `battle-callback-order` 独立成组，显式登记其读取的原版 EXE。

### VERIFY-04 | 参考保持原值

- 在候选比较前后分别快照完整参考目录和声明的外部输入，核对文件清单、目标位置与字节。比较过程使用只读输入；保存结果进入本次独立输出目录。
- 反例：候选测试改写、添加或删除一个参考文件，必须使本次结果失败。
- 当前入口：frozen-oracle 的 `acceptedReference`、`baselineChanged` 和各组输入前后快照；维护回归包含参考改变的反例。

### VERIFY-05 | 原版参考维护

统一队列的 `source-review` 组同时检查已接纳的参考来源。本地审查清单的 `products.<game>.<variant>.reference` 记录独立 provider、采集方法、单独接纳方法、采集程序与原版 EXE／DATA 身份、已接纳 golden manifest 和审查材料。每份 golden trace 的文件哈希、Replay 身份与有效帧范围均进入本次检查。清单显式声明候选不可更新 golden、维护输出写入 staging；普通验收读取这些证据，参考重新采集由显式维护入口执行。

- 显式选择参考维护任务，从已校验的原版独立采集到 staging，附输入身份、采集程序、范围和变化说明。审核新值的来源与方法后，再单独接纳参考。
- 反例：普通候选比较触发采集，或维护输出直接替换已接受参考，都不满足该流程；缺少维护任务或证据名称时入口必须拒绝。
- 当前入口：`oracle-cli.mjs --mode=maintenance` 与本作登记任务。维护成功证明采集完成，参考接纳另附审核记录。

### VERIFY-06 | 逻辑帧比较

- 以相同初始状态和完整逐帧输入驱动双方，按相同逻辑帧序列比较本作权威状态。显示帧另记；报告定位首个差异帧、字段、双方值及必要上下文。
- 反例：修改固定一帧的输入或一个受比较字段，要求报告检出；删除、重复和错位帧也必须失败。
- 当前入口：共用 Replay verifier、各作 native 对照以及字节证据辅助器；每种状态映射和样本由本作声明。

### VERIFY-07 | 观察与正式行为

- 对照诊断核心和正式 Runtime 的编译选项、生产源码与观察接口。重复读取状态前后比较权威数据，要求观察只复制；再通过正式入口播放 Demo 或接收真实输入。
- 反例：观察函数推进游戏、写入输入或改变状态，必须由读取前后的状态比较检出。
- 当前入口：正式包浏览器在独立 Runtime 导航中通过 Shell 导入同一 Demo，沿用本作标题到 Replay 的入口与 120 个逻辑步暖机，再逐逻辑步保留两次原生读取。`presentation-production-replay.mjs` 将正式包与诊断基线的公共状态、68-word trace 和 Replay 消费环对照，报告首个分歧边界。诊断专用状态槽位按源码所有者排除；构建凭据、输入 SHA 和保存的实际读数共同约束结果。共享判定和中央验收均重开原始文件。

### VERIFY-08 | 本作状态与结束点

th08 的 Quick／Daily 共用同一逐步采集器。v3 捕获为每个应用步保存 ReplayStream 的 loaded、frame、输入游标／块长度、timing 游标／块长度和 stride；权威行绑定自己的应用步与游标，筛选原因独立计数。读取器重新核对账本与行文件，缺行、重复、倒序或不符合原生推进规则的游标变化均保留未完成证据。原生 `ReplayPlayback::after_update` 在对话中按三帧、快进模式按五帧重入 Chain；同一应用步内的消费增量必须与 trace 帧增量一致。实际导入的 Replay 与 DATA 身份来自本次 Runtime 会话。

捕获身份同时核对作品、采集适配器版本、当前原生 ABI 与正整数 Runtime 代次；不同作品、旧接口或缺失代次的记录在比较前拒收。

RNG 首差异可在诊断构建中按 Chain 优先级定位消费来源。`audit_rng_enable(1)` 开启只读计数，`audit_rng_counts()` 返回本应用步的129个32位计数：0–63为计算优先级，64–127为 Draw 优先级，128为 Chain 外调用。统计限定为当前 GameApplication 的共享 RNG，默认关闭，普通构建不导出该接口。先保留不可变参考的最早差异，再读取该窗口的 owner 增量，继续追查具体 ECL、实体或动画路径。

敌人任务的细分记录由 `audit_rng_details()` 与 `audit_rng_detail_status(field)` 读取。status 字段0–5依次为版本1、容量2048、记录数、下次写入位置、覆盖条数和每条5个32位字。记录按环形顺序保存 category、敌人slot、arg0、arg1与调用增量；category 1–8依次为 Timeline、ECL、动画、接触与伤害、死亡、收尾、特效和道具。特效参数为kind／count，道具参数为kind／mode。增量包含嵌套调用，外层阶段与内部特效不能重复求和；覆盖条数非零时保留丢样状态。

`PlayerScene::effect` 的叶子调用使用 category `0x100 + owner`，范围为 `0x100–0x180`，arg0／arg1 分别保留 kind／count，slot 沿用当前敌人槽。读取器减去 `0x100` 得到所属 Chain owner；调用增量已包含在外层阶段中。零 RNG 调用不进入 detail 环，缺少叶子记录不能单独证明该分支没有执行。

`audit_rng_enemy_snapshots_v1()` 按接触前后、伤害前后及死亡前记录生命、状态位、掉落、死亡特效、父对象、ECL 子程序与位置。配套 `audit_rng_enemy_status_v1(field)` 使用相同的六字段环形元数据，每条15个32位字，位置三个字按 Float32 读取。父对象通过与已知池条目比对得到 slot；无父对象为 -1，未知非空引用为 -2。该观察用于定位候选内部的分支，原版对照沿已接受的独立来源比较。

比较先报告最早逻辑帧差异，再保存阶段／分数终态校验。显式未完成的相同前缀记录为 incomplete；声称自然完成却比参考提前结束，继续判为差异。原始 flags 保留在捕获文件，活动 Replay profile 将标题菜单内容可用性与路线来源分别列为元数据，游戏输入、RNG、practice、active、Replay 和 spell-practice 状态照常严格比较。

- 在本作指南登记字段来源、类型、单位、阶段、席位和结束条件，用独立固定状态逐项校验映射。构造正常完成、尚未完成和提前中止，要求结果分别正确。
- 反例：把应用帧当世界帧、把席位 0 当本地席位，或把菜单状态当回放完成，必须由固定夹具和运行边界检出。
- 当前入口：通用 Replay parser／policy 与 `runtime-observations.mjs` 提供跨作品观察约定；TH08 的 capture／golden suite 独立位于 `tests/adaptation/adapters/titles/th08-replay.mjs`，由 quick 与 daily 两个本作 gate 调用。通用 Replay driver 的导入身份不包含其他作品源码目录，方便新作稀疏检出后直接接入共享流程。维护 `state-schema.json` 的作品同时核对该表。新增或改变映射时，检查受影响作品和变体。

## 测试辅助器

共用 protocol-host 站点通过本地 HTTPS 提供经过身份核对的 Runtime、DATA 和字体。每次运行创建独立的一日 localhost 证书，测试浏览器按该证书的 SPKI 指纹接受连接。报告保存证书身份，并逐响应比较浏览器实际收到的字节数和 SHA-256；Host 与 Runtime HTML 同时记录响应头、缓存和 Service Worker 状态，身份不符时保存浏览器的原始响应供复核。站点关闭时释放连接并清理临时证书。工具使用 OpenSSL，可通过 `EAGLER_OPENSSL` 指定可执行文件。

响应采集在资源到达时启用独立 CDP 字节流，依次保存已缓冲的前缀和后续数据块；已结束的资源通过响应体接口读取。未压缩响应的流字节数与 `Content-Length` 不符时，重新读取完整响应体，最终身份仍由原冻结文件的字节数和 SHA-256 判定。默认单资源预算为 256 MiB，总预算为 512 MiB，超时和超出预算均进入失败结果。`contentIdentity` 由实际字节数和 SHA-256 判断，`transport` 保存原始完成或取消事件；完整字节身份与浏览器传输终态分别可审查。截断、替换或无法取得内容的响应不能通过身份核对。

离线路径边界反例单独保存预期拒绝响应。只有唯一请求、作品、Runtime 代次、读写操作、固定越界路径与原生拒绝文本全部匹配时，才从协议错误审计中分离；其他 Runtime 拒绝继续判为错误。

th06／th07 的输入清单必须提供 msgothic 与 unifont。配置完成后读取 Runtime 文件系统中的两份字体，核对实际安装字节与输入的大小和 SHA-256。若浏览器对同一代唯一请求记录 `ERR_ABORTED`，只有完整响应、安装结果和所属代次全部吻合，才能归为已完成消费的取消；原始请求失败与对应证明均保存在报告。截断、替换、重复请求、未知来源及其他网络错误继续使验收失败。基础 Runtime 检查在实例关闭、收齐事件后再次审计错误，再生成最终状态；最终关闭不会把当前代的未完成资源请求归为预期取消。

Replay 浏览器验收将播放场景与原版格式兼容状态分开记录。场景通过要求正式 Shell 导入、默认速率实际推进 120 个原生帧、观察到 Runtime `ended` 终止信号，并通过本作适用的原生计数自一致性检查。终止信号只记录 Runtime 状态；当前接口不能区分场景退出原因，报告将完整输入消费标为 unproven。各作原版计数与 native cursor 的单位关系按本作来源单独声明，TH11 保留 cursor、total 与阶段 metadata 的原值。候选计数和数值差异保留为观察项，只有绑定到同一输入且计数语义一致的原版终点才能完成 REPLAY-01。

桌面普通版 Runtime 验收使用 `node tools/ports/runtime-browser.mjs --manifest=/absolute/private-inputs.json --game=th06,th07,th08,th09,th10,th11,th15,th20 --variant=normal --gamepad --output=/absolute/results`。此入口运行普通版 protocol-host 场景；MP 使用下文真实房间入口，选择受支持的 2P/3P 与 RTC/Relay 路径。输入清单逐项声明 `id`、`game`、`variant`、Runtime 包目录 `runtime`、入口 `entry`、私有 DATA 路径 `data`、期望 `packageSha256`、仓库相对 `sourceRoot`、`buildReceipt` 和 `packageReceipt`，共用字体放在 `shared` 字段。源码收据使用 `eagler-touhou/runtime-source-build/3`，登记 `game`、`variant`、`profile`、`executionSha256`、完整 `sourceFiles`、`requiredSubmodules` 与编译 `outputs`。验收器逐项核对当前源码、产物包哈希、执行 WASM、编译加载器与 DATA；清单缺项、私有 DATA 缺失或源码／包身份不符都会使对应目标失败。

`requiredSubmodules` 逐项记录路径与提交，并与当前构建配方及 Git 子模块指针相符，无子模块依赖时为空数组。`outputs` 绑定 WASM、编译加载器，以及 CMake 的入口 HTML 或 Node 构建清单；这些文件在打包前后和浏览器验收时核对原值。`planSha256` 绑定实际命令、参数、工具链、特性和环境，打包与验收同时核对构建计划。Runtime 桌面验收执行 13 项必需契约。Replay 文件管理使用清单中本作的 `replay: {path, bytes, sha256}`，指定已有有效录像的绝对路径、字节数和哈希，经过真实导入校验后检查读取、列举、同步、新代恢复及删除持久化，并复核输入原值。录像播放另行验收。

输入清单还须提供仓库相对的 `packageReceipt`，由正式 `package-runtime.mjs` 入口生成。`eagler-touhou/runtime-package-build/1` 将完整目录字节、当前源码构建收据和打包控制文件绑定在一起；验收器逐项重新核对。统一的 `packageSha256` 覆盖游戏、模式、入口及有效载荷文件，发布目录转换为不可变代际后继续使用同一身份。

普通版和房间场景结束后再次核对当前源码、构建计划、收据及 Runtime 全部字节；房间场景同时复核 Launcher 当前提供的本作代际。运行期间的源码或产物变化会使本次验收失败。

普通版入口要求显式指定 `--game` 和 `--variant=normal`，并完整执行所选作品。记录包含包与源码构建身份、暂停与重开前后状态、已同步用户文件的刷新恢复、旧代请求拒绝及当前驱动身份。条目中的 `complete` 表示是否覆盖该编号的完整操作；分项截图与状态用于复核具体行为。

文件事件在报告中保存字节数和 SHA-256，存档原始字节写入本次输出的 `user-files/`，便于独立复核持久化结果。

支持版本化观察的 Runtime 导出 `<作品>_native_observation_v1()`，返回 12 个 `u32`：版本、有效位、阶段、已消费输入、世界逻辑帧、重开归零帧、暂停、多人逻辑帧、坐标 x/y 的 float32 位模式、应用帧、本地席位。读取只复制本作权威状态，有效位明确当前可观测字段。应用帧与呈现帧分别记录，MP 输入和坐标归属本地席位。

输入场景等待原生可操作阶段后执行，普通版核对席位 0；重启遮罩和结算画面分别记录。暂停检查世界逻辑帧保持，重开同时等待原生可操作阶段与逻辑帧重建条件，保存首次满足条件的边界观测，再核对世界继续推进。

th15 的独立输入上下文记录本地席位的生命阶段、幽灵状态、场景标志与对话状态，用于解释输入就绪条件。行为判定继续读取主观察接口中的已消费输入和位移。

报告保存实际传入浏览器的观察函数源码及 SHA-256，并附观察断言、录像输入验证器与手柄映射 bundle 的源码身份，供独立复核本次判定。

th20 的普通游戏按主菜单、难度、角色、石头选择逐页等待原生就绪后确认。重开按原作确认页操作，等待可输入后选择“是”，再检查世界重建与继续推进。th06／th07 的经典 Emscripten 页面从其全局 `HEAPU8` 读取同一只读观察 ABI。

th08 MP 从 `multiplayer_status` 按原生本地席位选择输入与坐标，并用 `multiplayer_netplay_status` 的世界就绪和已模拟帧判断进度。普通版沿用其单人状态导出。

th08 普通版的 `input.value` 来自 `diagnostics[11]`，读取 `player_state.input.buttons` 在整个应用更新结束后的发布值，报告标明 `snapshotPhase=after-application-update`。普通录制局的玩家更新在 priority 9，录制发布在 priority 17，此时的发布值将供下一次玩家更新消费。精确释放检查把桥接收到的输入、已发布的排队输入与实际移动 Tick 分别记录，按本作消费顺序核对边界。

行为断言读取正式 Runtime 已公开的原生输入、玩家坐标、逻辑帧、暂停阶段和呈现计数。方向操作在进入关卡后核对按下、位移与松开；暂停和重开按本作对应的逻辑状态判断。进入关卡、手柄采样、原生输入生效分别记录。键盘与手柄行为完成须同时具有原生输入变化、方向位移和释放证据。截图与无只读观察器的操作单独记为 `observed`；必需行为缺少通过记录时，目标状态为 `incomplete` 并返回非零。加 `--gamepad` 执行必需的原生手柄取样与效果检查。呈现计数和应用 Tick 按各自职责记录，观察器与必需场景由 `tools/ports/runtime-observations.mjs` 集中维护。

键盘操作共用完整的协议事件构造，按下与松开均包含 `location` 和独立请求身份。验收报告核对 Runtime 对这些输入的拒绝响应，并以原生效果判断操作结果。

真实多人房间可运行 `npm run ports:rooms -- --url=http://127.0.0.1:8130/ --manifest=/absolute/private-inputs.json --game=th11 --players=2 --route=rtc --output=/absolute/results`。驱动先从同一私有清单验证所选 MP 包的 builder receipt、当前源码哈希和包身份，再核对 Launcher 当前代及其每个服务字节与该包身份相同，随后通过产品卡片、建房、入座、准备和开局控件进入 Runtime，记录实际通道、席位、原生帧推进与截图。目标缺失或不支持所选人数时立即失败，不会跳过。`--route=relay` 验证 Relay 路径，`--players=3` 选择本作支持的三人场景。桌面浏览器验收不代表实体设备或原版资源验收。

启动 Chromium 前，驱动逐作核验本地 ZIP 的完整成员、每项声明的字节数和 SHA-256，以及 DATA 与本次私有输入的身份；未提供本地 ZIP 时，它核验同源 Release Catalog、Package Descriptor 和 DATA 字节。每个预检 HTTP 请求设有 5 秒上限并拒绝重定向。缺失或不匹配的作品会在报告中给出可执行的修复信息，该作不启动浏览器，其余资源就绪作品继续验收。每个席位在导入或下载后读取启动器原生资源状态，失败时点击界面重试一次并再次核验 `ready`；结果和错误文本按席位记录。每作结束后再次计算私有 DATA 与离线 ZIP 的字节数和 SHA-256，和预检身份比对，确保本次导入使用的输入保持一致。共享封面与站点图标作为独立 `siteAssets` 维度只检查和报告一次，不会被记成游戏 Runtime 失败。导入模式通过 `--packages=/absolute/packages.json` 提供作品到本地 ZIP 的映射，驱动使用房间设置中的导入按钮和文件选择器安装。ZIP 由 `package-server.mjs` 和 `package-offline-game.mjs` 生成，测试配置与私有游戏内容放在本地证据目录。

为单作普通版准备验证站点时，`package-server.mjs` 可显式接收 `--runtime-variants=normal`，Runtime 输入只需要目标作品的 `--<game>-build`。此选项限于 `web-validation-*` profile；省略时仍按产品目录要求普通版与 MP Runtime，正式发布沿用该默认规则。

多人命令加 `--disconnect` 后关闭一个实际客户端，检查另一端收到离开通知并停止推进。截图同时保存启动器界面与原生画布，驱动源码和哈希随结果保存。

加 `--lifecycle` 执行全席暂停、恢复、重开与第二局推进。暂停比较本作世界时钟，网络收包时钟继续单独记录；重开必须实际降低世界帧，提供代次的作品同时增加代次。加 `--spectator` 在开局前经房间控件申请旁观，核对服务端名册与原生回放推进，并检查旁观端右移、射击和低速键不进入任一玩家的原生输入。旁观报告保留具体操作范围和 `complete`，对应方法见[多人检查](multiplayer.md)。

断线通知包括当前通道的恢复状态或已结束状态。驱动检查共用返回按钮、原生帧停止与返回同一房间，保留当时的通道状态和提示内容。

th08 MP 断线另核对组合式世界进度：关闭前确认同一关卡处于实际游戏状态，敌机帧、控制 tick 与网络完成帧均前进，并单独记录已确认帧与已完成帧的差值；只要帧前沿一致且没有开放帧或纠正过程，短暂的预测确认滞后不会掩盖活跃世界。通知后等待网络前沿和纠正状态收敛，并在通知、800ms 与再过 250ms 的观察中核对上述计数、玩家坐标和世界状态保持一致。

多人驱动逐席核对页面、Console 和 Runtime 协议错误。主动关闭之前的错误直接进入失败结果；关闭后的预期通知必须与同席位原生错误、实际关闭席位及操作时间一致。Runtime 协议载荷保留无 `Error:` 前缀的原始传输文本，只有来源、席位、原生状态与关闭时间全部吻合时才按精确消息匹配；Console 错误仍按其完整首行匹配。返回按钮关闭同时记录请求时间和页面实际 click 事件时间，并要求成功回到同一房间；事件必须晚于 click。断线检查覆盖每个存活客户端的通知、停帧和返回房间。

逐作房间验收为每作创建独立浏览器进程，完成后释放进程与三个席位的资源。两个桌面入口在解析输入前建立带唯一运行身份的报告，并原子替换旧结果。初始化错误、缺失输入和执行异常写入本次失败记录；验收证据同时核对当前运行身份、完成状态及进程退出码。

两个浏览器入口均可加 `--gamepad`，使用标准虚拟设备和生产手柄映射，观察正式 WASM 的同步取样。普通版和房间中的每个本地席位都须在原生玩法阶段确认射击、低速与方向按下改变了本机实际输入，方向键推动本机角色，松开与设备断开后输入恢复中立。多人探测按每个房间席位读取原生输入与坐标；缺少席位、输入或位置观察能力会使该席位失败，映射桥采样本身不作为通过证据。该分项记录桌面 API 输入路径，实体控制器与 USB／蓝牙兼容性另行验收。

手柄效果报告同时记录动作与阶段、完整原生观察、最近的映射取样、等待次数和耗时，便于定位各本地席位的实际输入状态。

多人输入操作在截图之前执行，并逐次检查原生可操作阶段。截图附当时的原生状态，场景切换或受击造成的前置条件变化单独定位。

虚拟设备与其生产映射 bundle 在同一个浏览器初始化脚本中按顺序安装。运行报告分别保留页面异常、Console 错误与 HTTP 失败，初始化错误可直接定位到驱动入口。

普通版驱动的每次页面导航都显式携带实例代次。导航前退休旧实例，并按请求开始时所属的页面及祖先记录归属。已退休实例的浏览器导航取消单独保留；当前实例、未知来源、HTTP 错误和其他网络错误继续进入失败检查。

在 `launcher/` 运行 `npm run test:support`，检查浏览器辅助器、独立 Package 模块准备、当前键盘入口和本地 HTTP 服务。历史场景输入从固定夹具读取并校验哈希，当前代码沿用生产模块。根 CI 在界面行为任务中执行这组检查。

开发服务的 HTTP 检查读取清单中的字体别名并核对响应字节，同时保持游戏 DATA 身份与每次运行的 Relay 配置。字体路径发布与游戏内容身份分别验证。

真实启动器驱动先等待首次使用提示进入可操作状态，再通过关闭按钮继续。前端启动信号与提示弹窗的显示分别等待，保证首次进入和已有偏好的流程都按实际界面执行。

独立 Package 服务通过父进程管道管理生命周期，结束检查时关闭管道并等待服务退出，同时核对端口释放和临时站点清理。

Windows 本地发布检查验证 `EAGLER_ATOMIC_DEPLOYMENT_UNSUPPORTED_PLATFORM` 提前返回且无写入；POSIX 检查验证目录符号链接原子替换。预备目录刷新另行验证共享锁重试、完整候选检查和失败回滚。按实际平台记录对应结果。
