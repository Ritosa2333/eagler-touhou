# 验证记录模板

将下表复制到本作 `docs/verification/` 下的新记录，文件名包含日期和检查主题。结果文件可放在同目录，或链接到对应 CI 运行及附件。

| 字段 | 填写内容 |
| --- | --- |
| 提交 | 完整 commit SHA；有未提交修改时附补丁或树身份 |
| 源码 | 例如 `ports/th10-mp` |
| 构建 | `normal` 或 `multiplayer`；Runtime 文件哈希和编译选项 |
| 公共库 | 本次构建使用的 common 来源记录 |
| 环境 | 操作系统、浏览器版本、设备、显示刷新率 |
| 网络 | 联机时填写通道、人数、延迟与抖动设置 |
| 检查编号 | 本作 ADAPTATION.md 中的编号 |
| 方法 | [验收方法](test-methods.md)中的输入、前置条件、观察字段、断言和结束边界 |
| 预期依据 | 行为规格、独立固定夹具或原版实际执行的来源 |
| 操作 | 可重复执行的步骤、输入和样本 |
| 反例 | 破坏的行为、预期失败和实际非零退出结果 |
| 结果 | 实际观察到的结果及差异 |
| 附件 | 日志、逐帧对照、截图或测试运行链接 |

## 逐项审查表

自动结果沿队列报告汇总，无需逐编号人工签字。人工每行对应一个场景集，可关联多个编号；一组记录一次结论，发生异常时补充对象与时间范围。方法链接到分项指南。

| 关联编号与场景集 | 检验方式 | 准备和操作 | 通过时应看到 | 实际观察 | 本组结论 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |
| 多个编号 \| 本次场景集 | 人工／组合 | 起始状态、输入、结束步骤 | 具体画面或感官现象 | 问题对象与时间，或引用整组素材 | 通过／发现问题／素材不足 | 本次报告、帧图或录屏及时间范围 |

自动检查链接驱动已有的断言与实际结果。人工场景集填写一次审查者、时间、设备与观察范围，结论选择通过、发现问题或素材不足。通过时工具关联整组素材，发现问题时记录具体对象和时间。组合检查按各自范围汇总机器与人审结果；机器检查缺失或失败由测试处理。

## 显示人工记录

按[显示审查表](presentation.md#人工显示审查表)集中查看已准备的场景素材，整组记录：

| 字段 | 填写内容 |
| --- | --- |
| 审查者与时间 | 实际操作人的姓名或标识、审查时间 |
| 显示环境 | 显示器型号、系统当前刷新设置、浏览器及版本、系统及版本 |
| 运行范围 | 作品、模式、场景、Replay 或固定输入、对象类别和逻辑帧范围 |
| 自动结果 | 相应的逻辑步进、状态纯度、对象身份与提交采样报告 |
| 视觉结果 | 整组结论与素材；异常时附问题对象、时间和现象 |
| 报告绑定 | 原始报告文件名、UTF-8 字节数和 SHA-256，关联 Runtime、DATA 与 Replay 身份 |

Presentation Lab 将多个窗口放入同一素材集，导出一次明确的人工结论。工具记录各窗口的产物、输入、对象、帧范围和图像身份，审查者与设备信息在本次会话复用。通过无需另写逐编号文字；发现问题时附对象、时间和现象。素材集变化后重新选择结论。人工视觉结论与自动状态判定分别保留，并按各自范围汇总。

完成后，在 `ADAPTATION.md` 的对应模式填写状态，并链接这份记录。后续修复使用新的记录，便于比较两次构建。

## 逐项结果回填

将本作的集中审查结论保存到 `docs/verification/adaptation.md`，用 `adaptation.json` 登记逐项摘要。沿 th08 的[记录示例](../../ports/th08/docs/verification/adaptation.md)与[数据示例](../../ports/th08/docs/verification/adaptation.json)填写本作名称、日期、审查提交、模式和全部清单编号。证据保存原报告相对标识、字节数、SHA-256、实际运行时间与源码身份；原始文件和私有路径留在本地。

每项分别写已测行为和后续操作。“已验证”对应完整判据接受的实际范围，“部分验证”写清行为缺口、判据接入或材料范围。人工整组结论按实际素材关联编号。构建、浏览器和原版对照各自保留原运行身份，复算沿用证据保留原采集时间。

`ports:check --write-status` 读取这份摘要并在适配表中并列展示源码检查和运行验收。文档检查核对清单完整性、适用模式、证据引用和表格状态，源码检查更新时继续保留逐项运行记录。
