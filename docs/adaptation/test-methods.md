# 验收方法与新作品接入

本章为适配编号定义可复用的检验方法。是否已实现和执行，由本作适配表与带产物身份的报告说明。共用驱动执行操作，本作适配器读取权威状态，报告把断言绑定到当前普通版或 MP 产物。

[适配入口](README.md) | [逐项操作](validation.md) | [执行入口与环境](../../tests/README.md)

STG 按[阶段流程](stg.md)接入。通用操作与断言沿用共享驱动，本作提供状态映射、导航、输入语义和结束条件。非 STG 的玩法使用对应类型的适配器，构建、协议、存储和共享控件继续按各自契约验证。

先在一作的一个模式完成整套方法：构建、启动与生命周期、输入与触控、画面与声音、存档与 Replay、语言与练习，以及安装与离线。按全部适用编号核对自动断言、人工操作和二者需要合并的证据，再扩展其他作品和 MP。共享检查的通过范围由真实操作与观察决定。

## 一项测试怎样证明功能

编写或审查测试时，按下表说明方法，并在本作开发指南链接实际入口。同一方法覆盖多个编号时，逐一注明其断言。

| 内容 | 必须说明 |
| --- | --- |
| 对象 | 适配编号、作品、普通版或 MP，以及场景或样本范围 |
| 输入 | Runtime、DATA、录像、字体或原版程序的来源与哈希 |
| 前置条件 | 如何判断菜单、关卡、暂停、房间席位等状态已就绪 |
| 操作 | 用户输入、持续时间或逻辑帧数、释放与退出步骤 |
| 观察 | 来自哪个生产状态或外部结果，单位、归属席位和采样边界是什么 |
| 判定 | 必须成立的断言、允许变化的字段、结束条件与超时 |
| 反例 | 故意破坏哪种接线或行为，期望出现哪条失败信息 |
| 记录 | 执行入口、驱动身份、产物身份、实际结果与首个差异 |

预期值来自独立规格、已接受的固定输入或原版实际执行。需要改变预期值时，先说明行为标准；测试同时保存改变前后各自的证明范围。涉及数值差异时，写清比较的是逻辑状态、连续呈现位置、像素网格还是最终图像。

同一条记录可以支持不同职责的检查。音频按[事件守恒、实测延迟与受控增益](presentation.md#audio-06)分别判定。主线程 AudioParam 调用时钟保留为调用证据，受控未来帧的增益生效点通过预先排程的离线渲染核验。即时调用的逐点对照作为有来源的诊断保存。

输入观察注明采样阶段：桥接收到、原生采到、已发布待消费、动作实际消费各有自己的边界。动作效果与消费帧关联；存在原生输入管线的作品，按源码确定的顺序及实际排队输入核对过渡帧。

规则依据同时包含协议、分项指南、各作源码和已接受的对照。触控基准沿 th06 `Touch::GetPlayerDelta`／`ConsumePlayerDelta` 与 `Player::HandlePlayerInputs` 核对余量、低速比例、原生速度、轴倍率及最终位置；音效沿 `SoundPlayer::PlaySounds` 到共享 `WebSfx` 核对实际输出。各作[运动数值适配](../../tests/adaptation/adapters/movement.mjs)明确位置单位、舍入和倍率作用顺序。固定点精度按该作规则计算独立预期，实际速度上限等共同行为继续执行同一断言。源码中的行为与明确要求冲突时，以可重现的生产路径结果定位问题，保留能够检出差异的测试。

### 人怎样审查方法

Presentation Lab 和输入驱动按实际模块导入收齐工具依赖，并把闭集纳入本次证据身份。新增共用判据模块随依赖链发布和复核。th08 的轨迹状态摘要覆盖原生固定数组全部点，活动长度改变时仍使用同一套读法。

自动项由驱动保存操作、预期、实际观察、结论与证据。方法审查关注独立预期和反例，日常执行直接使用机器结果。需要感官判断的内容按[审查表](record-template.md)集中为场景集，一组结论关联多个编号；审查者记录异常对象、时间和现象。

统一队列生成的 `review.md` 默认呈现精简的人审场景集、自动结果计数和执行问题，逐编号的方法与证据折叠供追查。人审场景由 `checklist.json` 的 `humanReviewBundles` 明确登记，集中检查显示观感与文字排版。自动结果直接带入指南中的操作、通过判据、执行结论和证据，无需再次逐项签字。未关联任务和失败项由测试补齐或修复，保持各自的机器状态。

“未关联自动任务”表示当前统一队列没有该编号的自动任务。是否已有人工方法、是否需要现场判断，以及功能的实际结果，分别沿方法和审查记录核对。

逐编号的具体方法放在各分项指南的“可审查的验收方法”，与表内编号对应。审查时先看操作能否触发目标行为，再看观察是否来自真实结果，以及反例能否检出常见错误。输入已发出、函数已调用或页面有截图，各自证明到对应步骤；功能效果由单独的结果断言证明。

审查者应能在运行测试前说明一个会被检出的错误。预期值不能由待测代码生成，结果缓冲区也不能预填预期值后再声称读取正确。方法、样本、比较字段、允许误差和结束条件发生变化时，文档与实际断言一起审查。报告给出实际测试入口及范围，便于沿编号找到代码核对。

`npm run docs:check` 核对清单中的每个编号都有可见的方法、反例和当前入口说明，并拒绝漏项、重复和放错分项。方法是否能证明功能，由人结合独立预期和实际断言审查。

## 各类功能的验收方法规范

| 功能 | 操作与观察 | 判定重点 |
| --- | --- | --- |
| 源码与构建 | 逐变体执行正式构建和打包，核对工具链、依赖、输入与全部输出 | 当前源码、构建计划、WASM、加载器和包字节对应同一次有效构建 |
| 协议与生命周期 | 经过真实 Shell 发送配置、启动、暂停、重开和退出操作，读取响应与原生阶段 | 身份和代次正确，世界在暂停时停帧，重开后重建并继续推进 |
| 键盘、手柄与触控 | 经过生产输入入口执行按下、移动、组合键、释放和取消 | 原生消费的按键与本地角色效果一致，释放后回到预期状态 |
| 呈现 | 在确定的逻辑状态插入额外绘制，比较前后状态和绘制结果 | 逻辑状态保持，连续字段按既定规则变化，离散事件和材质、顺序正确 |
| 声音与音乐 | 选择已知曲目，采集实际输出，切换音量、暂停与恢复 | 曲目身份、PCM 或频谱、响度变化和恢复边界符合预期 |
| 存档与 Replay | 使用有效样本导入、播放或修改，再同步、重新启动并读取 | 文件持久化与游戏语义分别断言；播放覆盖声明的完整输入和结束点 |
| 语言与练习 | 选择语言或练习参数，进入指定菜单、对话或关卡 | 实际显示内容、字形与进入的游戏状态匹配所选配置 |
| 多人 | 启动真实房间，逐席操作，测试支持的人数、通道、退出与规则场景 | 每席输入归属、帧推进、状态收敛、资源和退出行为均有独立结果 |

实体控制器与触屏按硬件矩阵集中安排设备会话，一次操作采集多项行为的机器观察。高刷新显示器的视觉判断沿显示场景集记录。设备记录附型号、连接方式、刷新率和驱动版本，桌面虚拟设备结果保留软件路径身份。

### 一次就绪，执行一组场景

以作品、模式、启动配置和可操作场景组成执行组。一次构建与打包、一份身份核对、一次导航之后，在同一局依次运行输入、触控、暂停、声音等兼容场景。每项先确认就绪，结束时释放输入并恢复基线；无法恢复时只重建该组。需要不同音乐、触控模式、语言或练习配置时建立新代，产物和公共输入继续复用。

桌面驱动按实际选择建立触控配置代次。只选后台场景时沿用当前普通玩法；输入与共用运动组统一执行方向式摇杆及连续移动配置。动作组复用同一局检验生产触控控件和原生玩家消费者，未选择的场景列为 omitted。

按编号重跑时，统一入口把编号传入桌面驱动。驱动保留产物与 DATA 的前后核验，并在原有场景组内选择对应断言和配置代次。例如 `--check=TOUCH-03 --suite=desktop-input` 执行八方向摇杆及释放，其他移动、音频和后台场景列为 omitted；完整输入组继续执行全部登记断言。

作品可提供无出怪的练习场或固定 Replay 片段来稳定角色位置和音效触发。场景设置与状态观察分开：设置用于准备场景，检验仍走生产 Pointer、键盘、音频和存储路径。练习场的结果绑定该场景；伤害、出生销毁、切关、Replay 和多人规则由对应场景验证。设置、恢复与就绪逻辑集中于作品适配器，执行和断言沿用共用驱动。

th08 普通版的 `touch-motion` 和 `desktop-input` 在空关卡显式准备输入场景，保留原生玩家、输入、运动和逻辑 Tick，只暂停 ECL 时间线的执行。共享[场景适配器](../../tests/adaptation/adapters/scene.mjs)在共用运动场景逐 Tick 核对敌人、弹幕、激光均为零，世界与玩家所属逻辑继续推进，时间线确实经过暂停入口。场景按 Runtime 代次复用，新世界恢复正常时间线；本 Runtime 会话保持测试身份，导出的保存操作与原生文件写入口拒绝持久化，包括退出时的自动分数和配置写入。伤害、对象生命周期、切关、存档和 Replay 使用各自的正常世界与新 Runtime 会话。

菜单中的真实事件也可组成稳定场景。`audio-latency` 使用本作标题状态与生产音效映射，在同一 Runtime 先执行正常输入，再执行实测队尾延迟反例；共用驱动保留首帧、目标上传、PCM 和前后产物身份。标题场景记录标题就绪，玩法场景记录玩法就绪，每个 Runtime 代次各有对应的权威状态证据。

桌面输入音效先聚焦 Runtime canvas，保存文档可见性、实际焦点与活动元素，再将同一 SDL3 `AudioContext.currentTime` 上的可信 keydown→keyup 边沿作为音效归因区间；发送前至原生确认松开的外层窗口另保存同阶段的 baseline、held、released 玩家消费者快照，核对实际射击消费、玩家弹数增加及松键清除。生产 `WebSfx.started` 必须落在按键边沿之间，PCM 由共享并行输出 tap 按 voice 与 tap 身份采集，并保留同 voice 的每次重触发及样本。多个新 voice 或时钟/消费者证据不完整时记录为未完成；CDP 往返时间只作诊断，不参与输入与音效关联。

桌面驱动在浏览器关闭前统一采集 Host 协议记录、Runtime 状态及错误提示。启动失败和超时同样保存这些观察；输入清理与末次截图后再次核对协议、页面和本地 HTTP 错误，晚到错误也进入本次失败判定。

`desktop-input` 使用 headless Chromium 验证生产 DOM 输入到 Runtime 桥接和原生效果，并检查 Host 与 Runtime 文档的可见、焦点状态。headed `desktop-background` 使用实际 Chrome 页面与窗口身份，启动资源前恢复正常窗口、核验 Host 与 Runtime 焦点；配置完成后再次恢复并核验同一页面与窗口身份，再发出 launch。每次检查都保存恢复前后的实际状态。首个 Runtime 启动前无法取得原生文档可见性与焦点时，任务以环境前置未完成封存；已经进入执行的前后台转换继续按实际状态判定，身份、协议和清理错误保留失败。窗口最小化和同窗标签页后台行为由 headed 生命周期场景实际操作。

`music` 组按产品目录和各模式源码归属列出 AUDIO-01／03／04／05，并为声明 MIDI 的产品增加 MIDI-01 至 MIDI-04。每项只运行已登记的观察，其他适用编号明确列为 blocked；普通版和 MP 分别记录。编号选择复用相应场景组，结果按所选编号与实际观察范围判定。标准 `runtime-music` 入口也调用这一队列，新增产品随目录进入检查。

损坏 OGG 场景直接观察 Runtime 输出，保留解码拒绝状态与资源诊断，并在同一已识别的 AudioContext 上采集八个时钟推进的 PCM 窗口。无声结论以实际零 PCM 为依据；资源未进入播放状态时也执行输出采样。

前后台恢复同时核对原生游标、曲目身份和恢复后的真实 PCM。采样支路随生产节点重连，保留原 tap 身份；观测器保持生产断开操作的原有结果。

### 例：方向输入

1. 等待本机席位处于可移动的玩法阶段，并确认世界逻辑帧前进。
2. 记录原生已消费输入、角色坐标和本地席位。
3. 从生产输入入口按下右方向，观察输入位变化和角色 x 增大。
4. 松开，确认方向位释放。每个方向分别执行，边界场景单独设置。
5. 改键场景从启动器配置开始，再用映射后的物理键执行同一组断言；同时检查原生监听器和清空路径。

当前 [runtime-browser.mjs](../../tools/ports/runtime-browser.mjs) 的 `hosted-keyboard-native-effect` 检查进入玩法、右方向、位移与释放：按下右方向后等待 180 ms，比较原生输入与 x 正向位移；释放后等待 150 ms，核对输入恢复。完整方向矩阵和改键场景按各自编号补齐。`browser-shell` 使用生产 Shell 接线并包含破坏接线的反例，结果范围为接线执行。

### 例：暂停与重开

记录可操作关卡的逻辑帧，执行暂停并连续采样，要求逻辑帧保持。按本作实际确认流程执行重开，等待重建边界、恢复可操作阶段，并再次确认世界前进。呈现计数与世界逻辑帧分别观察。

当前入口为 [runtime-browser.mjs](../../tools/ports/runtime-browser.mjs) 的 `native-pause-and-restart`，原生字段由 [runtime-observations.mjs](../../tools/ports/runtime-observations.mjs) 归一化。[作品流程适配器](../../tests/adaptation/adapters/title-flow.mjs) 集中普通游戏入口、玩法就绪和暂停重开确认，Runtime、桌面输入和练习驱动共同调用；th20 的符石路径及重开确认在适配器中定义。MP 由真实房间驱动负责本机席位和就绪条件。

### 例：原版数值对照

向候选核心和哈希固定的原版程序提供相同输入，按逻辑帧或同一函数边界比较独立采集的状态。固定输入和参考文件在执行前后核对原值。首个差异保存字段、帧号、双方数值和邻近字节；录像比较还要求到达所声明的结束点。

共享报告写入器统一绑定本作来源。`original-only` 报告核对原版可执行文件的实际哈希，`candidate-comparison` 报告绑定候选核心哈希；场景数据提供观察与结论，来源身份由写入器生成。th15 普通版和 MP 的原版重开检查沿用同一判据，各自记录本作文件身份。

候选核心的渲染位置涉及连续呈现时，先用整数网格与固定分数位移建立独立控制，再应用该路径的精确关系。其他字段继续执行各自断言。具体输入隔离和原版参考维护见[原版对照测试](../testing-oracle.md)。

## 下一部作品怎样接入

### 作品适配模块

[适配器登记入口](../../tests/adaptation/adapters/registry.mjs)集中加载作品模块。[th08 模块](../../tests/adaptation/adapters/titles/th08.mjs)当前登记普通版输入与音效声明；MP 需要单独声明其 Runtime 与观察接口。新增作品从同一结构填写本作含义，运动场景、数值断言、音效时序与队尾反例由共用驱动执行。

| 字段 | 本作提供 | 共用检查 |
| --- | --- | --- |
| `runtime` | 实际 Runtime 全局对象、core、Module、app 字段名 | 浏览器读取同一实例，不靠 URL 或作品名猜测 |
| `observation` | 显式选择 `native-v1`、已实现的旧状态映射或 `unsupported`，注明采样边界与输入消费语义 | 按有效位核对原生状态，缺导出、字段或席位时阻断断言 |
| `flow` | 有限菜单步骤、具名原生状态谓词、源码锚点、总预算及可选重开流程 | 进关、等待权威状态、暂停重开与超时；缺少重开声明时停止并报告未完成 |
| `clock` | 生产循环导出名及参数签名 | 停止自动循环、每次推进一个原生逻辑步、恢复自动循环 |
| `movement` | 原生整数单位、舍入、倍率顺序，`inputBoundary` 与 `inputBoundarySource` 声明消费时机和源码锚点 | 微移、连续方向、速度上限、灵敏度与释放，排队输入同时核对释放延迟 |
| `actions` | 版本化的玩家消费者快照、动作位、Escape 脉冲存活步数与源码锚点，明确区分已消费输入和排队输入 | 按完成的玩家逻辑步核对焦点、射击、Bomb 库存与状态；暂停中等旧脉冲耗尽，再以新边沿恢复并等待新的消费者序号 |
| `replay`、`parseReplayFrames`、`parseReplayExtension` | 录制与回放消费边界、生产保存／打开入口、trace 字段、原版与扩展格式独立解析 | 多种输入共用一份实际录制，按文件原字节核对逐帧录制、指针应用及同文件回放时的实时输入隔离 |
| `controlledScene` | 标题前预约导出、世界快照、生命周期与写入回执，以及启动期写入策略和源码锚点 | 在新世界首次逻辑更新和 ECL 时间线前接受请求，核对逐步进展及持久提交为零；按声明核对启动期 RAM 覆盖或无初始化写 |
| `audioLatency` | 音效、输入、菜单状态、实际接受输入的原生门槛及源码锚点、目标 voice 与源文件映射 | 输入门槛开放后发送可信输入，核对真实 PCM 起点和实测队尾负控，失败保存原生状态与输入边沿 |
| `deriveSfxContract` | 从生产音效表解析独立映射的薄函数 | 源表改变或上传、入队顺序不符时阻断运行 |
| `language` | 只读观察导出、语言表路径、实际消费键与源码锚点 | 从真实 Launcher ready 边界启用观察，独立对照包字节与冷启动原文，逐码点核对实际字形来源和同场景呈现 |
| `practice` | 快照 ABI、归一化解码、独立参数案例、菜单与本作控制操作，以及可选 Replay 格式能力 | 共用参数比较、配置消费、实际效果、菜单和语言旅程；跨页面只传 Runtime 挂载名与单个快照 ABI，标题解码留在 Node；Replay 保存、持久化、导入与新实例恢复由同一流程配对 |

登记器在浏览器启动前检查模式、单位、导出名与必需状态。共用读取函数接收可序列化声明，新增导出名和 Runtime 挂载名沿用同一个读取路径。`native-v1` 同时声明 Runtime 映射，观察从该实例的导出和内存取值；挂载缺失时立即阻断。普通版的接口不自动继承给 MP。驱动按模块实际导入闭集保存源码与哈希，新作品模块随依赖链进入前后身份复核。采样边界由本作生产源码与运动轨迹共同核对，12 字 ABI 携带的状态与有效位按声明解码。

以上登记分成共享执行入口与本作语义两层。注册一个模块不会自动证明它覆盖的编号；目录把选择映射到任务，驱动结果再按作品、模式、编号和结构化观察逐项复核。

稳定输入场景使用 16 个 `uint32`：版本、已启用、可准备、玩法就绪、模态占用、Replay、敌人／弹幕／激光计数、阶段、世界逻辑帧、玩家控制帧、已抑制的刷新次数、原有刷怪程序数、辅助场景标记及生命状态。原生接口只暂停刷怪入口，玩家输入和运动继续经过生产路径。会话在加载前锁定持久提交；自动初始化写入由作品策略声明，受控 Runtime 的持久提交字节必须为零。th08 在加载作用域内把自动 `score.dat` 写入 Runtime RAM 覆盖并报告成功；共用场景通过独立写入 ABI 核对尝试、RAM 覆盖、丢弃字节、拒绝次数和提交字节。普通会话保留原有的一次 RAM 更新与持久保存顺序。没有启动期写入的作品声明 `none`，共用断言不要求它伪造 RAM 写入。准备会改变场景时，在新 Runtime 中运行存档与 Replay 场景。

受控世界的准备与写入约束贯穿运动、动作和暂停。运动要求世界帧与控制帧各推进一步。当前原生 `pause.active` 成立时，控制帧推进一步，敌人帧与时间线计数保持不变；暂停解除后恢复逐步推进，普通运动继续拒绝模态占用。Replay 录制使用普通真实游戏世界，共享一次准备与保存；播放启动从原生首个消费帧开始留存 trace，加载期样本单独保留。

### 接入步骤

绘制与原版对照的本作路径、样本和结果语义集中在[诊断适配器](../../tests/adaptation/adapters/diagnostics.mjs)。共用诊断驱动管理一个本地服务，顺序执行 `presentation`、`quick` 和 `daily`，分别收集真实 WASM 观察或固定参考比较。所选字体、DATA、Replay、诊断包、构建源码和工具进入同一证据身份；场景选择和本地输入见[诊断与原版对照队列](stg.md#诊断与原版对照队列)。

1. 在[产品目录](../../common/contracts/product-catalog.mjs)、[源码映射](../../launcher/config/workspace.json)与[构建配方](../../launcher/config/runtime-builds.json)登记作品及支持的模式。按[适配表创建命令](README.md#4-建立并维护适配表)生成逐目录表格。
2. 在本作 `docs/DEVELOPMENT.md` 登记有效 DATA、录像和字体的准备方式，以及本作场景、输入位、逻辑帧、暂停和结束条件。普通版与 MP 分别列出差异。
3. 为正式 Runtime 提供只读状态观察。优先使用[统一观察 ABI](../../tools/ports/native-observation-contract.mjs)，从本作真实权威状态填值；MP 明确本机席位。观察函数只复制状态。
4. 在 `tests/adaptation/adapters/titles/<game>.mjs` 登记本作 Runtime、原生观察及 `flow` 导航步骤。在 `registry.mjs` 显式导入本作模块，并将声明加入 `createAdapterRegistry` 列表；登记器校验模块，共享 `title-flow.mjs` 执行流程。新原生观察沿用 `native-v1` 归一化字段；已有特殊 ABI 的解码留在本作映射。MP 通过房间驱动验证席位与联机生命周期。有效位、字段含义和边界用固定夹具验证，再运行正式包。
5. 对接本作需要的原版或 Replay 对照。使用 frozen-oracle 的作品，在 `oracle-suite.json` 分类每个测试并声明输入，提供本作核心构建入口和共享 native 输入策略；其他作品沿用本作已登记的验证入口。
6. `tests/adaptation/catalog.mjs` 从产品目录生成普通版、MP 和房间组合，通过 `tests/run.mjs --profile=adaptation` 统一选择、预览和执行。场景组声明适配编号、输入、驱动和时间预算；本作专项对照继续进入 `tests/suites.mjs` 及所属组件清单。新作接入后核对计划与报告均存在该作。给关键路径加入破坏行为的反例，检查封存断言失败与进程失败都会使队列失败。
7. 按编号补足本作方法：共用场景沿用共用驱动，特有机制由本作夹具与适配器提供。适配表填写本次实际范围，报告链接到对应模式和产物身份。

`--plan` 对每个可执行场景使用 identity reader 的输入预检分支，读取所选清单、Runtime 目标和本地包、DATA、录像等输入；失败的场景显示 blocked 及具体原因。预检不生成执行身份、不准备 Launcher 或构建、不启动浏览器。远端 Launcher 地址只校验 URL 格式；实际服务身份在执行前复核。实际执行仍独立计算来源、产物、输入与工具身份。

新作登记、表格生成、测试发现与完整行为覆盖分别核对。没有驱动、输入或有效观察的编号保持待验证；失败记录区分行为差异、测试错误和环境输入。每次修复依据明确的方法复验。

## 结果怎样进入适配表

浏览器身份按驱动实际参数记录。软件输入、触控和音效场景绑定 headless Chromium，桌面后台场景绑定实际 headed Chrome。Python 诊断采集绑定其实际解释器、Playwright 包、驱动和 Chromium 文件，Node 场景绑定本身加载的 Playwright；续跑分别核对所用执行文件与依赖版本。

单作执行按所选 Runtime 的源码与构建凭据绑定原生实现。Replay 参考读取再登记该样本实际使用的原版文件和源码锚点；其他作品目录可以缺席，基准原字节与本次候选输出各自保存。

统一队列读取实际驱动报告，并核对作品、变体、运行时间和封存状态。进程返回成功且内部断言失败时，任务记录 failed；缺输入、未执行和覆盖不完整分别保留 blocked、not-run 和 incomplete。桌面报告的 `adaptationIds`、其他驱动的 `checks` 共同汇入逐编号证据。按编号选择时需要 `complete=true` 的成功证明；场景执行结果和完整适配覆盖各自保留。

整作选择从 `checklist.json` 生成当前产品的全部要求，逐项应用产品与构建模式的不适用规则。缺少驱动的要求显示 unmapped，并阻断整作完成。指定场景组时汇总所选场景的要求，便于独立开发与复跑。

编号的完整证明同时包含结构化观察。驱动可将观察放入检查项的 `observation`／`evidence`，或用 `evidenceRefs` 的 JSON Pointer 引用同一报告的观察封套。封套用 `game`、`variant`、`adaptationIds` 标明归属，`observation` 保存实际状态、字节身份与操作记录。汇总核对引用的作品、模式和编号，保存指针及内容 SHA-256；封存子报告保存原值。元数据、其他检查的结论和说明文字分别保留自己的职责。静态源码接线、生产组件执行与真实产物行为按各自证明范围记录。

[完整证据判据](../../tests/adaptation/complete-evidence.mjs)按共享检查重新核对实际观察。驱动的 `complete: true` 是待复核声明；对应判据可用且实际证据满足范围后，汇总才接受完整结果。新增完整检查同时接入判据与反例；尚无完整判据的编号保留实际场景结果与未完成范围。练习 Replay 留存可重新执行本作格式判据的输入，包括保存、持久化和导入字节及原生初始应用状态。

计划中的每个编号都要有对应的实际结果行。已运行但观察不完整的结果保留实际原因，并与缺少结果区分；缺项、未知或缺前置条件会使场景保持未完成，外层进程成功不会补齐这些记录。房间驱动按人数、通道和所选旅程核对实际操作步骤与逐席结果。续跑核对前后身份，并从封存子报告重新复核逐编号结论、观察引用与场景结果。

续跑以作品和场景组为边界，检查当前驱动依赖、产物、私有输入、浏览器与旧封存报告的身份。沿用旧证据标为 retained，本次运行标为 executed；原始时间和报告哈希随证据保存。具体选择、输入配置与重跑命令见[逐作适配队列](../../tests/README.md#逐作适配队列)。

离线场景同时绑定 Launcher 构建入口与界面、服务、静态资源源码；Replay 续跑逐文件复核驱动实际选用的原生与参考输入。产品声明不支持的人数或模式记录为不适用，不影响已支持组合的完整成功证据。正式打包清单与构建矩阵按产品目录覆盖普通版和 MP，新作品登记后执行相同的身份检查。

执行场景与排除范围分别记录：基础离线报告列出本次导入和重新打开的结果，选用更新包时增加更新旅程。未选用的更新要求保留逐编号状态，基础场景可以独立形成完整成功证据。所选场景中的失败和最终浏览器错误审计始终阻断通过。共享准备按任务声明依赖，失败时保留准备证据，其他独立场景继续执行。[Launcher 场景准备](../../tools/ports/launcher-fixture-preparation.mjs)集中生成站点输入、核对 DATA 布局并管理本地服务生命周期。

缺前置条件的编号按本次选择判定：选中的编号缺结果或被阻断时，该组保持未完成；报告中另列的未选更新项继续保留状态。实际执行得到的失败与浏览器错误继续阻断本次场景。

`ports:check` 更新源码接口、模块检查和已登记构建结果。浏览器报告分别保存本次场景结果与逐编号 `checks`；每项检查记录 `complete` 和观察证据，房间报告还保存逐席操作、输入效果和生命周期结果。覆盖该编号全部操作的成功记录支持“已验证”；场景可通过自身断言，同时在覆盖汇总中保留 partial 或 blocked 项。

在[验证记录模板](record-template.md)填写方法、独立预期依据和实际执行结果，再链接到本作 `ADAPTATION.md`。共用驱动或观察规则改变时，复验全部受影响的作品和模式。
