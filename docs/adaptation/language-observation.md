# Runtime language observation

The language observation ABI records actual localization and font work from a fresh Runtime instance. It is disabled by default. After Runtime readiness, the shell enables it with `language_trace_enable_v1(1)` immediately before `sdl_prepare_next()`, then reads the receipt with `language_trace_json_size_v1()` and `language_trace_json_v1(pointer, capacity)`.

The size call includes the final NUL byte. The copy call returns the JSON byte count without the NUL and writes a terminator at that offset; it returns zero when the supplied buffer cannot hold the complete document. Strings are represented as hexadecimal source bytes, so UTF-8 and CP932 text round-trip without normalization.

Loaded MSG dialogue is compared directly with independently extracted archive members and the title-owned entry decoder. Its actual raster, glyphs and subsequent present form the proof; a localization lookup is required only for consumers that use that operation. Result navigation and read-only UI fields are title declarations executed by the shared finite scene driver. One language instance supplies title, statistics and dialogue material for the grouped text review.

The selected translation archive may replace MSG members through the declared mount root. Independent source selection reopens that exact archive; absent members retain their DATA source. A read-only native UI snapshot exposes consumed menu input and dialogue text alpha. Physical menu edges remain held until sampled or a declared transition occurs. Review capture stays within the same bounded MSG Wait and requires the declared text-alpha threshold before saving its image.

The document schema is `eagler-touhou/language-trace/1`. Its bounded event table stores 2048 distinct observation tuples. Identical complete tuples are summarized by `first`, `last`, and `count`; truncated strings remain separate rows. Font preparation glyphs use a separate bounded summary of up to 64 profile/source/result-flag groups, so warmup volume does not consume event slots reserved for Runtime work. `preparationGlyphs.observations` includes grouped and dropped preparation calls, while `preparationGlyphs.overflow` marks any dropped group. `droppedEvents` and `overflow` expose event-table capacity exhaustion; `stringTruncated` and the per-field truncation flags expose incomplete byte strings. A strict reader requires zero dropped events, truncated strings, and preparation overflow.

Events carry `kind`, `phase`, and the active `Scene` value from `SupervisorFrame.hpp`:

- `lookup` records the public operation, input key or fallback bytes, returned bytes, numeric identifiers, and record/translation flags. `operation` distinguishes spell, stage, music, spell-comment, ASCII, string-ID, and formatted-string lookups.
- `raster` records the bytes and encoding passed to the active text rasterizer, with font height and weight where applicable. `ascii-atlas` rows capture a string after its per-character sprite submissions complete; each `glyph` row still records missing atlas coverage.
- Runtime `glyph` rows record requested code, actual code, font profile, source, cache state, and requested/actual coverage. Preparation glyph groups aggregate by profile, source, and result flags. Source values are `bitmap`, `msgothic`, `pack`, `unifont`, `msgothic-notdef`, and `ascii-atlas`. A `.notdef` raster has no actual code and never claims coverage; the resolved source remains attached to cached glyphs for later Runtime rows.
- `present` records successful normal Runtime presentations. `a` and `b` are the first and last successful present sequence numbers in the summarized row. `first` and `last` are monotonically increasing recorder observation ordinals shared by lookup, raster, glyph, and present events; `count` is the number of calls summarized by that row.

TH08 samples the active `Scene` before the semantic draw in `sdl_loop_tick`, while `BrowserRuntime::present` records it after the backend reports a successful swap. The initial `Init`→`Title` transition can therefore change `scene` between a text raster and the successful presentation of that draw. Correlate an unchanged-scene presentation by requiring its observation range to extend beyond the raster; across a scene boundary, accept only the immediate next recorder observation (`present.first === raster.last + 1`) with a positive successful-present sequence. A missing, prior-only, unsuccessful, or unrelated later presentation remains incomplete.

`phase` is `prepare` for the bounded font warmup and `runtime` for normal title, music, practice, game, result, and ending scenes. Loading-screen submissions use a separate direct path and do not enter the Runtime present stream. Localization activation’s internal table validation is not a public lookup event.

The recorder uses fixed storage and performs no string copying or allocation while disabled. Producers append observations only after their real lookup, raster, glyph resolution, or presentation path runs; enabling observation never requests a key, font, or glyph from the game.

The browser journey verifies pending response bodies before a Service Worker control reload, preserving the byte evidence of the preceding document. Localization activation and successful pack-font fallback messages are classified by the current Runtime source and the verified mounted font path. Other console errors remain blocking. Actual Runtime glyph coverage and successful presentation are checked independently of these diagnostic messages.
