# 多人接入与规则

[适配流程](README.md) · [文档目录](../README.md)

先连接并同步开局，再验输入、游戏规则、回放和旁观。每个 MP 源码目录维护自己的表。

## 准备

本地多人驱动从同仓库 `services/relay/src/netplay-relay.mjs` 启动 Relay，从 `launcher/` 读取共用前端与协议辅助器。外置服务源码可通过 `EAGLER_RELAY_ROOT` 显式选择。

th15 的旁观驱动使用同一 Relay 入口，可通过 `TH15_RELAY_ROOT` 指定服务源码目录；发布验收核对打包使用的 `th15.mjs` 与同次构建的 WASM。合作旁观首次进入按原生关头正常播放，只有显式定位或“回到直播”执行一次固定目标的快进。

TH11 的启动器场景驱动通过房间里的回滚开关选择实测纯延迟，并在结果中记录 `pure-delay`。有界回滚使用本作 `rollback-browser-acceptance.mjs` 的对应场景验收，两种时序分别保存结果。

TH11 回滚驱动通过 `TH11_TEST_FONT` 与 `TH11_TEST_UNICODE_FONT` 接收共用字体，按正常 `configure.sharedResources` 接口安装，并把字体哈希纳入验收输入身份。

主动断线场景完整保留 Console 与 native 错误。驱动在明确关闭通道之后，将同席位 native 已确认的对应关闭通知单独记录；其他时间、来源与内容的错误继续使验收失败。

使用两个独立客户端；本作支持三人时补三人检查。先用稳定通道完成完整连接流程，再加入网络延迟、抖动和断线。记录实际 WebRTC／Relay 路径、构建和设备。

所有玩家资源就绪后，测量实际输入通道、确认时序参数，再从第 0 帧开局。实现说明见[联机架构](../architecture/netplay.md)与[回滚架构](../architecture/rollback.md)。

房间预加载持续呈现本地标题。`configure` 保存开局参数，`launch` 统一接管连接与模拟；两个命令之间可跨越任意呈现帧。旁观退出后恢复同一标题与游戏实例，再次加入沿用这一启动边界。合作作品的原生房间检查在配置后保留 500 毫秒标题运行窗口，覆盖三次旁观返回与重入，以及暂停、精确跳转和回到直播。th11 在退出联机会话时一并释放 GameSession 的多人输入归属，标题继续按本地菜单运行。

合作作品的旁观采用[流式 Replay](../architecture/spectator-replay.md)。关头由原生 Replay 入口数据与多人资源组成，后续连续发布全席位已确认输入。th08 的房间标题可以先运行多个联机帧，进入游戏后从首个原生 Replay 关头建立历史。预先开放的 Extra 与符卡内容直接进入标题菜单；普通版与多人版沿用相同的内容开放规则。

th09 在联机连接结束后完成原生标题交接，同时释放本次连接的停止标记。旁观断线、返回房间与再次加入共用同一游戏实例；先前连接的生命周期编号继续隔离旧回调。

th06、th07 按每次房间开局建立共同的联机会话代数起点，旁观多次重入后换到玩家席位也从同一握手身份开始。本地生命周期代数持续递增，为确认音频和其他单次副作用保留独立身份。原生房间检查同时覆盖玩家与旁观身份互换，以及程序和 DATA 的持续复用。

th10 返回房间菜单时结束本次录像记录、确认音频队列与待执行重开状态，下次开局从第 0 帧建立新的录像和音频时间线。th11 将联机通道结束交给原生菜单返回流程，保留已加载游戏，下一次切换身份继续使用同一实例。

MP-RULE-01 至 MP-RULE-05 是合作模式规则，只用于产品目录中 `multiplayer.gameplay` 为 `cooperative` 的作品。实际生命、Power、碎片、幽灵救援、资源给予与剧情规则按本作开发指南核对。TH09 标记为 `versus`，应将这五项标为“不适用”，改按 TH09 对战指南核对双方资源、对战状态和结束流程。TH15 当前使用实测输入延迟。

红点采用最近未满 Power 优先的原生吸引：上线收点选择最近的未满 Power 玩家，全员满 Power 时选择最近玩家。直接拾取先归未满 Power 的拾取者，满 Power 拾取者将红点吸引到最近的未满 Power 队友。已吸引的道具保持接收者，接收者满 Power 或退出可操作状态时重新选择；席位资格以当前房间实际启用的玩家为准。统一说明位于[多人规则书](../../launcher/content/MULTIPLAYER.md#红点自动分配)。

原生道具验证分别使用 th07 的 `tests/item-collection-browser.py`、th08 的 `portable/multiplayer/check-cooperation.py --case nearest_power_routing`、th10 的 `portable/check-multiplayer-rules.mjs --suite item-ownership`、th11 的 `portable/multiplayer/native-test.mjs --cooperative` 与 th15 的 `portable/multiplayer/native-test.mjs --items-only`。th15 的原生检查与正式构建使用同一公共头文件目录，按当前房间人数核对小 P 数值。

各合作作品的当前联机身份：th06 为 19、th07 为 17、th08 为 `0x08000018`、th10 为 `0x1000000e`、th11 为 5、th15 为 21。th07 的多人 Replay 玩法身份为 15。房间握手、旁观与多人 Replay 按对应身份校验玩法规则。

th08 同时支持 `0x08000017` 版本录制的多人回放，播放时保留该版本的跨面补弹行为。

th15 新对局和新录像使用规则版本 21，并校验录制构建身份。规则版本 20 的回放按已登记的旧构建选择兼容路径，沿用录制时的场景交接与过渡移动。

版本 20 的基线为提交 `b804050534e7c8a07785ef8a03dd2b24163035bb`，对应 [CI 构建](https://github.com/Ritosa2333/eagler-touhou/actions/runs/40085809634/job/120848424530)的 WASM SHA-256 为 `69cf52f0644bdac4784d5168cab6de550fe7b4286862a565a74722ab9c3fa07e`。回放中的四字构建身份取该摘要的前 128 位。每条兼容路径同时限定来源构建与目标规则版本，新增旧构建或升级规则时一并验证。`portable/multiplayer/network-test.mjs` 覆盖双人／三人、0／2／9 帧延迟、跨面输入保存、兼容构建准入、未知构建拒绝及重编码。

房间标题接收本地键盘、手柄和触控，可在开局前调整内置设置。开局交接期间由同一实例切换到房间输入，菜单操作与联机输入各有自己的归属。合作菜单按席位合并按下边沿，同伴持续按住射击时，其他席位的确认、对话与暂停操作依然有效。

th09 与 th075 的房间预览沿原生输入采样操作选项，标题中的开始游戏与退出交给房间管理。`launcher/tests/browser/test-room-options.mjs` 使用正式 Runtime 和本地 DATA，实际进入 Options、通过聚焦后的物理按键调整选项并返回，逐作保存画面与原生状态。预加载时长和开局复用继续由 `test-room-title-preload.mjs` 对照双端状态。

保留实例返回房间时，启动器把开局前保存的本地选项重新配置给 Runtime，等待确认后开放菜单输入。玩家主动返回和原生结束事件使用相同流程，旁观身份与上一局的网络选项一起切换成本地标题配置。`ROOM_OPTIONS_RETURN=1` 在原生返回后继续检查 Options 操作与实例复用。

合作对局以最后一个已确认游戏帧交接结算。各玩家独立推进 ending、全灭结果、署名和录像保存，通道继续送达局末输入，结算操作不再进入对局历史。旁观按全席位 Replay 展示自机，暂停菜单保留在模拟流程中，画面呈现游戏场景。

本局结束以全员全灭的救援等待结束、整局通关或确认退出当前对局为边界。最后一个已确认游戏帧之后，Ending、结果菜单、署名、保存 Replay 与返回标题由各端独立推进。暂停、对话和普通切关继续使用共同输入；R 重开共同建立新局。

th08 在同步结束后按本地帧持续绘制 Ending 与结果界面，并推进本地时钟与键盘／触控输入。对局历史保留最后确认帧；结局操作由各玩家独立完成。原生交接与 SDL 呈现的行为检查见[多人开发指南](../../ports/th08-mp/docs/DEVELOPMENT.md)。

旁观播完本局尾帧后进入本机的原生结果菜单，选槽、署名与保存沿用各作现有界面。完整录像由来源端的原生 Replay 编码器生成，按当前局身份交给观众的原生保存器。暂停中的观众保留播放位置，继续播放并播完后进入结算。文件传输有 8 MiB 上限和 15 秒发送窗口，换局即切换文件归属。

本机结果菜单持续接收本地操作，直到返回房间或离开这次旁观。来源端后续换局和文件到达保持正在进行的选槽、署名与保存流程。

## 逐项检查

| 编号 | 操作 | 通过时应看到 |
| --- | --- | --- |
| <a id="mp-rule-01"></a>MP-RULE-01 · 合作模式死亡、幽灵与救援 | 仅合作模式：覆盖被弹、Deathbomb、幽灵、救援与命数上限。 | 状态转移与复活符合本作合作规则表。 |
| <a id="mp-rule-02"></a>MP-RULE-02 · 合作模式个人与团队资源 | 仅合作模式：多人同时拾取生命、Power、碎片与得分道具。 | 个人和团队资源归属符合本作规则表。 |
| <a id="mp-rule-03"></a>MP-RULE-03 · 合作模式资源给予 | 仅合作模式：按本作操作向存活或幽灵席位给予资源。 | 目标选择、数值与反馈符合本作规则表。 |
| <a id="mp-rule-04"></a>MP-RULE-04 · 合作模式对话、结算与全灭 | 仅合作模式：让各席位推进对话，并触发结算、全灭与重开。 | 流程符合本作规则；全灭进入本作团队结束流程。 |
| <a id="mp-rule-05"></a>MP-RULE-05 · 合作模式自机可见性与多人 HUD | 仅合作模式：让队友靠近、重叠，再分别观察各客户端 HUD。 | 个人与共享信息清楚，自身强调和遮挡反馈符合本作规则。 |
| <a id="mp-01"></a>MP-01 · 独立 MP 产品变体 | 分别构建、打包并选择普通版和 MP。 | 产品身份与模式分别可定位；共源码也有独立发布身份。 |
| <a id="mp-02"></a>MP-02 · 房间人数、难度与机体 | 创建房间，切换人数、难度和机体。 | 可选范围来自产品目录。 |
| <a id="mp-03"></a>MP-03 · 所有席位准备并同步开局 | 让各席位以不同速度加载资源并准备。 | 资源与参数就绪后，各席位从同一逻辑帧开局。 |
| <a id="mp-04"></a>MP-04 · 确定性输入与状态检查 | 记录双端输入与状态，加入延迟和乱序。 | 相同已确认帧状态一致，差异可定位。 |
| <a id="mp-05"></a>MP-05 · 各席位输入归属 | 让各席位分别使用键盘、手柄和触控。 | 每种输入只控制自己的席位。 |
| <a id="mp-06"></a>MP-06 · 旁观加入与输入隔离 | 满员玩家房间加入旁观者，并尝试旁观端操作。 | 旁观席独立；旁观输入不进入玩家逻辑。 |
| <a id="mp-07"></a>MP-07 · 旁观只读取连续已确认历史 | 记录一段预测与回滚，再观察旁观历史。 | 历史只包含连续且校正后的全席位输入。 |
| <a id="mp-08"></a>MP-08 · 慢旁观者与玩家隔离 | 降低旁观端接收速度，触发其队列上限。 | 玩家仍继续游戏，旁观端按自身策略处理。 |
| <a id="mp-09"></a>MP-09 · 旁观尾帧与结束时机 | 在局末改变房间状态或断开旁观连接。 | 已收尾帧按序播放，结束依据本作生命周期。 |
| <a id="mp-10"></a>MP-10 · 联机暂停与重开 | 多人暂停、恢复、R 重开，然后重复一局。 | 所有席位同步进入对应状态。 |
| <a id="mp-11"></a>MP-11 · 多人 Replay | 保存多人 Replay，退出后从启动器再次回放。 | 席位、输入和本作模式还原一致。 |
| <a id="mp-12"></a>MP-12 · WebRTC 与 Relay 路径 | 分别使用 WebRTC 和配置的 WebSocket Relay 进行对局。 | 两种路径都能连接、开局和退出。 |
| <a id="mp-13"></a>MP-13 · 本地玩家可见性 | 切换本地玩家高亮、遮挡透明度等选项。 | 只改变画面可见性，玩法状态一致。 |
| <a id="mp-14"></a>MP-14 · 联机与回滚诊断 | 观察延迟、预测、回滚和连接诊断。 | 共用界面显示当前通道与构建的实际状态。 |
| <a id="mp-15"></a>MP-15 · 游戏结束返回房间 | 正常结束、主动退出、连接失败后返回。 | 回到房间流程，其他启动器状态可继续使用。 |
