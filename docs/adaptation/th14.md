## 发布输入

TH14 需要显式选择 `--games=th14`；默认 Host 和 Runtime Release 构建不要求准备 TH14 的运行包或原版数据。

- 已构建的 TH14 单人和多人目录运行包及各自的 `runtime-files.json`，包含 SDL Wasm、工作线程、归档解码器、`Th14StageMemoryWorker.wasm` 和字体栅格。
- 日文 v1.00b 的 `th14.dat` 和 `thbgm.dat`。内容准备器核对原版哈希，输出 `th14.data` 和 18 首 Ogg Vorbis；文件在虚拟文件系统中挂载为 `/th14.dat`、`/music/*.ogg`。
- 网站封面和站点图标。原作数据、音乐及生成运行包由运营方部署，不加入 Git。Host 默认复用[作品进度表的辉针城封面](../../launcher/docs/assets/game-covers/thumbnails/th14.jpg)，发布为 `th14-card.jpg`；也接受 `--override-dir` 下的同名 JPEG。

`ogg` 组件和其他作品一样使用 libvorbis 质量 5。循环起止继续从原版 `thbgm.fmt` 读取。已安装的旧 FLAC 包可以继续播放，更新资源后切换为 Ogg。没有 MIDI 模式。

## 构建修复后的运行时

TH14 的运行源码随仓库检出，位于 `ports/th14`，以 THP `5eb4ac87` 为上游基线。TH14 与 THP 的其他运行时共用部分引擎实现，因此源码仍使用上游的 `runtimes/th12` 路径。网页运行分辨率为 1280×960，包含 ANM、激光、对话、thprac 和输入调度修复。

从仓库根目录构建 SDL3／WebGL2 核心，使用 `common` 中的 ImGui 和练习面板。核心构建会生成 Wasm、启动壳和构建回执：

```sh
python ports/th14/tools/th14-build-gles.py --common common --emsdk /srv/emsdk --out /srv/build/th14-core
python ports/th14-mp/tools/th14-build-gles.py --common common --emsdk /srv/emsdk --out /srv/build/th14-multiplayer-core
```

运行时模板提供归档解码器、字体及目录协议资源。组装器核对构建回执，替换核心、启动壳和工作线程模块并生成目录清单。以下命令从仓库根目录开始执行：

```sh
bun launcher/scripts/prepare-th14-content.mjs --original=/srv/original/th14 --output=/srv/content/th14
cd launcher
bun scripts/prepare-th14-runtime.mjs --input=/srv/build/th14 --output=/srv/runtime/th14-template
node scripts/assemble-th14-runtime.mjs \
  --template=/srv/runtime/th14-template --core-build=/srv/build/th14-core --output=/srv/runtime/th14
node scripts/assemble-th14-runtime.mjs \
  --template=/srv/runtime/th14-template --core-build=/srv/build/th14-multiplayer-core --output=/srv/runtime/th14-multiplayer
bun run build
bun scripts/package-server.mjs \
  --games=th14 --test-build=1 --profile=web-validation-th14 --output=/srv/releases/th14 \
  --th14-build=/srv/runtime/th14 --th14-multiplayer-build=/srv/runtime/th14-multiplayer --th14-assets=/srv/content/th14 \
  --th14-ogg=/srv/content/th14 --music=ogg \
  --artwork-dir=/srv/artwork --font=/srv/fonts/unifont.otf \
  --vanilla-font=/srv/fonts/msgothic.ttc --site-url=https://example.invalid/
bun scripts/verify-server-build.mjs /srv/releases/th14
```

组装时用 `--practice-font=<unifont.otf>` 提供 TH15、TH17 使用的 Unicode 字体，并可用 `--max-file-bytes=15728640` 限制单文件大小。超过上限的原版字体表以 gzip 文件发布；浏览器解压后核对原始大小和 SHA-256，再交给游戏使用。

原版组件对照见 [ANM VM Oracle](../../ports/th14/docs/porting/TH14_ANM_VM_ORACLE.md)、[界面 Oracle](../../ports/th14/docs/porting/TH14_UI_ORACLE.md)和[纹理显示 Oracle](../../ports/th14/docs/porting/TH14_TEXTURE_DISPLAY_ORACLE.md)。完整流程、玩法和录像的已覆盖范围见 [TH14 行为验收](https://github.com/AdingApkgg/thp/blob/336a1ff0f9fdd197eba3ff5d8e7f94f1e31c34b4/docs/porting/TH14_BEHAVIOR_MATRIX_NOV13.md)。

## HTTPS 和线程

当前运行时使用共享内存线程，部署必须提供可信 HTTPS，并在网站与运行时响应中设置：

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
Cross-Origin-Resource-Policy: same-origin
```

不可变 Runtime generation 的响应还必须包含 `Cache-Control: no-transform`，让 CDN 保留哈希清单登记的原始字节。Cloudflare 的 WebMCP／JavaScript Detections 自动插入脚本会改变 HTML 长度和哈希；不要通过放宽启动器校验来兼容改写后的程序。仓库静态服务器已为 generation 路径设置此指令，其他反向代理也应保留它。Cloudflare 的相关行为见[缓存指令说明](https://developers.cloudflare.com/cache/concepts/cache-control/)。

TH14 用 MS Gothic 和 Unifont 在运行时绘制文字。原版日语优先使用 MS Gothic；简体中文和英语语言包使用 Unifont，两种字体可以互补缺字。启动器的「游戏语言」选择原版日语、简体中文或英语，翻译沿用 thcrap 语言包，原版文本通过 CP932 表解码。运行包保留原版界面图像和数值图标，移除了八张预生成字形表及其混色表。

THP 从 `5667250a` 起会输出 `shell.mjs` 和七个录像导出。组装器验证并优先使用该启动壳；早期构建使用运行时模板。修改前端源码后，重新构建前端再打包。

## 多人模式

多人源码与构建位于 [ports/th14-mp](../../ports/th14-mp/README.md)。目录保留从 TH14 普通版分出时的 Git 历史。

多人版支持两人和三人。拾取残机碎片、完整残机或完整 Bomb 时全队获得奖励，每 3 个残机碎片合成一条残机，满残机后的转换按席结算。Bomb 碎片由拾取者独享，双人每 4 片、三人每 3 片合成一个 Bomb。咲夜 A 护盾结束时只向本人发放 2 片（双人）或 1 片（三人）。吸点的道具数按席统计，吸点期间只允许一席发起吸点，满 Power 后飞向队友的 P 点计入发起者的道具数，吸点奖励轮次由全队共用。

普通 Bomb 的无敌时间全队共用，在这段时间内其他玩家不能发动普通 Bomb。开雷期间，全队的普通射击和 Bomb 伤害一并受当前敌机的免疫或减伤倍率影响。咲夜 A 护盾独立生效，魔理沙 B 独立计算本机的 Bomb 冷却。靠近队友后，连续轻按五次 Shift 转移一条残机，连续轻按五次 Z 转移一档 Power。残机耗尽时成为幽灵，队友可以转移一条残机将其复活。Ctrl 标示本机并可快进对话和结局。任意玩家可按 Esc 暂停或恢复，暂停操作与战斗输入一起确认。

右侧沿用原版的残机、Bomb、碎片与 Power 元素。每席有自己的库存行，高分、分数、最大得点及擦弹各保留一行。本机席号显示为黄色。

房间默认使用最多 12 帧的回滚。房主可以在「游戏设置」中关闭回滚，选择 0–9 帧的手动输入延迟。战斗中迟到的输入会从受影响的帧重新演算；对话、读盘和场景切换等待各方输入确认。音效、录像和观战只接收已确认的帧。正篇通关后，各玩家按本机选择的机体独立播放结局，并可各自用 Ctrl 快进。录像和观战到最后一个确认的游戏帧结束。多人录像保存在独立的 `/savesth14mp/replay`，使用 `th14mp_*.rpyx`。公共 Relay 识别 TH14 后，大厅可以按房号加入；对局开始后，观战者可以从大厅进入并补播已确认的输入。

回滚会复用刚恢复的检查点，并按浏览器的刷新预算分批重算。恢复时按最早一次写入的记录还原每个敌弹和道具槽；持续发射或 Bomb 重用的动画空间在每个检查点内循环分配。仅无限速滑动使用连续确认坐标做短程预测，Bomb 等真实的按键输入。测游戏内帧率时，以实际提交给画布的帧数为准，同时记录快照、恢复、重算、逻辑绘制和实际绘制的耗时。

回滚检查点的场景、活动动画和闲置动画分别复用缓冲区，增长时会释放该缓冲区的旧空间。已确认和被回滚丢弃的检查点只留一份备用缓冲，供下一帧复用。统计检查点占用时包含敌弹和道具缓冲。需要更多空间时，本机等待当前帧的输入确认后继续，后续帧可恢复预测。错误报告包含 Wasm 堆大小、已分配字节数和检查点缓冲区所占空间。

浏览器回归脚本用原版数据和组装好的多人运行包，在 WebRTC 上传层注入延迟和抖动，逐帧核对各席确认后的战斗状态。第一关双人、三人和手动延迟实测及上游 `6e28c016b` 的复测见[回滚验证记录](../../archive/th14-rollback-20261114/README.md)。连接本机测试 Relay 后，从仓库根目录运行：

```sh
node ports/th14-mp/tools/tests/test-th14-rollback-browser.mjs \
  --runtime=/srv/runtime/th14-multiplayer --data=/srv/original/th14/th14.dat \
  --output=/srv/reports/th14 --players=2 --observe
node ports/th14-mp/tools/tests/test-th14-rollback-browser.mjs \
  --runtime=/srv/runtime/th14-multiplayer --data=/srv/original/th14/th14.dat \
  --output=/srv/reports/th14 --players=3
```

## thprac


TH14 的练习、符卡阶段、作弊、局内信息和高级菜单基于 [thprac_purple 2.2.2.7 的 TH14 源码](https://github.com/RUEEE/thprac/blob/69f79b54bb52bb4f2d00d24d70ba12c7fa521d24/thprac/src/thprac/thprac_th14.cpp)。从原版主菜单进入 Practice Start，选择难度、角色和机体后进入紫版练习菜单。可以选择原版或增强练习，增强模式按原版分类选择道中章节、道中 Boss、关底 Boss、非符或符卡。F12 打开全屏高级选项，Backspace 打开作弊面板，F1–F7 和 U 对应紫版操作。紫版的 F8 信息面板在网页端用 Tab 打开；手机仍用公共 ImGui 折叠入口。触摸从面板外开始时仍可移动自机。

高级选项按紫版顺序排列为游戏速度、游戏进行、魔理沙激光、反应力测试和关于。Windows 键盘 API 诊断在浏览器里不可用；浏览器使用自己的输入接口。原版的独立 BGM 变速/变调依赖可选 Windows 声音钩子，网页不显示这一可选行。

原暂停菜单可保存作弊录像。键盘录像使用 `.rpy`，包含触控轨迹的录像使用 `.rpyx`。练习参数兼容紫版的 `PRAC` 区块；魔理沙激光记录、播放和修复使用紫版的 `RECR` 区块。浏览器额外用 `PR14` 保存局内作弊变更，用 `T11T` 保存触控轨迹。回放练习或作弊录像时需开启 thprac。

THP 的 `tools/generate-th14-practice.mjs` 接受紫版 TH14 源码、语言表、许可证及从日文 1.00b 解出的 ECL 目录，生成跳段表和菜单目录；`tools/generate-th14-purple-ui.mjs` 从同一紫版 checkout 提取高级设置、练习和局内信息的三语标签。核心核对 ECL 指纹后在本局副本上应用跳段。面板与 TH15、TH17 共用 `common` 中的 Dear ImGui、字形构建和触控折叠面板。组装器核对构建回执后在清单中声明 `features.thprac`。

全关疮痍时显示现有 Score Ranking；进入前十才需要输入姓名。确认后继续使用原疮痍菜单和录像保存入口。

## 启动取消与音频生命周期

普通版与多人版在资源请求、解压／哈希结束和写盘边界检查启动取消信号；字体和音乐安装沿用该信号。进入浏览器缓存时保留后续最终离开的取消监听。异步音频恢复按运行时维护请求版本，新的暂停、退出或恢复使旧请求失效。

多人版沿目录投影三方合并接收公共修复，保留联机房间、回滚输入、存档根路径及内存预算。当前源码与生成包检查、旧版反例和候选范围见[上游接续记录](../../archive/th14-behavior-acceptance-20261117/TH14_UPSTREAM_RECONCILE_NOV17.md)；普通版已完成静音普通启退及暂停恢复专项，多人对局与其余范围继续，新核心尚未部署。
