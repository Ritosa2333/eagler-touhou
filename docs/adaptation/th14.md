# TH14 网站接入

TH14 使用 [AdingApkgg/thp](https://github.com/AdingApkgg/thp) 的独立 C++ / SDL3 / WebGL2 运行时，以 `retail-memory` 目录适配器接入启动器。作品显示在「测试版功能」中，状态为适配测试中；本接入仍处于原作行为级对齐与适配验收阶段。

## 发布输入

TH14 需要显式选择 `--games=th14`；默认 Host 和 Runtime Release 构建不要求准备 TH14 的运行包或原版数据。

- 已构建的 TH14 目录运行包及 `runtime-files.json`，包含 SDL Wasm、工作线程、归档解码器、`Th14StageMemoryWorker.wasm` 和字体栅格。
- 日文 v1.00b 的 `th14.dat` 和 `thbgm.dat`。内容准备器核对原版哈希，输出 `th14.data` 和 18 首 Ogg Vorbis；文件在虚拟文件系统中挂载为 `/th14.dat`、`/music/*.ogg`。
- 网站封面和站点图标。原作数据、音乐及生成运行包由运营方部署，不加入 Git。Host 默认复用[作品进度表的辉针城封面](../../launcher/docs/assets/game-covers/thumbnails/th14.jpg)，发布为 `th14-card.jpg`；也接受 `--override-dir` 下的同名 JPEG。

`ogg` 组件和其他作品一样使用 libvorbis 质量 5。循环起止继续从原版 `thbgm.fmt` 读取。已安装的旧 FLAC 包可以继续播放，更新资源后切换为 Ogg。没有 MIDI 模式。

## 构建修复后的运行时

生产核心直接使用 [THP `c407a169`](https://github.com/AdingApkgg/thp/commit/c407a1693cce55fa9f4ffea6f687ea2ac61c137e)。该提交已整合 Goan114 的 ANM／界面／原版高清字库与纹理、Ogg／短输入及浏览器调度修复，并补回无纹理绘制时解绑旧 sampler。配置保留原版的 640×480、960×720、1280×960 三档。`tools/th14-anm-vm-oracle.py`、`tools/th14-ui-oracle.py` 和 `tools/th14-texture-display-oracle.py` 提供原版组件对照。协作补丁文件仍保留原始差异；`19170e47` 的 alpha 阈值比较已独立整合；延迟颜色清屏仍保留为单独候选。

在独立 THP 工作树直接构建该提交。原先的运行目录用于提供不随核心编译的启动协议模块、归档解码器和字体：

```sh
git -C /srv/source/thp fetch origin main
git -C /srv/source/thp worktree add --detach /srv/source/th14-release c407a1693cce55fa9f4ffea6f687ea2ac61c137e
python /srv/source/th14-release/tools/th14-build-gles.py --emsdk /srv/emsdk --out /srv/build/th14-core
```

```sh
bun launcher/scripts/prepare-th14-content.mjs --original=/srv/original/th14 --output=/srv/content/th14
cd launcher
bun scripts/prepare-th14-runtime.mjs --input=/srv/build/th14 --output=/srv/runtime/th14-template
node scripts/assemble-th14-runtime.mjs \
  --template=/srv/runtime/th14-template --core-build=/srv/build/th14-core --output=/srv/runtime/th14
bun run build
bun scripts/package-server.mjs \
  --games=th14 --test-build=1 --profile=web-release-th14 --output=/srv/releases/th14 \
  --th14-build=/srv/runtime/th14 --th14-assets=/srv/content/th14 \
  --th14-ogg=/srv/content/th14 --music=ogg \
  --artwork-dir=/srv/artwork --font=/srv/fonts/unifont.otf \
  --vanilla-font=/srv/fonts/msgothic.ttc --site-url=https://example.invalid/
bun scripts/verify-server-build.mjs /srv/releases/th14
```

源码工作区的 `ports/th14` 对应 THP 独立检出，供发布来源登记使用。模板准备步骤去除归档加载器的 Node 后端；组装步骤核对构建回执中的核心模块和工作线程身份，替换模块并重写启动壳和目录清单。打包器发布不可变 generation、内容描述符、哈希和版本清单。

最新核心另修正 TH14 Player 激活前的空速率时钟及 tick 默认速率；六种自机初始化、960 次时钟比较、加载回归和静音普通开局通过，完整录像／画面／声音及旧加载 RNG 反例仍开放。[验证范围](https://github.com/AdingApkgg/thp/blob/336a1ff0f9fdd197eba3ff5d8e7f94f1e31c34b4/docs/porting/TH14_PLAYER_INITIALIZATION_NOV13.md)。

当前核心另补齐33个Player移动历史点和八个僚机初始Y；原版六自机90步、当前35,000回调所测状态及弹字段通过，三面相机缓存差异仍开放。正式包仅重编1单元、核验复用145，原点39个完整响应均通过，公网首轮37个通过、两个连接重置文件完整重取后也通过；没有Range、缓存清除或完整性绕过。既有18首Vorbis保留，实际生产解码器及流式适配器另通过99,457,880帧独立解码比较、54个寻址窗口与循环边界检查；这不代替浏览器播放、最终 PCM 或整作行为验收。

本轮独立核心另通过灵梦B Normal六关122,005回调的所测玩法／RNG／HUD／录像游标与成绩文件比较、30个普通／Extra入口和操作用例，以及六机体实际GPU短流程。Extra使用明确的外部解锁测试存档，仅验证解锁后的入口。本轮浏览器Wasm为 `e7492a19…`；浏览器入口与普通保存等剩余覆盖继续记录，不把这些有限通过称为整作完成。详见 [TH14行为验收](https://github.com/AdingApkgg/thp/blob/336a1ff0f9fdd197eba3ff5d8e7f94f1e31c34b4/docs/porting/TH14_BEHAVIOR_MATRIX_NOV13.md)。

测试站的固定 1280×960 运行时使用 [TH14 核心补丁](../../launcher/patches/th14-runtime.patch)。它保留上述 Player 初始化和纹理绑定修复，并启用延迟颜色清屏、道具空槽跳过、矩形消弹共享旋转以及 ANM 绘制链直接摘除。测试构建使用下面的补丁入口，再执行相同的目录组装和打包命令：

```sh
git -C /srv/source/thp worktree add --detach /srv/source/th14-test 5eb4ac87d227027f390fa006e1126a094b820860
git -C /srv/source/th14-test apply --index /srv/source/eagler-touhou/launcher/patches/th14-runtime.patch
python /srv/source/th14-test/tools/th14-build-gles.py --common /srv/source/eagler-touhou/common --emsdk /srv/emsdk --out /srv/build/th14-test-core
```

组装测试包时用 `--practice-font=<unifont.otf>` 提供 TH15、TH17 使用的 Unicode 字体，并可用 `--max-file-bytes=15728640` 限制单文件大小。超过上限的原版字体表以 gzip 文件发布；浏览器解压后核对原始大小和 SHA-256，再交给游戏使用。

## HTTPS 和线程

当前运行时使用共享内存线程，部署必须提供可信 HTTPS，并在网站与运行时响应中设置：

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
Cross-Origin-Resource-Policy: same-origin
```

不可变 Runtime generation 的响应还必须包含 `Cache-Control: no-transform`，让 CDN 保留哈希清单登记的原始字节。Cloudflare 的 WebMCP／JavaScript Detections 自动插入脚本会改变 HTML 长度和哈希；不要通过放宽启动器校验来兼容改写后的程序。仓库静态服务器已为 generation 路径设置此指令，其他反向代理也应保留它。Cloudflare 的相关行为见[缓存指令说明](https://developers.cloudflare.com/cache/concepts/cache-control/)。

TH14 用 MS Gothic 和 Unifont 在运行时绘制文字。原版日语优先使用 MS Gothic；简体中文和英语语言包使用 Unifont，两种字体可以互补缺字。启动器的「游戏语言」选择原版日语、简体中文或英语，翻译沿用 thcrap 语言包，原版文本通过 CP932 表解码。运行包保留原版界面图像和数值图标，移除了八张预生成字形表及其混色表。

仓库静态服务器可通过环境变量开启这些响应头：

```sh
EAGLER_TOUHOU_CROSS_ORIGIN_ISOLATION=1 node scripts/serve-static.mjs /srv/releases/th14 8208
```

HTTP loopback 可通过 SSH 转发用于浏览器验收；它连接的是远端生产服务。普通远端 HTTP 不能满足共享内存的安全上下文要求。使用 Cloudflare Tunnel 时，将目标域名的 ingress service 指向该 loopback 服务，并确认公网 HTTPS 响应保留以上三个响应头。隧道无需将本机监听端口开放到公网。

## thprac


TH14 的练习、符卡阶段、作弊、局内信息和高级菜单基于 [thprac_purple 2.2.2.7 的 TH14 源码](https://github.com/RUEEE/thprac/blob/69f79b54bb52bb4f2d00d24d70ba12c7fa521d24/thprac/src/thprac/thprac_th14.cpp)。从原版主菜单进入 Practice Start，选择难度、角色和机体后进入紫版练习菜单。可以选择原版或增强练习，增强模式按原版分类选择道中章节、道中 Boss、关底 Boss、非符或符卡。F12 打开全屏高级选项，Backspace 打开作弊面板，F1–F7 和 U 对应紫版操作。紫版的 F8 信息面板在网页端用 Tab 打开；手机仍用公共 ImGui 折叠入口。触摸从面板外开始时仍可移动自机。

高级选项按紫版顺序排列为游戏速度、游戏进行、魔理沙激光、反应力测试和关于。Windows 键盘 API 诊断在浏览器里不可用；浏览器使用自己的输入接口。原版的独立 BGM 变速/变调依赖可选 Windows 声音钩子，网页不显示这一可选行。

原暂停菜单可保存作弊录像。键盘录像使用 `.rpy`，包含触控轨迹的录像使用 `.rpyx`。练习参数兼容紫版的 `PRAC` 区块；魔理沙激光记录、播放和修复使用紫版的 `RECR` 区块。浏览器额外用 `PR14` 保存局内作弊变更，用 `T11T` 保存触控轨迹。回放练习或作弊录像时需开启 thprac。

THP 的 `tools/generate-th14-practice.mjs` 接受紫版 TH14 源码、语言表、许可证及从日文 1.00b 解出的 ECL 目录，生成跳段表和菜单目录；`tools/generate-th14-purple-ui.mjs` 从同一紫版 checkout 提取高级设置、练习和局内信息的三语标签。核心核对 ECL 指纹后在本局副本上应用跳段。面板与 TH15、TH17 共用 `common` 中的 Dear ImGui、字形构建和触控折叠面板。组装器核对构建回执后在清单中声明 `features.thprac`。

全关疮痍时显示现有 Score Ranking；进入前十才需要输入姓名。确认后继续使用原疮痍菜单和录像保存入口。
