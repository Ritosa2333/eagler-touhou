# TH05 合作观战

独立多人通过主项目房间旁观席接收观战。启动器使用 `netplaySpectator=true` 标识旁观身份，保留的 0 号槽位用于观战视角；接收端不创建玩家输入席位。运行组件只消费房主上传的已确认输入；观众的键盘、触控与数位笔输入不会进入玩家输入通道。

## 阶段转播

TH05 使用合作观战的 E5SV / E5NP 通道，作品标记为 `0x35`，原生状态 ABI 为 `0x54483501`。房主在关卡初始化前采集状态，以显式小端整数编码角色、难度、初始资源、跨关资源、全局游戏数值、随机种子与统计。每个检查点 360 字节；接收端重新构造关卡，再消费同一前缀中的已确认物理输入。原生回滚内存保留在玩家运行组件内部。

中继沿用合作作品的身份验证、当前关卡历史、观众准入和容量限制。房主观战上传失败时关闭转播，玩家同步继续运行。

## 播放控制

观众通过 `__th05PeerTransport` 上报只读接收连接，通过 `spectatorPlayback.seeking` 上报初次追赶与定位状态。启动器在接收路径就绪且重建完成后解除加载遮罩。

观众向启动器报告版本 1 的 `spectatorPlayback` 状态，沿用共享观战时间轴。支持暂停、继续、定位当前关卡已接收范围以及返回直播。换面后以新关卡入口作为可回看的起点。重建和追赶分批执行，并暂停音频输出，追上后恢复播放。

## 验证

运行 `node ports/th05-mp/tests/spectator-browser.mjs` 使用实际原生运行组件和隔离中继验证两人观战。设置 `TH05_MP_PLAYERS=3`、`TH05_MP_ROUTE=relay` 或 `TH05_MP_MODE=0` 分别覆盖三人、中继及回滚。

## 对话与切面

多人回滚将对话文字、背景淡入淡出、开场和关末淡出纳入现有预测窗口。资源脚本和场景切换保持确认屏障，观战上传始终消费已确认输入。阶段检查点仍在关卡初始化前采集。
