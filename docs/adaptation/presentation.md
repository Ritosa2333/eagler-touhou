# 画面与声音

[适配流程](README.md) | [文档目录](../README.md)

固定逻辑频率，画面跟随显示器刷新。声音事件按真实游戏事件输出。

th12 的托管帧循环检查直接运行浏览器循环、显示限频器和插值选择器，在 60、120、144 Hz 下分别核对自由呈现与 60 Hz 限制，保持相同的 60 Hz 游戏逻辑。

多人前进时钟与显示截止时间分别维护。普通版引入高刷新策略后，MP 的确认输入、追帧额度与回滚历史继续由独立逻辑时钟计账。th11 的分离实现与 26,288 项账本检查见对应[验收记录](../../ports/th11/docs/records/2026-10-24-display-high-refresh.md)；同类作品接收显示调度修改时，同时核对网络调度的时钟依赖。

插值副本沿原生对象保留席位归属，样本按所属时钟和对象身份隔离。恢复后重建可见性与插值端点，额外 Draw 保护原生 VM、实例标记和相机状态。同架构作品接入时核对这些拥有者，使用不同显示限制的双端状态与实际输入 Replay 作对照，见 th11 MP 的[完整世界与联机验证](../../ports/th11-mp/docs/records/2026-10-24-display-high-refresh.md#mp-接收与逻辑时钟)。

## 准备

准备一台 60 Hz 设备和一台高刷新率设备。使用固定输入或 Replay 比较游戏状态，再观察角色、弹幕、激光、特效、背景、菜单与暂停画面。

[Presentation Lab](../../common/testkit/presentation-lab/README.md) 用于重复绘制与状态对照；本作具备其他同等检查工具时，在表中记录对应入口。

## 逐项检查

| 编号 | 操作 | 通过时应看到 |
| --- | --- | --- |
| <a id="display-01"></a>DISPLAY-01 · 固定逻辑步进 | 在 60 Hz 和更高刷新率下用同一输入运行。 | 游戏逻辑、RNG、计时和 Replay 按同一逻辑频率推进。 |
| <a id="display-02"></a>DISPLAY-02 · 跟随显示器刷新率 | 在 120／144 Hz 显示器上移动角色、观察弹幕，并测量呈现间隔。 | 额外画面帧按显示刷新率呈现。 |
| <a id="display-03"></a>DISPLAY-03 · 额外绘制无逻辑副作用 | 固定逻辑状态重复绘制，比较状态摘要。 | 额外绘制只改变画面，逻辑与存档状态相同。 |
| <a id="display-04"></a>DISPLAY-04 · 连续视觉字段插值 | 观察角色、弹幕、激光、附属物和动画切换。 | 连续位置平滑；离散贴图与状态按当前逻辑切换。 |
| <a id="display-05"></a>DISPLAY-05 · 出生、销毁和瞬移 | 测试出生、死亡、瞬移、切面与池对象复用。 | 画面直接使用新对象的当前状态。 |
| <a id="display-06"></a>DISPLAY-06 · 暂停画面的表现 | 暂停游戏并打开模态菜单。 | 世界保持暂停；菜单按其设计更新。 |
| <a id="display-07"></a>DISPLAY-07 · 实际呈现后报告首帧 | 记录启动期间的实际绘制与 `first-frame` 时间。 | 首帧事件出现在实际呈现之后。 |
| <a id="display-08"></a>DISPLAY-08 · 限制到 60 Hz | 在高刷设备上切换 60 Hz 限制。 | 只有画面频率改变，游戏速度与输入规则一致。 |
| <a id="audio-01"></a>AUDIO-01 · 正常 OGG 音乐 | 选择 OGG，从标题进入一局并切换曲目。 | 可听到本作对应曲目。 |
| <a id="audio-02"></a>AUDIO-02 · 无 BGM 模式 | 选择无 BGM 模式，再触发射击、击中等音效。 | 背景音乐关闭，其他音效仍正常。 |
| <a id="audio-03"></a>AUDIO-03 · 切曲、渐变、暂停、停止 | 覆盖标题、开局、Boss、暂停、重开和退出。 | 切曲、循环、渐变与停止跟随游戏状态。 |
| <a id="audio-04"></a>AUDIO-04 · 返回前台后恢复声音 | 播放中切后台再返回，并按页面提示恢复音频。 | 恢复声音输出，曲目位置与循环状态连续。 |
| <a id="audio-05"></a>AUDIO-05 · 音乐资源错误信息 | 用缺失或损坏的音乐资源启动。 | 错误出现在共用提示或诊断中，可继续选择其他音乐方式。 |
| <a id="audio-06"></a>AUDIO-06 · 高刷新与音频事件分开 | 在高刷与回滚场景触发同一音效。 | 每个真实事件只发声一次。 |
| <a id="audio-07"></a>AUDIO-07 音效即时输出 | 在音乐加载、解码和预排缓冲期间触发音效，记录事件与输出的时间。 | 音效及时输出，音乐准备和队列不阻塞音效。 |
| <a id="midi-01"></a>MIDI-01 · 声明 MIDI 选项 | 核对本作音乐能力和站点可提供的资源。 | 支持 MIDI 时才出现可用选项。 |
| <a id="midi-02"></a>MIDI-02 · 可听到的 MIDI 输出 | 选择 MIDI 并进入游戏。 | 能听到正确曲目。 |
| <a id="midi-03"></a>MIDI-03 · MIDI 生命周期 | 切曲、暂停、重开、退出。 | 播放与停止跟随本作状态。 |
| <a id="midi-04"></a>MIDI-04 · MIDI 与 OGG 分开 | 移除 OGG 后选择 MIDI，再切回 OGG。 | 两种音乐方式独立选择和获取资源。 |

## 声音验收方法

已有检查按音频路径复用：[共用 WebSfx 单测](../../common/tests/web-sfx-output.test.mjs)使用替身 AudioContext 检查节点、游标和资源释放；[th12 音乐单测](../../ports/th12/tests/music.test.mjs)检查选曲、异步加载、循环与停止；[th15 SDL 音频浏览器检查](../../ports/th15/web/tests/sdl/audio-browser.test.mjs)使用本作音效、曲目和音频测试构建检查混音、声道、暂停游标与队列。各入口按本作指南准备素材与产物。

选择已知曲目与可重复触发的音效，分别记录标题、开局、暂停恢复、重开和退出时的结果。无 BGM 模式同时检查音效；资源错误使用缺失或损坏的文件复跑，核对提示与后续可选操作。切换音量时记录实际输出变化，音乐位置和循环状态单独观察。

`npm --prefix launcher run test:audio-output:browser` 从生产 `WebSfx.hpp` 读取 JS，在 Chromium 的 `OfflineAudioContext` 中渲染实际 PCM。检查即时输出与另一条预排音轨叠加、双声道增益、暂停时游标保持、恢复、停止、清空及末尾静音，并确认延迟启动的错误实现会被断言检出。这是 WebSfx 组件测试；各作是否使用该组件、曲目是否正确及扬声器输出使用上表验收。
