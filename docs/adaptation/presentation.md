# 画面与声音

[适配流程](README.md) | [文档目录](../README.md)

固定逻辑频率，画面跟随显示器刷新。声音事件按真实游戏事件输出。

## 准备

准备一台 60 Hz 设备和一台高刷新率设备。使用固定输入或 Replay 比较游戏状态，再观察角色、弹幕、激光、特效、背景、菜单与暂停画面。

[Presentation Lab](../../common/testkit/presentation-lab/README.md) 用于重复绘制与状态对照；本作具备其他同等检查工具时，在表中记录对应入口。

## 可审查的验收方法

以下方法供逐项审查，当前入口说明实际覆盖范围。

### DISPLAY-01 | 固定逻辑步进

- 场景与操作：在 60 Hz 与更高刷新率设备加载同一模式、DATA 和固定输入／Replay，按相同逻辑边界采样。
- 权威观察与预期：读取本作逻辑帧、RNG、计时和 Replay 位置，并与同输入参考逐边界比对；刷新率只改变呈现机会。
- 通过／失败：相同输入序列到达相同逻辑状态与 Replay 边界即通过；逻辑时钟随额外绘制次数变化即失败。
- 反例：让模拟更新错误地绑定每次绘制，确认逻辑帧或状态摘要立即偏离。
- 当前入口与覆盖：各作 `frame-scheduler`／presentation 单测覆盖组件逻辑，TH15 有 `tests/sdl/high-refresh-browser.test.mjs`；跨设备同输入对照仍按实测设备记录。

### DISPLAY-02 | 跟随显示器刷新率

- 场景与操作：在系统报告为 120／144 Hz 的显示器进入可操作关卡，持续移动角色并采集浏览器绘制与实际提交帧时间。
- 权威观察与预期：把浏览器／合成器的已呈现帧时间与设备当前刷新设置对照，同时读取原生逻辑帧；只以提交帧证据计呈现。
- 通过／失败：额外绘制机会跟随设备刷新而逻辑状态仍按本作时钟推进；只有 RAF 回调增加、画面未提交不能通过。
- 反例：注入绘制回调但不提交画面，确认报告不会把回调数写成实际呈现数。
- 当前入口与覆盖：TH15 `high-refresh-browser.test.mjs` 驱动虚拟 RAF 与原生帧；其他作品的 `runtime-browser.mjs` 记录原生呈现计数，不替代实体高刷验证。

### DISPLAY-03 | 额外绘制无逻辑副作用

- 场景与操作：在同一逻辑帧保存世界、RNG、计时和存档状态摘要，重复请求绘制，再重新读取这些状态。
- 权威观察与预期：使用本作只读观察和固定快照比较绘制前后逻辑字段；相同逻辑输入的绘制结果另行比较。
- 通过／失败：额外绘制不改变逻辑状态、RNG、Replay 或存档字节；任何一项变化即失败。
- 反例：在绘制路径推进动画随机数或更新对象池，确认快照定位到首个改变字段。
- 当前入口与覆盖：`common/testkit/presentation-lab` 提供重复绘制对照；th07 `singleplayer-presentation-purity-test.py` 与各作 renderer 测试覆盖部分生产路径，逐作完整状态仍由本作入口补齐。

### DISPLAY-04 | 连续视觉字段插值

- 场景与操作：用固定输入选取两个连续逻辑样本，在其间增加绘制采样，分别检查玩家、弹幕、激光、附属物和动画切换。
- 权威观察与预期：连续字段按本作明确的采样映射与逻辑前后值检查；贴图、状态、出生／销毁仍按离散逻辑边界检查。
- 通过／失败：中间呈现符合本作连续字段契约，离散变化只在相应逻辑状态生效；旧状态残留或状态提前切换即失败。
- 反例：把连续坐标改成只取整网格，或在对象复用后沿用旧插值端点，确认位置／对象身份断言失败。
- 当前入口与覆盖：th09 `renderer.test.mjs`、TH11 `anm-renderer`／`player-rendering`、TH15 `position-interpolation` 等覆盖各自字段；不得把单个 renderer 或共用模块结果写成全部对象通过。

### DISPLAY-05 | 出生、销毁和瞬移

- 场景与操作：用固定关卡样本触发对象出生、销毁、瞬移／切面及对象池复用，跨越各自逻辑边界连续采样。
- 权威观察与预期：记录对象身份／代次、有效状态、当前逻辑位置及提交的绘制对象；新对象的当前状态构成独立预期。
- 通过／失败：新对象从自身当前状态绘制，销毁对象不再出现，瞬移不沿旧对象轨迹补间；任一旧代状态残留即失败。
- 反例：强制池槽位复用但保留前一对象的位置或贴图，确认代次与画面对象不匹配。
- 当前入口与覆盖：TH11 有 `player-lifecycle`、`item-rendering`，TH15 有 `player-lifecycle`、`stage-resource-lifetime` 等测试；逐作登记实际触发的对象类型与样本范围。

### DISPLAY-06 | 暂停画面的表现

- 场景与操作：进入可操作关卡后打开本作暂停菜单，连续采样世界、对象动画及菜单呈现，再按本作流程退出暂停。
- 权威观察与预期：以原生暂停状态和世界逻辑帧为世界权威；菜单动画／光标依本作暂停界面的状态机单独观察。
- 通过／失败：暂停期间世界保持暂停，菜单只按其设计更新；世界帧继续推进或菜单错误冻结即失败。
- 反例：使用 GameOver／Restart 遮罩冒充暂停状态，确认暂停断言要求真正的 Pause screen。
- 当前入口与覆盖：`tools/ports/runtime-browser.mjs` 有原生暂停／重开检查，TH11／TH15 各有 `pause-frame`、`pause-menu` 等单测；截图补充菜单外观，不能代替帧状态。

### DISPLAY-07 | 实际呈现后报告首帧

- 场景与操作：从冷启动开始记录启动事件、首个绘制提交和浏览器实际呈现证据，覆盖初次加载与刷新后恢复。
- 权威观察与预期：把 Runtime 的 `first-frame` 与对应页面及画布的首次实际呈现事件按同一次导航身份关联。
- 通过／失败：首帧事件发生在可验证的实际呈现之后；仅完成初始化或提交绘制命令而没有画面呈现即失败。
- 反例：推迟合成器提交或保持画布空白，确认事件不能因 Runtime 初始化完成而提前通过。
- 当前入口与覆盖：`runtime-browser.mjs` 的 `configure-launch-first-frame` 等待 Runtime 事件并核对画布；事件与浏览器实际呈现时点的关联断言待接入。

### DISPLAY-08 | 限制到 60 Hz

- 场景与操作：在高刷设备运行相同关卡与输入，分别关闭和打开 60 Hz 呈现限制，记录实际呈现、逻辑帧和输入效果。
- 权威观察与预期：比较本作原生逻辑帧／已消费输入与呈现事件；限制开关只约束呈现频率。
- 通过／失败：开启限制后画面按 60 Hz 口径呈现，而逻辑速度、输入规则和 Replay 结果不变。
- 反例：让限帧器跳过模拟步或累积输入，确认逻辑帧／Replay 对照失败。
- 当前入口与覆盖：TH15 `high-refresh-browser.test.mjs` 检查受限与未受限绘制循环；其他作品需执行同一设备操作并附本次刷新设置和原生帧记录。

### AUDIO-01 | 正常 OGG 音乐

- 操作：选择本地或远端 OGG，进入标题再开始一局，并按本作表要求切换曲目。
- 观察与独立预期：采集实际 PCM 输出和加载的 OGG 身份，将曲目与固定资源清单或独立原版执行对照。
- 判定：每个要求场景输出对应曲目，错误曲目、持续静音或未解码都失败；不设置未有依据的幅值门槛。
- 反例：界面显示已选择 OGG，但 Runtime 没有读取轨道或 PCM 全零，应失败。
- 当前入口/边界：th11 的 tests/browser/audio-check.mjs 从原生混音器采样 WAV/音乐 PCM 并检验若干生命周期；不是正式 Launcher 包验收，也未覆盖全作品。Launcher 的 music-availability 测试只核模式选择。

### AUDIO-02 | 无 BGM 模式

- 操作：选择无 BGM，进入玩法并触发原表列出的射击、击中等音效。
- 观察与独立预期：分别采集音乐轨和音效输出通道/事件，参考同一场景启用 OGG 时的独立轨道身份。
- 判定：BGM 轨无输出而音效仍产生对应 PCM；“全静音”不能作为无 BGM 通过。
- 反例：音乐关掉后音效设备也被停止，应失败。
- 当前入口/边界：runtime-browser 用 music none 配置但没有检查 PCM；当前自动覆盖主要是选项/可用性契约，尚无全作品音效与音乐分离验收。

### AUDIO-03 | 切曲、渐变、暂停、停止

- 操作：按原表顺序进入标题、开始、触发 Boss、暂停、重开和退出，并在每个边界采集实际输出。
- 观察与独立预期：记录曲目资源身份、音频事件、PCM 连续位置及播放/停止状态；切换顺序由本作场景和原作/适配规则确定。
- 判定：切曲、循环、淡入淡出和停止均发生在声明的游戏状态边界；每种转换结果单独记录。
- 反例：本作规定该阶段挂起音乐时曲目仍推进，或退出旧 Runtime 后旧音频仍覆盖新局，应失败；暂停期间是否继续 BGM 以本作已确认规则为准。
- 当前入口/边界：th11 audio-check harness 覆盖若干 native pause/restart/跨 stage 行为；runtime-protocol 和音频桥接契约只检查消息，不证明正式 Launcher 的完整曲目流程。

### AUDIO-04 | 返回前台后恢复声音

- 操作：播放期间隐藏页面或切后台，再返回并执行浏览器需要的音频恢复手势。
- 观察与独立预期：记录 AudioContext 状态、选中曲目、输出 PCM 和当前位置；返回前后按音频连续状态及曲目循环规则比较。
- 判定：前台恢复后有正确曲目输出，位置沿连续曲目推进或按本作既定暂停策略恢复。
- 反例：AudioContext 显示 running 但采样 PCM 仍为零，应失败。
- 当前入口/边界：audio-health 与 MidiBridge 单测检查恢复策略和状态事件，shell-protocol 测试模拟可见性处理；没有所有作品实际 OGG PCM 的前后台回归。

### AUDIO-05 | 音乐资源错误信息

- 操作：用缺失和损坏的 OGG 分别启动，再从提示中切换至本作仍可用的其他音乐方式。
- 观察与独立预期：记录请求失败、Runtime/Launcher 可见诊断、可用模式和切换后的真实 PCM。
- 判定：错误能定位资源问题，Launcher 仍可让用户选择其他有效方式；不能静默标成音乐正常。
- 反例：缺失资源后留下旧曲音频却报告所选新曲已播放，应失败。
- 当前入口/边界：music-availability 覆盖资源可用性决策，资源获取有包与导入测试；没有所有标题对损坏 OGG 的端到端提示和恢复场景。

### AUDIO-06 | 高刷新与音频事件分开

- 操作：在 60 Hz 与更高刷新设置下，以相同逻辑输入和回滚样本触发同一音效。
- 观察与独立预期：将原生实际音效事件身份/数量和输出 PCM 起点与逻辑事件对应，独立参考是一项逻辑事件对应的声音事件。
- 判定：额外绘制帧不增加音效事件；回滚重演不重复播放已确认事件。
- 反例：仅提升显示刷新率便使一次击中发出多次声音，应失败。
- 当前入口/边界：presentation source contract 与 audio-health 诊断模型检查接口/诊断字段；没有全作品高刷回滚音效计数器。

### MIDI-01 | 声明 MIDI 选项

- 操作：逐一检查产品能力声明、已安装音乐资源和 Launcher 中音乐选择控件，再改变 MIDI 能力或资源 fixture 重载。
- 观察与独立预期：产品目录和发布 manifest 是能力预期，UI 是否出现选项与当前能力及可用播放路径一致。
- 判定：声明支持时选项存在且具备资源/传输路径；不支持时不提供不可用 MIDI。
- 反例：能力声明为不支持却显示可选 MIDI，或支持项被错误隐藏，应失败。
- 当前入口/边界：adapter capability、product catalog 与 midi-capability-contract 检查声明和共享传输接线；这些是静态/组件证据，不是所有产品页面的实机播放验收。

### MIDI-02 | 可听到的 MIDI 输出

- 操作：选 MIDI 并进入原表指定场景，触发已知曲目。
- 观察与独立预期：保存 Runtime 输出的 MIDI 字节流，并采集合成器实际 PCM；将曲目消息与同一资源的独立 MIDI 序列对应。
- 判定：输出包含正确曲目事件且合成 PCM 非静音；只发出事件或 MIDI 设备存在不等于可听。
- 反例：合成器调用被发送但没有连接到音频输出，PCM 仍为静音，应失败。
- 当前入口/边界：midi-capability-contract 检查 Runtime 到 Launcher 合成器的通路，midi-bridge.test.mjs 明确使用模拟 AudioContext；当前没有正式包内 MIDI 曲目 PCM验收。

### MIDI-03 | MIDI 生命周期

- 操作：在曲目播放时切曲、暂停、重开并退出，捕获每个转换前后的 MIDI 消息与合成 PCM。
- 观察与独立预期：把 Note On/Off、控制器重置、合成器活动音符和本作阶段对应；边界预期由原版行为或正式音乐规则给出。
- 判定：暂停/退出按本作设计停止或挂起，重开与切曲恢复正确曲目，没有遗留音符。
- 反例：退出后仍有旧 Note On 声音，或暂停时旧音符悬挂，应失败。
- 当前入口/边界：midi-bridge.test.mjs 覆盖模拟 MIDI 消息、focus、pagehide 和 dispose 生命周期；没有真实 Runtime 曲目与 PCM 连续性测试。

### MIDI-04 | MIDI 与 OGG 分开

- 操作：移除 OGG 后选择 MIDI并播放，再恢复 OGG 文件，切回 OGG重新播放。
- 观察与独立预期：分别核对有效模式、资源请求和实际 MIDI 消息/OGG PCM；两类资源身份和读取路径独立。
- 判定：OGG 缺失不禁用有效 MIDI，MIDI 切换不复用旧 OGG 声音；安装 OGG 后选择 OGG 使用 OGG 轨。
- 反例：菜单变为 MIDI，但实际仍输出先前 OGG；或删除 OGG 导致 MIDI 也无法启动，应失败。
- 当前入口/边界：music-availability.test.mjs 以组合 fixture 检查模式决策，catalog 测试检查资源挂载；未检查两条真实 Runtime 音频路径切换。
