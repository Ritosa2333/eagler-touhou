## 启动

服务端需要 **Python 3.10+**，玩家推荐使用新版 Chrome／Edge。单人和本机合作需要浏览器支持 WebAssembly JSPI。通过启动器使用 HTTP 访问，不要直接双击 HTML。

| 模式 | 启动器 | 地址／端口 |
| --- | --- | --- |
| 单人／本机双人或三人 | `start.bat` | `http://127.0.0.1:9872/index.html` |
| 两／三人局域网 | `start-lan.bat` | 19822，使用窗口显示的局域网网址 |
| 两／三人公网 | `start-public.bat` | 窗口显示的临时 HTTPS `GAME URL` |

本机端口 9872 被占用时会寻找后续可用端口，以启动窗口为准。启动页可选择四种模式；局域网／公网房间需要运行对应服务。

首次部署联机服务，先运行 `install-relay.bat`，或执行：

```powershell
python -m pip install -r requirements-relay.txt
```

公网临时隧道还需要安装 `cloudflared`：

```powershell
winget install --id Cloudflare.cloudflared --exact
```

`start-public.bat` 会启动或复用本项目的房间后端。把完整 `GAME URL` 分享给伙伴，房主和其他玩家均使用这个网址，并保持启动窗口开启；重新启动可能生成新地址。`start-public-tunnel.bat` 是同一公网启动入口。其他玩家只需浏览器，无需安装 Python 或模拟器。

非 Windows 系统可在本目录运行 `python server.py --no-browser`，或安装联机依赖后运行 `python lan_server.py --bind 0.0.0.0 --port 19822`。正式 HTTPS/WSS 部署、直连与 TURN 配置见 [局域网与公网说明](LAN-公网联机说明.md)。

## 模式与操作

**单人游戏**使用独立磁盘，保留原版开场、菜单、选难度、选机及原版资源、得分和碰撞规则。支持低速、判定点、手柄、按键自定义与触屏。默认使用浏览器独立 BGM，也可选择原版声音。

单人保留当前原生 EMS Boss HUD：全部六场关底 Boss、前四面有 HP 的道中、阶段刻度及实际可用的倒计时／∞，并保留右侧纯黑背景校正。练习覆盖从已发布的 HUD 单人 MAIN 派生，安装在运行副本中；新练习 REP 严格核验对应资源与终态内存。

**本机合作**支持两人或三人共用一个游戏世界。人数、语言、P1／P2／P3 机体、起始关卡、难度、备用残机、起始 Bomb 和低速／判定点均在浏览器设置，启动后直接进入所选关卡，跳过开场、难度与选机菜单。Extra 使用原生 Extra 难度；各玩家的低速偏好可分别保存。

多人直接开局同时跳过原版 ZUN 标志动画，并关闭 BIOS 启动页的定时等待，保留原版驻留程序和音效驱动初始化。联机仍完整校验资源，并在所有玩家到达相同关卡状态后同步开始。

**局域网／公网**支持两人或三人。房主在浏览器选择语言、人数、起始关卡（1～5／Extra）、难度、备用残机（0～5）、起始 Bomb（0～5）、全队低速开关、敌人瞄准方式和回滚；每名玩家落座后选择自己的机体并准备。低速固定为各机体正常移速的 **50%**。修改机体或本局设置会清除全员准备。全员加载至相同关卡初始状态后同步开始，跳过开场和选机菜单。Extra 使用原生 Extra 难度；默认每人 2 个备用残机、3 个 Bomb。游戏中不支持加入或重新接管。

默认键位如下，联机时每端用 P1 键位控制自己的座位：

| 操作 | 本机 P1／联机本端 | 本机 P2 | 本机 P3 |
| --- | --- | --- | --- |
| 移动 | 方向键 | WASD | 小键盘 8／2／4／6 |
| 射击 | Z | J | 小键盘 0 |
| Bomb | X | L | 小键盘小数点 |
| 低速／停火救援 | Shift | K | 小键盘 Enter |

Esc／P 打开原生暂停菜单，主键盘 Enter 确认；本机 P3 的小键盘 Enter 不触发菜单确认。联机原生菜单由 P1 选择，其他玩家可以请求暂停／确认。页面提供全屏、声音开关、音乐音量、重新启动和“下载故障信息”。

“按键与触控”可保存键位及触屏布局。标准手柄可分别分配给各玩家：摇杆／十字键移动，A 射击、B Bomb、X／左肩键低速、Start 菜单、Back 确认；同一手柄只分配给一个玩家。

触屏支持单指拖动、第二指低速、开火切换、Bomb／双击 Bomb、停火救援、灵敏度和限速设置、判定点，以及横竖屏分别保存布局。本机合作可切换触控玩家，暂停菜单交给 P1。本机低速设置保存在当前浏览器；联机低速由房主统一设置，判定点显示仍由各玩家自行设置。关闭低速移动后，低速键仍可用于停火救援。

游戏运行中的文件和分数记录仅在本次运行有效；刷新或重启重新载入初始盘。

## 合作规则

所有玩家共用关卡、敌人、敌弹和道具，各自移动、射击，独立持有生命、火力和 Bomb；分数及计分计数为全队共用。原生侧栏显示各玩家资源与 Boss 总血条；联机工具条显示团队分数。备用残机为 0 时仍有当前一命，残机和 Bomb 上限均为 5。

| 多人倍率 | 双人 | 三人 |
| --- | --- | --- |
| P 点增量 | 原版 1.5 倍 | 原版 2 倍 |
| Boss／中 Boss 有效血量 | 原版 1.5 倍 | 原版 2.2 倍 |
| 分数奖励 | 原版 1 倍 | 原版 1 倍 |

倍率按开局人数确定，玩家退场后不降低。合作侧栏以原生整数显示火力，例如 `P 20/80`，上限保持 80 P；双人小 P 交替增加 1／2 点、三人增加 2 点，大 P 分别增加 15／20 点，各席位独立保留半点余量。多人共享弹池已由 38 格扩至 114 格，各席位保留原生射击周期及独立僚机射击相位，不按人数减少发射量。世界和弹丸每帧只更新一次，射弹归属在生成时直接记录，伤害等级在确认命中后读取，减少反复扫描与未命中计算。

- P 点增加拾取者火力；判定重叠时按 P1、P2、P3 顺序优先。
- 一个 Bomb 道具使所有存活玩家各增加 1 个 Bomb，幽灵不获得；释放只扣释放者库存。Bomb 演出使用释放者的机体类型，演出期间不能重复发动。各玩家的射击类型独立。
- 一个 1UP 使所有存活玩家各增加 1 个备用残机；幽灵以当前一命、0 个备用残机复活，保留火力和 Bomb，并获得 150 帧无敌。
- 全队共用一份分数与加命进度，在 100 万、200 万、300 万、500 万、800 万分触发一次团队 Extend。效果与 1UP 相同：所有非离线队员加一条命，幽灵按 1UP 规则复活，残机上限为 5。
- 用尽生命后成为不能移动、攻击、拾取或受伤的幽灵。全员退场才结束游戏；换关时幽灵免费以当前一命、1 个 Bomb 和保留火力重新加入。
- 敌人默认从存活玩家中选择最近目标；普通无敌期间仍可成为目标，幽灵和受击死亡动画不参与。页面可关闭队伍瞄准，恢复只瞄准 P1。
- 多人模式下，任意玩家中弹都会清除全屏普通敌弹和独立激光池；本地双人／三人与网络合作共用这条原生规则。测试无敌开启时，P1／P2／P3 撞弹同样触发清弹且不扣命；死亡动画只在首次中弹时清弹。

救援需要施救者至少有 1 个备用残机。停火、不放 Bomb，靠近目标后低速键连按 **5 次**；每两次最多间隔 **24 个游戏帧**。射击、放 Bomb、离开范围或切换目标会清空进度，暂停时不累计。顶部 HUD 显示 `1/5` 至 `4/5`。

- 目标存活：转移 1 个备用残机，双方火力和 Bomb 不变。
- 目标为幽灵：施救者扣 1 个备用残机，Bomb 减半向下取整；目标以当前一命、1 个 Bomb、保留火力和 150 帧无敌复活，并短暂清弹。
- 键盘与触屏都要分别按下、松开低速键；完成后松开才能再次给命。触屏救援按钮每次点按记一次，并在连按期间暂时停火。

P1 使用原版红色灵梦，P2 蓝色，P3 绿色，出生位置分别在左、右、中间；退场后的幽灵也按红、蓝、绿区分。本体使用 `ghost-preview/th02-player-colors` 的 **TH02 专用绿色玄爷**素材，包含全部 10 帧，保留玄爷、肤色、头发和透明区域。幽灵使用 `ghost-preview/th05-four-player-colors/reimu` 的三色灵梦幽灵，仅借用幽灵素材。本地合作与联机共用这套美术。

右侧每位玩家的标题行增加同色札弹标识，采用 TH02 原版 `MIKO16.BFT` 第 4 帧。札弹位于 x=480，原僚机图标移至 x=504，中间保留 8 像素空隙；幽灵状态也显示席位颜色，僚机仍按所选机体显示。

多人玩家信息按每人三行连续排列，取消玩家之间的空行；三人时占第 8..16 行（从 0 计），与第 19..20 行的 Boss 标题、血条之间保留两行空白。右侧面板仍由游戏原生绘制，底色保持纯黑。

三种机体的主射弹、僚机射弹及命中动画使用 `ghost-preview/th02-player-colors` 的弹幕分色素材：P1 保留原版弹色，P2 使用蓝／紫罗兰／青，P3 使用绿／青绿／金，保留不同弹族的区别、白色高光和黑色轮廓。僚机外观一律保持原版，不采用预览目录里的僚机颜色差分。弹形、弹道、命中判定、伤害与计分沿用原生逻辑；本地合作与联机均生效。

测试无敌默认关闭，可在页面启用；开启不增加资源或自动复活，成绩应与正常游玩区分。

## 联机、音乐与性能

默认使用 **WebSocket 服务器转发**，不依赖 ICE 打洞或玩家端口映射；服务器只转发输入与控制消息，不运行模拟器或传输音视频。可手动选择 WebRTC 直连，启动连接失败或超过 8 秒时全房间自动切回转发。

游戏中发现断线后留出 **5 秒恢复期**，同一页面会尝试恢复连接。客机超时后，由在线玩家同步离线时刻，对应席位成为原配色的**离线幽灵**，右侧显示 `OFFLINE`，其余玩家继续；两名客机都掉线后房主也能继续。离线角色不能操作、攻击、受伤、拾取或接受救援，1UP、换关和续关都不会将其复活。本局保留其席位、库存和开局人数，不支持刷新页面后接管离线席位。房主断线超时仍结束本局，与 TH04 相同。

协议为 `th02-rollback/6`。默认开启预测回滚，**零步本地输入缓冲、最多领先 6 步、保留 12 步恢复历史**；达到预测上限等待真实输入。这减少快慢端之间的无效恢复和重算，高延迟时会更早等待。关闭回滚后使用开局测量确定的 2～12 步锁步缓冲。短按会保留到原生游戏真正读取，降低采样频率不同造成的输入遗漏。

**联机音乐与音效独立播放**：15 首原曲由浏览器加载 Opus 并独立循环，19 个原作 PMD 音效预加载为完整声音。切曲、淡出及原生优先级选出的音效在同步步确认后提交；已开始的声音由音频设备独立播完，等待网络和回滚不再造成逐帧 PCM 断供或重复播放。新的音效仍跟随对应游戏事件，补包时保留最新音效，沿用原作单音效通道的打断规则。本地音乐音量可独立调整，首次无声时点击“启用声音”。音乐加载失败会显示详情，不直接停止游戏。

各端开局前校验游戏盘、核心及适配模块的实际资源摘要。**更新后重启服务，所有玩家关闭旧游戏页、强制刷新并重新建房**；不同版本不能混用。公网入口重启后分享新生成的完整网址。

当前真实浏览器回归覆盖中／日文双人／三人、WebSocket 和 WebRTC、延迟输入、暂停恢复、回滚后共同确认状态、短暂断线恢复、客机离线变幽灵后继续、完整内存／执行栈／文件恢复，以及独立 BGM。三种 Bomb 演出共 8 次完整释放的优化绘制、可见像素与重放对照一致，覆盖范围内未发现额外闪烁，保留原生明暗效果。

上述测试使用本机浏览器和部分 QA 状态设置，不代表全部关卡自然通关、实体手机／手柄或异地公网长期验证。弱设备计算不足、高延迟和抖动仍会使全局等待；减少重算不等于保证满速。优化方法及测量范围见 [联机同时操作卡顿优化记录](联机同时操作卡顿优化记录.md)，原始报告保留在开发机的 `reports/`，不随发行包发布。

遇到卡住、不同步或画面异常，请在重启前使用“下载故障信息”，联机时各端均保存。故障文件只下载到本机，不会自动上传。“游戏逻辑帧率”、同步步和画面提交次数是不同指标，不能用浏览器绘制次数代替游戏帧率。

## 开发与重建

以下命令只用于保留完整开发文件的本地工作区，在 `th02-coop-lab` 目录执行；发行仓库不包含这些开发目录。重建依赖同级 TH04 的固定 FAT12／NASM／核心工具、源游戏盘和其他本地素材，不能仅凭发行仓库从源码重建全部资源。

```powershell
# 重建合作盘，保留 TH02 专用运行时包装器
python tools/build_local.py --keep-runtime
python tools/build_launch.py
python tools/build_network_sound.py
python tools/refresh_network_patches.py

# 修改原生布局或颜色核心后，重建本地、联机及写入追踪核心
python tools/build_player_art_runtime.py

# 重建独立单人盘
python tools/build_solo.py

# 运行资源修改后刷新联机摘要并审计
python tools/update_network_manifest.py
python -B tools/audit_network_assets.py
```

`tools/build_local.py` 保留 TH02 专用运行时，并从三色 PNG 生成 `web/assets/th02-player-art.bin` 与来源摘要。`tools/build_player_art_runtime.py` 从 `build/art-baseline-20261016` 固定核心派生带像素来源标记的 RGB 核心，重新生成写入追踪；须在原生补丁重建后运行，以匹配数据段布局。RGB 替换作用于实际原生绘制出的服装、幽灵、席位札弹图标和玩家射弹，射弹颜色取自已有的发射者归属记录，保留原生遮挡、文字层及调色效果，来源标记随回滚恢复。

合作盘重建后必须运行 `tools/refresh_network_patches.py`，重新生成联机会话私有 MAIN 的状态交换、行复制和普通弹碰撞优化。它会验证中／日文入口字节和目标空闲区；不能只更新旧策略的摘要。`update_network_manifest.py` 会拒绝与当前 MAIN 身份或代码段不一致的策略，避免生成资源摘要后仍在联机启动时失败。

`python tools/build_network_runtime.py` 是从 TH04 冻结公共核心派生基础 TH02 核心的旧入口，单独运行会替换多人配色核心。完整重建需要固定的基础核心和工具链。音乐构建使用 `tools/build_local_bgm_assets.py`、PMD 渲染器和 ffmpeg/libopus。普通游玩无需 Node.js、NASM、Binaryen 或上述源码工具。
