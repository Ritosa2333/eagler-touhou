# TH02 局域网与公网联机

## 局域网

1. 房主电脑运行 `start-lan.bat`，默认监听 `0.0.0.0:19822`。
2. 两台或三台设备连接同一个局域网，打开启动窗口中同一个 `http://电脑局域网IP:19822/lan.html`。
3. 创建或输入四位房间号。房主在网页选择人数、语言、起始关卡（1～5／Extra）、难度、每人备用残机、起始 Bomb、全队低速开关、敌人瞄准方式和回滚；每端选择不同座位，包括 P1 在内均在网页选机体。
4. 全员准备后房主开始。各端先加载至关卡初始状态，再同步开始游戏，跳过开场和选机菜单。Extra 使用原生 Extra 难度；残机不含当前自机，资源独立。

默认使用服务器转发（WebSocket），无需 ICE 打洞；两种联机入口均保持每端独立模拟。加入者自动采用房间的连接方式。

可在“连接方式与帮助”中手动选择设备直连（WebRTC）。启动时直连等待超过 8 秒、协商失败或浏览器不支持 WebRTC，全房间自动改用服务器转发，保留房间号、座位、设置和已加载的游戏，不必退出重新建房。三人局也会全员统一切换；开始后在当前连接方式下尝试恢复，客机断线超时则变成离线幽灵，其余玩家继续。

如果旧页面曾显示“建立数据通道超过 30 秒（ICE disconnected）”，关闭旧服务窗口后重新运行 `start-lan.bat`（公网用 `start-public.bat`），所有玩家刷新页面并新建房间。默认入口不再依赖 WebRTC；公网重新启动后分享新生成的完整 HTTPS 网址。

## 公网：一键临时 HTTPS/WSS

运行 `start-public.bat`，把窗口打印的完整 `GAME URL` 分享给其他玩家。全部玩家包括房主使用这个网址。此脚本会自动启动本项目后端；如果端口上已经运行本项目同协议服务则复用，退出时只停止自己创建的进程。

默认地址格式：`https://随机名称.trycloudflare.com/lan.html?network=public&transport=ws`。关闭窗口或 Ctrl+C 后公网入口停止；下次启动生成新地址，旧房间不可恢复。实际可达性和延迟取决于各玩家到 Cloudflare 的网络，临时隧道不能保证所有地区可用。

启动阶段 WebSocket 的 DNS／TLS／升级握手临时失败会在 30 秒期限内自动重试；游戏中同一页面的短暂断线也会自动重连并补发未确认消息，避免重复执行操作。离线已被全队确认后不能重新接管。持续无法访问临时域名时，可重新启动公网入口生成新网址，或使用下面的正式 HTTPS 服务器部署。

部署机需 Python 3.10+、`pip install -r requirements-relay.txt`，以及 `cloudflared`。Windows 可安装：

```powershell
winget install --id Cloudflare.cloudflared --exact
```

玩家只需浏览器，无需自己安装模拟器、Python、cloudflared 或拷贝游戏文件。新版 Chrome／Edge 推荐使用；局域网 HTTP 上某些浏览器不提供手柄权限，可改用 HTTPS。触控和键盘沿用网页入口。

## 正式公网服务器

把本目录运行文件与完整 `web/` 一起部署。后端启动命令：

```bash
python -m pip install -r requirements-relay.txt
python lan_server.py --bind 127.0.0.1 --port 19822
```

在已配置证书的 Nginx HTTPS server 中代理整个独立域名根目录，保留原 Host，以便来源校验：

```nginx
location / {
    proxy_pass http://127.0.0.1:19822;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_buffering off;
    proxy_read_timeout 600s;
}
```

玩家访问 `https://你的域名/lan.html?network=public&transport=ws`。网页、房间 API 和 `/relay` 必须进入同一个后端实例；房间是内存状态，多进程部署需要会话粘滞，不可随机分配到不同实例。后端不运行模拟器、不传输画面或音频。

## 公网 WebRTC / TURN

使用 `lan.html?network=public&transport=rtc`。默认 STUN 为 `stun.cloudflare.com:3478`；浏览器 ICE 尝试打洞。HTTPS Tunnel 仅代理网页／HTTP／WSS，不能替代 TURN。

需要 TURN 时在 `web/netplay/udp-config.js` 填入同源短期凭据接口，或使用随附 `configure-turn.bat` 配置服务器私有 Cloudflare TURN 凭据，再把 `credentialEndpoint` 设为 `/api/ice`。长期密钥保存在网页目录外的 `turn-config.local.json`，不能上传到 `web/`。页面提供实际选中候选对的路径诊断；收到 ICE candidate 不等于直连成功。

## 操作和故障

默认开启预测回滚，关卡开始即生效，本机输入缓冲为 **0 步**。远端方向最多连续预测 6 步，快端最大预测领先也限制为 6 步；达到上限时等待真实输入，再由输入到达唤醒。保留 12 步回滚恢复历史，零步本地缓冲不变，不额外插入固定 6 步延迟。此限制减少双方持续射击、变向时的无效恢复与重算，但高延迟网络会更早等输入。回滚会额外消耗重算与快照性能，性能较弱时可关闭。关闭后在全员关卡就绪后测量玩家之间的往返延迟，排除编译／预热期间的假延迟，以单程延迟加一同步步余量统一设置 2～12 步锁步缓冲（约 33～200 ms，另有执行和呈现时间）。三人局计入客机之间链路；整局固定。例：160 ms RTT 使用 6 步缓冲，旧版为 12 步。

键盘／触控短按先保留到同步输入成功采样，再保留到原生游戏真正读取；不因等待或模拟器中途让出执行而被松开状态覆盖。更新使用 `th02-rollback/6`，需重启本项目服务、所有玩家强制刷新并新建房间。

**BGM 与本体分离**：15 首原曲使用本项目的 Opus 资源，由浏览器按需加载、独立循环播放；原生 PMD 不再加载／播放乐曲，原生 FM 音效保留。切曲、音量和淡出命令经过同步步确认后提交，投机回滚不会提前切曲或重复播放。等待网络、原生暂停和回滚期间，音乐继续按本机音频时间推进。工具条“音乐”滑条只改变本机 BGM；首次没有声音时点击“启用声音”。音乐下载或解码失败只在详情显示，不停止游戏。玩法性能仍取决于设备和链路，迁出音乐不代表消除所有卡顿。

“游戏逻辑帧率”反映原生游戏计数，不等同于同步步或浏览器刷新率。“等输入时间占比”高时优先检查网络；模拟耗时持续超过每步约 16.7 ms 时，设备计算速度也会限制推进。下载故障信息包含最近 120 个约一秒统计周期，便于比较两端。暂停、关卡切换及隐藏页面时的数据不应当作战斗帧率。

- 各端方向键、Z、X、Shift 或已设置的手柄／触控控制自己的座位。
- 原生暂停菜单由 P1 选择；任意玩家可以请求暂停／确认。停火靠近队友，低速键连按 5 次救援，每两次最多间隔 24 个游戏帧；给命惩罚沿用原规则。
- 全队低速由房主统一开启或关闭，固定为各机体正常移动速度的 **50%**，默认开启。关闭后低速键仍可停火救援。判定点只影响当前浏览器显示，可由各玩家自行设置。
- 修改人数、语言、关卡、难度、残机、Bomb、机体、低速、敌人瞄准或回滚后清除准备，需要全员重新准备。游戏开始后锁定设置，不支持中途加入。
- 游戏中断线先留 5 秒恢复期。客机超时后，全队同步将其席位变为原配色的离线幽灵，右侧显示 `OFFLINE`，其余玩家继续；两名客机均离线后房主仍能继续。离线幽灵不参与战斗、拾取或救援，不能通过 1UP、换关或续关复活；开局人数及席位保持。房主超时仍结束本局，不支持刷新页面后接管席位。
- 游戏详情显示确认步、实际游戏帧、输入等待、回滚和路径。各端相同确认步的状态摘要必须相等；发现不同会停止，防止继续运行两个不同的世界。
- 页面提供“下载故障信息”，文件仅在本机下载。卡住时保留两端报告与同帧号，不把浏览器绘制频率当作游戏帧率。
- 房间和资源版本必须匹配；修改脚本或核心后运行 `python -B tools/update_network_manifest.py`，所有玩家强制刷新并重新建房。

本次同时操作优化的验证与范围见 [联机同时操作卡顿优化记录.md](联机同时操作卡顿优化记录.md)。更新资源后所有玩家强制刷新并新建房间；游戏窗口的“下载故障信息”包含最大预测领先、回滚／重算累计值、最近两分钟执行成本及最近 512 次画面提交间隔。
