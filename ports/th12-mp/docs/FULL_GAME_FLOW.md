# th12 旧网页前端流程

本页说明 `build-legacy-eagler.mjs` 对应的网页前端与对照工具。正式 SDL 应用见[开发指南](DEVELOPMENT.md)。

## 入口与职责

`site/index.html`／`game.mjs` 是完整游戏入口，`preview.html`／`main.mjs` 保留独立关卡、
拖动录像及原版逐帧对照。检查器 iframe 直接访问 `preview.html?frameInspector=1`。

`TitleScenes` 负责60Hz菜单输入、选择、过渡和请求；`TitlePresentation` 解释原版菜单 ANM。
标题八项为 Start、Extra Start、Practice Start、Replay、Result、Music Room、Option、Quit。
Manual 是 F1／工具栏的移植版说明，不是添加的原版标题选项。

标题输入重复遵循26帧起、每8帧重复；闲置1800帧后按 demo2、demo1、demo0 循环。
标题音乐在初始化阶段建立播放传输，进入标题即可播放；没有共享 AudioContext 的启动器也使用此路径。浏览器需要额外音频手势时，点击游戏画面即可解锁，无需进入菜单。游戏画面保留鼠标指针，供原生练习面板使用。
Demo 接受 Z／X／Esc／Enter 退出，3540帧开始淡出，3600帧返回标题。
音乐室连续显示十行，所选曲目越过边界时移动顶部索引；确认后播放并展示八行原版评论。
选项使用原版100／80音量默认值及5%步长；Key Config还原为五项手柄按钮编号，
默认按钮为0、1、2、4、3。临时更改须在Quit确认才生效；Reset恢复进入页面时的设置。

当前菜单修订来自静态反编译和ANM资源，按用户要求没有运行测试或画面对照。
标题背景保留长期实例；返回标题不重播180帧开场；Option保持标题背景。
Extra经专用难度页进入，难度卡及选中人物保留到装备页，过渡采用原版IRQ及14／40帧时序。
标题Extra锁定前立即执行行定位IRQ30／31，再排入锁定IRQ29；首次菜单出现时即应用。
Extra难度卡使用root132的子脚本125，初选仍是IRQ17。
Practice装备确认只等10帧且不淡出，保留装备／人物／难度；选关背景120固定在382／270。
选关取消等6帧，确认第10帧开始32帧淡出、第40帧开局；文字依照选关子状态时钟显示。
加载画面直接绘制原版ascii/loading.png及ascii18组合脚本，文字与花朵由15／16／17的ANM控制，
不再使用HTML加载文字。411b80给出的坐标是480／392；装备及Practice确认第10帧、录像第2帧
创建指示，使用同一实例跨越菜单淡出和资源准备。411b00的IRQ1退休保留子VM淡出。
加载期间保持绘制循环，游戏逻辑不推进；花朵使用独立共享显示随机流。
启动先绘制sig0／1原始全屏画面，按43f320至少等待180帧，随后直接释放sig，切入标题并退休指示。
小型loading-resources.json由本地菜单资源准备器导出，允许在完整资源清单、Wasm及音频完成前绘制。
这些修改未运行测试或画面检查。
录像每页25行，共三页；缺失槽位仍可高亮；录像关卡按全部七行绘制。
保存录像先选25个槽位之一，再用13×7命名格输入，保存后回槽位列表。
Player Data只在成绩及按难度过滤的十行符卡页间循环，使用原版标题脚本和ASCII字体。
选择页高亮使用title的opcode108／几何18渐变矩形，保留原始颜色、伸缩及选择IRQ。
难度、人物、装备、练习、录像、成绩和音乐室共享ascii20／19花朵动画，退回标题时发送IRQ1。
花朵使用独立显示随机流；音乐室仅加载115标题、211起的曲目及text41～48评论，不加载结果页206～210。
游戏内菜单只接受键盘和手柄输入；无鼠标命中、可点击菜单或屏幕按键，浏览器工具栏保持独立。
Music Room标题取musiccmt原始行，评论逐行淡入；未听曲目显示原PE中八行警告。
暂停的游戏区域以截图叠加绿色模糊，颜色在20帧内渐变，恢复等待12帧。
死亡后的排行榜使用游戏内窄版排版，名字格位于112／320；普通死亡先排行／命名再进入续关。
Practice的完成／失败分别用front116／117；Extra完成排行之后用front116。
游戏内保存录像保留暂停背景，25行从48／64开始；命名行移至102／224。
Extra死亡使用原版共用排行与四项菜单，但续关选项仍受现有C++核心Extra限制，
原版请求14的后续处理尚未确认，未据菜单入口猜改核心。
结局字幕采用text68～72，坐标64／384及16像素行距，保留显隐、五行分页和原版无限确认等待。
已看结局状态独立保存，只有重复观看允许Ctrl跳过。

## C++ 关卡生命周期

`StageFlow` 仅在启用完整游戏时接管 `th12_tick`，独立关卡接口保持原有行为。
普通关卡结算保留120逻辑帧通关奖励，随后执行30帧场地淡出，再进入下一面并淡入；主线第六面等待380帧进入结局，Practice／Extra进入结果。
原版通关奖励由核心结算，网页只绘制奖励数字。
MSG21的通关提示取HUD+6d44中的front85，奖励数字沿用其透明度及224／200位置；不使用text85场景截图。
Boss底部位置标识使用嵌入式ascii0，位于Boss.x+224／480，保留生命阈值闪烁、靠近自机变淡及越界隐藏。
暂停菜单、R快捷键和结果菜单的Retry统一重建整局：普通模式从一面、Extra从Extra、Practice从所选关卡开始。

新关卡主脚本出生前原子恢复 SessionCarry：资源、碎片、UFO库存、内部全局字段、位置、
低速状态、随机数种子；每关 RNG 调用数归零。资源先全部读取，再切换核心。
回放继续消费原录像关卡尾部输入，到实际录像边界才切换下一份关卡头。

续关重开当前关，重置分数、擦弹、PIV和库存，设置原版资源及 rank 惩罚；次数个位封顶9，
没有虚构三次续关限制。Practice 初始化九残机，第二至六面初始2.00灵力，不领取最终资源奖励。
主线按机体、装备和是否续关选择十二份原版结局；Good分支进入原版staff卷轴。

生命周期请求先执行，再推进新局；禁止菜单切回 playing 的当帧误推进已结算的旧录制器。
失焦暂停和操作说明保留当前局；关闭说明后恢复名字、成绩、录像关卡等完整页面参数。

## 浏览器记录与录像

`GameProfile` 在 IndexedDB 的原版文件名路径下存储标明的移植版 JSON。
它不宣称兼容原版 DAT／CFG 编码，遇到未知字节时保留而不覆盖。
记录覆盖排行榜、通关及练习解锁、音乐、符卡尝试／取得次数、名字和游玩时间。
符卡计数由 C++ 的128×7×2原版结构维护，回放仅读取；网页缓存名称和最佳成绩，不重复计数。
Player Data 提供六机体、五种难度含Extra的筛选、成绩、全部对应符卡及原版三项计数。

命名采用原版88字符表和8字符限制，录像可保存到25个编号槽。
同名槽位以浏览器新存数据为先，服务器参考录像为后备，导入文件不上传服务器。
续关后的局不能保存录像。`.rpy` 使用原版头、关卡字段、输入边沿、FPS、结束标记、
加密及合法字面量压缩；文件编码验证与游戏重放验证独立。

## 证据与未验收项

原版静态依据包括43f760标题输入、422ab5 Demo、449360音乐室、410d76结局选择、411420结局解释器。
关卡继承与续关局部测试核对72份原版资源样本和七个 RNG 重置边界。
短录像送入实际43c350加载器并执行4639d0解密、44c710解压；默认字段来自423250／43b080。
菜单几何20的左右渐变依据45d0a0顶点采样；通关文字数字依据421393／420bbc／420c65。

上一版的浏览器检查覆盖标题到开局、暂停确认、设置、音乐室、Demo、名字、保存、同名覆盖及刷新恢复。
六关到结局以及 Practice／Extra 结果链使用合成 ECL／MSG 提前触发边界，不冒充关卡行为 Oracle。
初段900帧完整模式与独立模式一致，录制后重放一致；十二结局和staff脚本解释检查通过。

仍需原版实际游玩核对整局跨关、菜单／结局动画时序和文字排版。
原版配置／成绩的字节兼容编码和共享发布协议尚未实现。

通关后的计分、名字和录像保存流程播放计分曲 `th10_17`；Extra先冻结游戏，再切换计分音乐。录像命名确认按原版43441d／43515e播放音效18。
