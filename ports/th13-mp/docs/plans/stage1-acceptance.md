# Stage 1 全链路验收合同

这是验收定义，不是当前通过声明。外层任务 `stage1-full-chain` 的完成依赖全部必需门。任务执行器、工作流、主 Agent 均无权临场更换口径。

## 1. 框架有效性的实测条件

用户于 2026-10-24 要求：指定 CPA `zai-glm-5-3` 实际接手并完成正确的 Stage 1 全链路，之后才能宣布本轮弱模型开发框架已经做好。工具自测、接手演练、计划书、局部首差推进都不能替代这个条件。

承接入口：外层 `AGENTS.md` → `scripts/verify.py doctor/resume` → 当前任务卡。具体模型宿主 ID 由实际模型列表确认；本轮为 `new-provider/zai-glm-5-3`。工作流运行记录必须绑定实际模型，不由施工报告自报。

## 2. 固定场景与输入身份

第一条主线包括：装载与标题、主菜单、难度、角色/机体选择、普通 Stage 1 道中、Boss、关末对话/过场、真实 Stage 2 入场。

不得以直入战斗的诊断模式替代菜单到战斗链。Replay 的受控输入可用于战斗段，但必须证明其装载初值、六字节输入、消费相位及和主线启动的联系。普通开局必须不走符卡练习。选择的 EXE、资源、录像、难度、角色、机体、种子、初始资源、确定性时间和帧映射写入同一场景 manifest；参数未认证时保持 BLOCKED。

主线的具体期望帧号从已认证原版生产路径生成，不能从视频秒数、旧 Python 玩家模型、历史 HANDOFF 或 port 反推。禁止将 f61 等历史签名推广为所有角色/录像的普遍真值。

## 3. 五道必需门

### 参考资格

- 原版可执行身份及实际使用的资源内容匹配。
- Replay stage 头与原版恢复路径的实际写入字节一致；未知字段保留 raw，不猜 score/lives/bombs。
- state/pressed/released 的六字节值与原版消费点逐帧核对，原版输入游标及更新相位有日志。
- 逻辑帧、battle 帧、Replay 输入帧和 Present 序号分别记录，不靠肉眼或最佳偏移扫描认定相位。
- 正常道中、Boss 进入/击破、关末、Stage 2 装载/进入均有具名生产事件。仅生成足量日志不能证明场景到达。

### 捕获完整

- 每个请求帧唯一且连续，无共同缺帧、重复覆盖、尾部截断或写错误。
- 帧事件结束、进程结束、文件完成记录和实际输出摘要一致。
- 稀疏行为流用生产端完成记录证明全窗执行，不从最后一条行为事件猜测时长。
- 原版与 port 来源独立且身份明确。相同文件、别名、硬链接或把一方输出复制成另一方不能通过。

### 行为和完整渲染语义

- 行为状态与事件不使用旁路伤害、99残机、无碰撞等验证专用规则。
- 全部有效几何、矩阵、每 draw viewport/target、pipeline 状态、纹理内容/版本、字形、clear/copy/upload 和提交顺序相同。
- 未支持状态/未知资源/未捕获绘制来源不能被过滤或当成 null。
- legacy DrawCapture v1 的相同只是局部诊断；新生产提交证据与实际 Renderer 消费同一真值，不允许只写 trace 的补画。
- 严格比较无 ignore、非精确 ULP 或临场豁免，并同时检查比较进程退出码和结构化结果。

### 后端与最终输出

- 真实网页 GLES 后端通过独立数学/GPU fixture；合批/实例化/布局缓存和纹理更新不丢失提交。
- 独立运行原版真实渲染输出，与真实浏览器游戏画布自动数值比较；不是看截图评审，也不是两个输入交给同一个 renderer 自比。
- 捕获帧映射确定，颜色格式、分辨率、渲染配置和读取边界固定；默认 framebuffer 在同一任务内采样，读取不污染 renderer 状态。
- 独立原版环境不存在或失去资格时此门 BLOCKED，不降低为“图看起来接近”。

### 覆盖和无回归

- 主线所有必要阶段均真实发生；HUD、STD、玩家/弹/道具、Boss、对话、暂停/恢复、菜单与转场的提交来源有覆盖登记。
- 单测四套、Node 工具/协议测试、双目标与捕获构建、浏览器统计、旧诊断 golden 全跑。旧基线不退化单列；旧参考失去资格时标为未认证而非重写基线。
- 页面错误、运行崩溃、输出错误、加载失败不被隐藏。

## 4. 报告与判决

每一道门返回匹配当前源码、输入、构建、契约的机器结果。框架有效性只在指定模型实际施工记录和五道门全部闭合时成立。

报告必须分别列出：TOOL_PASS、捕获完整、BASELINE_HELD、参考资格、严格行为、完整绘制、实际后端/最终输出、场景覆盖。任一门缺失不宣布 Stage 1 正确完成。Stage 1 正确主线也不等于全角色、全难度及全游戏还原。

## 5. 后续主 Agent 的固定失败动作

环境失败先修环境；参考资格失败先修参考；捕获字段不全先补捕获；已有资格下的分歧按具名机制定位。每个模块最多三轮无机制进展后保存最小复现进入复核。允许在既定架构中完善任务卡和测试，但不得把“通不过”解释成可以改验收目标。
