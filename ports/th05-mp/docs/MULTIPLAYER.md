# TH05 原生合作模式

两人、三人合作在 `ports/th05-mp` 独立维护，基于 uth05win 原生 C++ 关卡编译为 WebAssembly／WebGL。启动器负责房间、选人、准备和资源安装，Runtime 负责共享世界与逐帧输入。

## 合作规则

- 房间／难度设置由房主选择全队初始残机 0–5、初始 Bomb 0–3；默认 2 残、3 Bomb，残机不含当前自机。设置修改后全员重新准备，开局固定，Extra 与重开使用相同设置。
- 灵梦、魔理沙、魅魔、幽香自由混选；各席独立移动、射弹、生命、Bomb、Power 和拾取半点余量。
- 分数、点数、梦点、擦弹和结算为团队状态；公共世界每帧更新一次，自机射弹总预算为 288。
- 双人 Boss 有效血量 ×1.5，三人 ×2.2；伤害除数保留余数，击中得分保持原作倍率。
- 小 P 在双人时交替增加 1／2，三人增加 2；大 P 分别增加 15／20。满火力拾取者支援最低火力的存活队友，同火力按距离和席位确定。
- Bomb 道具奖励存活玩家；1UP 与每累计 100 个蓝点奖残作用于全队，并复活幽灵。
- 停火靠近队友，连续点按低速键 5 次，相邻两次间隔最多 24 个游戏帧，可转移一条生命。救活幽灵时，救援者 Bomb 减半，被救者得到一个 Bomb。
- 世界同一时刻运行一个 Bomb 演出，动画、图像与伤害始终绑定释放者。
- 暂停、重开和返回房间由确认输入同步。暂停菜单的触控点选先进入输入队列；等待网络时继续绘制界面以接收短按。
- 通关沿用原生结局、Staff、评价与祝贺流程，再返回房间。挑战模式禁用 Bomb，以死亡次数替代残机显示。

## 同角色配色与图层

同一角色按出现顺序使用原色、替代色一、替代色二，读取审定的 `th05-four-player-colors.zip`：灵梦／魔理沙采用原色、蓝、绿；魅魔／幽香采用原色、暖橙、紫红。三个移动姿态、16 张射击图形、幽灵与侧栏射击标记都使用对应素材；灵梦乌龟、魔理沙扫帚与幽香对比残影保留审定图的颜色。

自机位于弹幕和效果之上，本机最后绘制。队友使用 TH08／TH10 的本地显示透明度曲线：远处上限 128／255，50 像素以内为 51／255，本机保持完整透明度。幽灵固定在各席开局位置；存活玩家靠近后执行救援。显示决策不进入输入或世界校验。

素材来源与 PNG 哈希见 `resources/player-art/source.json`。运行 `python scripts/generate-player-art.py --zip /path/to/th05-four-player-colors.zip` 从审定包生成内置纹理；构建通过 `--check` 验证生成内容。纹理在关卡载入时解码并组成精灵图集，游戏帧内复用。

## 画面与显示配置

侧栏沿用 PR #143 的原生像素字形、分数位置、各席生命／Bomb／Power 资源行、公共点数／擦弹／梦槽及底部 Enemy 血条。两人和三人共用固定的 128 像素侧栏，游戏世界保留 384 像素宽度。

多人启动器的“画面”设置提供原版侧栏、红魔乡式顶部和环形三种血条，以及阶段刻线、剩余阶段星星、时间／轮数、梦槽数值和各席火力数值。偏好经 `th05MultiplayerDisplay` 配置传入，保持在各自的本地显示层；不同玩家选择不同样式也使用相同的世界输入与校验。血条切换自动约束阶段提示和时间显示，游戏内关闭 thprac 辅助入口。

开启“火力以数字显示”时，各席改用两行资源布局：玩家编号与对应配色的射弹标记、`当前火力/128`、原版 P／残机／Bomb 道具图标和数量。P1／P2／P3 编号采用青／黄／绿区分席位，机型标记直接复用该席射弹贴图；关闭后显示原火力槽。

## 时序与输入

启动器的回滚开关在纯回滚和纯延迟之间切换；Runtime 同时支持延迟＋回滚时序。回滚窗口为 8 帧，方向输入最多连续预测 2 帧；相对触控位移只消费一次，绝对触控保留场地目标。纯延迟使用全部确认输入，自动测量与 0–9 帧手动延迟继续可用；混合模式按测量结果预留 1／2 帧预测余量。房间传入的预测上限声明作品能力，纯延迟模式始终禁用预测。

`portable/Netplay.cpp` 使用公共 `RollbackCore` 保存不可变输入，使用 `RollbackJournal` 恢复 `Game/Coop/WorldRollback.cpp` 捕获的关卡、自机、射弹、敌人、激光、Boss、效果、全局统计与独立随机数。每个战斗检查点约 331–343 KiB，最多保留 8 个未确认帧；已确认帧直接执行并退休日志。纠正复用历史输入，不重复读取键盘、手柄或触控。

音效、切曲与音量操作按帧暂存，纠正时作废被替换的未来，连续确认后顺序输出。暂停、对话、Boss 工厂、四面分支和换面经过确认边界；道中 Boss 对象保留到关卡结束，支持恢复到其退场前。每次纠正最多执行 4 帧或约 4 ms，然后将执行权交还浏览器；中间重演不提交画面，暂停 UI 与音频泵继续运行。

检查点在只读捕获区间批量复制，结束捕获后再修改输入和世界；无音频事件的帧不创建输出记录。弹池分别维护点弹／图弹的占用上界，更新与绘制跳过末尾空槽，保留 1,800／2,200 槽容量、分配顺序和消弹生命周期。上界与世界一同回滚，死亡标志清除后才收缩。自机弹循环在入口固定容量，敌弹循环在入口固定演示模式。

多人画面使用单调世界修订号：普通前进和已完成的纠正提交新画面，等待输入时复用最后画面；暂停菜单持续处理短触控。游戏仍以 56 Hz 推进，75／90 Hz 屏幕按新游戏帧呈现，避免额外呈现门限丢失新画面。

每 120 帧交换已纠正、连续确认的游戏状态校验，覆盖随机数、团队与各席资源、敌人、自机射弹、激光及 Boss；超出预测窗口时等待真实输入。

直连／中继传输和双通道输入修复沿用 [PR #143](https://github.com/Ritosa2333/eagler-touhou/pull/143) 的 `managed-transport.mjs` 与 `input-transport.js`，来源提交为 `659e65658d4cd1bcfee1670f4c5cc63d79d2819f`。中继从已认证连接添加席位来源，客户端不能用载荷选择发送者。公网开局固定 Runtime generation；本机 `ws://127.0.0.1` 开发服务可使用源码构建入口。

滑动触控同步目标坐标，在执行帧由原生自机计算实际位移；限速模式继续按机体速度截断。摇杆同步速度。这样排入延迟队列的滑动不会重复补偿过去的位置。

单人保留 `/savesth05` 和原生 `.rpy`；多人使用 `/savesth05mp`。当前多人入口提供玩家席位，观战与多人录像工作区由后续协议接入。旧独立页保留在多人栏的“旧版联机入口”。

## 构建与验证

```powershell
node ports/th05-mp/scripts/build-eagler.mjs
node --test ports/th05-mp/tests/*.test.mjs
$env:TH05_BROWSER_TESTS='1'
node ports/th05-mp/scripts/build-eagler.mjs
node ports/th05-mp/tests/multiplayer-native.mjs
node ports/th05-mp/tests/rollback-native.mjs
node ports/th05-mp/tests/rollback-boundaries.mjs
node ports/th05-mp/tests/rollback-performance.mjs
node ports/th05-mp/tests/multiplayer-browser.mjs
$env:TH05_MP_PLAYERS='3'
$env:TH05_MP_ROUTE='relay'
node ports/th05-mp/tests/multiplayer-browser.mjs
```

单人 `ports/th05` 与多人 `ports/th05-mp` 各自编译、维护和导出历史。`launcher/config/workspace.json`、Runtime 构建配置与 `docs/adaptation/port-sync.json` 登记目录和同步基线；`project-history.py --game th05` 刷新两侧投影与 MP 的普通版上游。
