# 联机同时操作卡顿优化记录

日期：2026-10-15。目标：减少双方射击、移动和变向时的突发停顿，继续使用已接入正式目录的 DOSBox 优化核心。

## 问题与定位

联机有两个不同瓶颈：弱端每步模拟时间决定持续推进能力；快端预测错误后的恢复、重算会造成额外的画面停顿。本次针对后者，不改 CPU 周期或游戏规则。

原局域网策略允许最多领先12步，但方向预测仅持续3步。快端领先超过3步后会预测对方已松开方向；对方实际仍持续按住时，后续输入不断延长有效方向预测并使已执行的预测失效，触发反复回滚。双方频繁变向时，还叠加真实输入变化引起的修正。

真实设备复现：桌面 Edge + Samsung SM-T500 ARM64 Chromium 157，局域网 WebRTC，开启回滚，第一关双方持续射击并频繁变向。旧策略约18秒内，快端回滚309次、重算1258步，而平板没有回滚。

## 采用的改动

仅修改 `web/netplay/room.js` 的输入策略和新一轮模拟前的等待条件：

1. 方向预测统一为6步（此前直接连接3步，中继6步）。
2. 当预测领先达到6步时等待权威输入，收到输入后由原有 `wake()` 继续推进。
3. 保留12步回滚安全窗口和原有检查点存储、恢复逻辑；并未删除历史状态。
4. 保持本地输入延迟参数为0；不主动插入固定6步输入延迟。6步是最大预测领先限制，在60Hz同步时间下约100ms，不是保证的网络延迟。
5. 保留真实输入修正、启动锁步、暂停、离线处理；关闭回滚时不进入新增的预测限速条件。

作用：在快慢端之间限制无效的预测工作，避免快端持续执行即将被推翻的长尾。没有改变模拟核心、弹幕、判定、cycles、声音内容或游戏帧率目标。

代价：网络暂时没有输入时，快端会比原先更早等待；预测的方向也可能维持到6步，再由真实输入纠正。高延迟和高抖动公网尚未充分测试，不能保证这一策略对所有网络都更优。

## 未采用的第一版

仅将领先限制在原有3步：快端回滚降到35次、重算105步，但平板开始出现10次回滚、15步重算，并遇到首次快照分配的长停顿，平板最大画面提交间隔约242ms。该策略把负担转给弱端，因此未采用。

## 首轮实机筛选结果

| 指标 | 原策略 | 3步候选（拒绝） | 6步候选 |
|---|---:|---:|---:|
| 电脑游戏帧/秒 | 26.86 | 25.92 | 26.75 |
| 平板游戏帧/秒 | 27.20 | 25.89 | 26.74 |
| 电脑回滚次数 | 309 | 35 | 29 |
| 电脑重算步数 | 1258 | 105 | 173 |
| 电脑画面间隔P95 | 72.8ms | 50.2ms | 52.0ms |
| 电脑画面间隔P99 | 152.2ms | 92.0ms | 70.5ms |
| 电脑最大画面间隔 | 210.7ms | 197.2ms | 77.4ms |
| 平板回滚次数 | 0 | 10 | 0 |
| 平板画面间隔P99 | 45.4ms | 75.3ms | 45.8ms |

这些是约18秒的真实设备顺序短测，不是严格同检查点性能AB；温度、网络与场景时序会波动。原策略/3步脚本还叠加了旧的单端方向切换，6步起统一为双方每秒变向，因此输入序列并非逐帧相同，不能将表中差值作为精确提升比例。最终另做6步复测。

画面间隔来自最近512次 WebGL 提交，不是物理屏幕刷新测量；平均帧率仍由平板核心计算限制。本轮不宣称提高了弱端平均帧率。

### 最终复测（完整通过）

清理脚本修正后，使用同一6步策略再测约17.8秒：电脑27.01帧、平板26.99帧；电脑回滚29次、重算172步，画面间隔P95为57.0ms、P99为76.9ms、最大90.7ms。平板零回滚、零重算，画面间隔P99为45.7ms。共同确认校验一致，脚本正常结束，无页面错误。结果支持减少快端的长停顿，但未证明提高低端设备平均帧率。

## 验证

- `tools/test_prediction_pacing.cjs`：直接提取生产 `nextInputs()`，覆盖双/三人、3/6步边界、迟到输入导致的重放、权威输入恢复，以及关闭回滚连续推进。
- `tools/test_dosbox_rooms.cjs`：双/三人 WebRTC，注入65ms输入延迟，验证实际回滚、共同确认哈希、暂停恢复、三人离线继续和故障信息导出；均通过。
- 真实局域网候选测量期间共同确认帧校验一致。
- 首轮6步测试在测量完成、状态校验通过后，自动清理房间时发生重复断开导致的“房间不存在”错误。已修正测试脚本为客机先停止、房主后停止，不再重复点击退出。该轮记录保留错误，不能写成整轮无异常通过；最终复测另存。
- 已更新 `web/netplay/runtime.json` 的 `room_sha256`，让不同调度版本不能混用资源身份。
