# TH04 网页单人练习工具

更新：2026-10-24。当前实现为 `th04-browser-practice/1`，按 TH02／TH04 交接约定（原工作区本地文件 `../TH02-04-PRACTICE-PORTING.md`） 接入本作 DOSBox-X 单人入口。本文记录本作实现和实际验证范围；TH05 的验收结果不作为本作证据。

## 使用

运行本目录的 `start-solo.bat`，使用新版 Chrome／Edge。更新后重启服务器并刷新旧页面。中日文、主线程和 Worker 共用入口，均需要 WebAssembly JSPI。

- 默认开始仍是原版标题、选人和完整流程。辅助默认关闭，完整流程保留原版资源与死亡规则。
- `F12` 或“特定练习”按钮打开目标面板，选择角色、难度、关卡、道中／关底 Boss 和攻击后确认开始。到达后进入原版暂停，用 Z／Enter／Esc 恢复。
- `Backspace` 展开右侧紧凑辅助菜单。只有此菜单展开时，F1–F5、U、Shift+D／A／S、Shift+F 才响应；收起后已开启的辅助继续生效。F12 面板通过鼠标控件修改选项。
- `Tab` 开关右上角统计。高级设置包括速度、锁 Rank、强制低速、判定点和按键显示。

| 操作 | 行为 |
| --- | --- |
| F1 | 原生碰撞消除命中弹后消费受击，Miss +1，不进入死亡，也不增加无敌时间 |
| F2 | 保留原生死亡、掉火力、掉道具与复活，只绕过最终扣命／Game Over |
| F3 | 零库存也能发动原生 Bomb，绕过库存门槛与消耗；统计实际发动次数 |
| F4 | 开启时锁住当时火力，关闭后恢复原生增长与损失；默认关闭 |
| F5 | 限制实际阶段计时或循环耗尽，攻击继续，HP 击破仍可结束 |
| U | 共享射击命中例程仍消耗射弹，但不返回伤害；包含激光和 Bomb 伤害 |
| Shift+D／A／S | 分别禁用 Bomb、低速、射击 |
| Shift+F | 重试已确认的特定练习，保留当前辅助；完整流程无定点重试 |

特定练习固定 **0 备用残机、0 Bomb、初始梦 0**，保留当前这一命。初始火力范围为本作的 1–128；F4 不会因初始火力设置而自动开启。到达目标时重置梦道具收集数及梦分数，开始后正常拾取增长。Tab 同时显示当前梦分数。Rank 按难度限制为 Easy 4–16、Normal 11–24、Hard 20–32、Lunatic 22–34、Extra 16–20。

初始火力和 F4 恢复火力时调用原生 `sub_11DE6`，同时重算射击等级、当前角色的射击函数及原生火力 HUD。此前只写火力字节会导致面板数值变化但弹型仍保持旧等级，现已修正。梦与 Rank 是两个独立状态，不用 Rank 代替梦。

Boss 自定义 HP 的 0 表示原生值；其他值限制在当前攻击有效范围内，不会跨过本段击破阈值。攻击名称同时显示内部阶段号，避免把过渡演出当成独立攻击。

## 目标与结果

开放一至六面及 Extra 的关卡开头、关底 Boss；一至四面开放实际有 HP 的道中 Boss。四面按角色进入魔理沙／灵梦分支；Extra 可选择梦月至幻月全战或幻月入口。Extra 道中的脚本敌人不作为可选 HP Boss。

阶段选择来自本作状态机：有些 Boss 的多种出弹共享同一个内部阶段，并不拆成虚构的阶段。具体列表位于 `web/practice-config.js`。

准备过程保留原生 STD、对话中的素材／音乐／调色板加载，跳过无关道中与文字等待。对话解析保留外层和文本框的两层 STOP 语义，并按原版两字节处理文本，避免把 Shift-JIS 尾字节误认成命令。到达后清除准备期受击、死亡、不可操作与无敌计时，再进入原版暂停。

Boss／道中 Boss 定点在原生换段后、聚气发射器和前景渲染之前，一次性清除准备期普通弹、激光、聚气发射器、自定义投射物、掉落道具及圆形效果，并取消旧消弹倒计时。当前页立即重画，后续两帧使背景全页失效，清除双缓冲残影。恢复后不再清弹，目标攻击继续正常生成弹幕。四面魔理沙的四个使魔保留；原生发弹模板、阶段状态和幻月发射柱坐标不改写。幽香安全圈由阶段 4 内部正常生成，入场时的旧圈一并清除。

未开保命辅助时，特定练习中弹即失败；完成选定攻击／Boss／关卡即成功。同帧受击和击破优先失败。Extra 整战跨过梦月至幻月交接后才算完成。结果冻结本次尝试，等待手动保存 REP、重试或另选目标。

结果菜单竖向排列，↑／↓ 循环、Z／Enter 确认；X／Esc 选回重试。录像异步封存不会改变当前选择。修改尚未提交的 F12 表单，不会改变“重试当前练习”的起点。

## 预载快速重试

F12 高级设置默认启用“预备快速重试（额外内存）”。当前特定练习入口就绪后，后台只预备下一次尝试；菜单出现“下次重试已就绪”即可用 Shift+F 或结果菜单直接切换。切换仍停在原版入口暂停，需要按 Enter／Esc 继续。目标始终使用上次提交的配置，保留当前辅助和速度，清除上一局按键与触控。

预载会独立启动同一练习目标，完成原生换段、准备期清弹和入口暂停，再在正常宿主 sleep 边界挂起 JSPI，并冻结练习时钟。停放期间不会推进弹幕、增加录像时钟或累计练习时间。切换后才记录并应用当前辅助选项；每次尝试保留自己的启动记录、音乐桥与 REP，可在新页面独立回放。它是轮换独立实例，不是即时存档，也不保证每次启动的随机种子相同。

若重试时尚在预备，会等待该实例；预备失败则回退到正常重新加载。重新提交目标、改变语言／声音／录制／线程模式、返回完整流程、关闭预载或离开页面都会释放旧预备实例。每次切换后再预备一个后继；普通完整流程不预载。

代价是预备期间增加 CPU 使用，并额外保留一个模拟器。当前样本约增加 92 MiB Wasm 内存，另有磁盘、音频和录像缓冲；内存紧张时可在 F12 取消此选项。首次进入和尚未就绪的远期目标仍需正常准备。

## 音乐与 REP

独立 BGM 在普通单人、特定练习、录制开启／关闭以及 REP 播放中使用相同音乐桥。速度 25%–200% 改变模拟推进，独立曲目的播放速率保持 1，切速不重启当前曲目。准备、原版暂停与结果界面静音。若选择模拟器原声，音乐与模拟时钟一起变化；要保持音乐速度请选独立 BGM。

REP 保存初始练习配置、私有磁盘差异、音乐模式及后续辅助／速度事件。每次定点尝试新建一份录像，成功或失败在确定的宿主边界封存。播放安装同一音乐桥，以只读观察转发换曲事件。资源身份包含实际音乐驱动、练习覆盖程序和核心；更新代码后的旧身份录像不能跳过校验强行播放。

## 实现与构建保护

原生入口在 `patches/practice.asm`，使用同步 dword OUT `0x7fe0`–`0x7fe5` 对应加载、帧开始、玩家前／后、世界更新结束、Boss 更新后。最后一个入口位于原生 `call far [0xbcd0]` 后、道具／聚气更新和渲染前，因此不会等到下一帧才清理旧发射器。JS 只在这些原生回调写客体状态；浏览器 rAF 负责界面与输入，不负责补写 HP 或判断击破。

F2／F3 接入原生扣命与 Bomb 分支，零库存也在原生 HUD 重绘入口夹紧；F1 在碰撞之后、死亡处理之前消费受击。F5 使用本作实际帧、循环计数和道中滚动条件，不读取 HUD 的预测倒计时。最终生存攻击进入时保留原生前段 HP，不凭空设定健康值。

`tools/build_practice_assets.py` 从哈希锁定的中日文单人 HUD MAIN 派生独立覆盖，校验 Hook 原字节并更新 MZ 重定位。生成 `web/practice-*.exe.gz`、启动器与描述清单。`tools/build_practice_core.mjs` 从锁定的 fast 核心派生 `wdosbox-x-practice.wasm`，只增加上述 OUT 回调。

普通单人和定点都加载这套私有覆盖；单人使用固定 16000 CPU cycles。多人仍走原有核心／配置。构建不写发布 HDI，也不更新原生 HUD baseline。启动时只修改内存中的 FAT 副本。

完整开发工作区中的构建／检查命令：

```powershell
python tools/build_practice_assets.py
node tools/build_practice_core.mjs
python tools/test_practice_guest.py
node tools/test_practice_engine.mjs
node tools/test_external_replay.mjs
node tools/test_solo_test_commands.mjs
python ../tools/verify_native_boss_hud_release.py
```

构建依赖本地已审计的源盘、根目录原生 HUD 工具、NASM、Capstone 和 Binaryen；原生 Hook 执行检查还使用 Unicorn。浏览器检查使用本机 Playwright／Edge，不要求玩家安装这些开发依赖。

## 验证范围与限制

原生执行检查通过 **204 项中日文检查**：实际 MZ 重定位、寄存器／标志／栈、原版暂停、库存、F2／F3、伤害返回、对话分段与资源命令，以及 13 个火力取值在帧开始、玩家前后、世界结束、Boss 后五个入口的真实射击等级／函数更新和 HUD 调用。新增入口还核对原生 Boss → 到达回调 → 背景重画的顺序，以及完整流程不触发到达回调。**40 项引擎检查**覆盖完整流程隔离、受击统计、同帧失败优先、原生超时、最终生存段 HP、Boss 独立范围、程序退出错误、时钟及定点梦归零／恢复自然增长；清弹回归逐槽核对各池、使魔保留、旧安全圈移除、模板／HP 不变、两页重绘和目标新弹不被持续清除。

本机浏览器报告保存在 `reports/practice-*.json`，由 `tools/test_practice_browser.cjs` 生成；报告含运行方式、语言、配置、入场状态、音乐、截图及录放终态。部分早期报告对应修复前身份，应结合时间和当前资源哈希阅读。

清弹修复的真实入场检查覆盖一面阶段 3、胡桃阶段 5、四面魔理沙／灵梦阶段 11、五面阶段 17、六面阶段 4／16、Extra 幻月阶段 7，以及一面道中（锁时辅助开启）。一面阶段 3 实际清除了 48 发旧弹；五面阶段 17 清除了 107 发旧弹和 1 条激光。各入口暂停时所有应清池为空，恢复后目标自身出弹；另观察到魔理沙四个使魔及幽香阶段 4 安全圈正常生成。报告的 `resources.hazards`、`resources.cleanup` 和 `attackResources` 分别记录入场存活槽、实际清除数量与恢复后的生成状态。上述出弹观察开启无敌、敌方无敌和锁时，不作为自然通关证据。

清弹修复最终身份还通过两组新页面 REP 重放及重试：日文主线程一面阶段 3 成功（`practice-main-jp-0-boss-3-0-auto-rep-clear-retry-power32.json`）、汉化 Worker 五面阶段 17 失败（`practice-worker-cn-4-boss-17-0-auto-rep-failed-retry-power32.json`）。两组终态客体内存 SHA 一致。录放检查不注入弹幕或道具。

已覆盖代表性关头、前四面道中、四面角色分支、三面 Elly、五／六面幽香及 Extra 姐妹入口；实际碰撞、F2 死亡复活与火力损失、零库存 Bomb、U 伤害屏蔽有实机检查。录放检查使用实际游玩输入和新页面重启，比对整个 WASM 客体内存 SHA；单元测试或注入状态检查不作为自然通关证据。
