## 启动

需要 Python 3 和最新 Chrome / Edge。单机、本地合作需要浏览器支持 WebAssembly JSPI。请运行启动器，通过 HTTP 打开网页。

| 模式 | 启动器 | 地址／端口 |
| --- | --- | --- |
| 原版单机 | `start-solo.bat` | `http://127.0.0.1:9867/solo.html` |
| 本地双人合作 | `start.bat` | `http://127.0.0.1:9867/local.html` |
| 两／三人局域网 | `start-lan.bat` | 9868，伙伴使用窗口显示的局域网地址 |
| 公网联机 | 部署 `lan_server.py` 或 `start-public-tunnel.bat` | 保留原房间、WebRTC 和 WebSocket 接口 |

9867 被占用时本地服务器会寻找后续可用端口，以启动窗口显示的网址为准。手机访问使用局域网服务器。WebSocket 转发模式先运行一次 `install-relay.bat`；临时公网隧道还需要安装 `cloudflared`，并保持局域网服务和隧道窗口同时运行。

详细加入方法见 [局域网试玩说明](LAN-试玩说明.md)，公网／转发部署见 [Relay 说明](README-RELAY.md)。

保留汉化／日文选择、原版单机开头及菜单、本地双人、两／三人房间、回滚开关、团队分数 HUD、独立资源、幽灵和救援、声音模式、手柄、自定义按键与触屏设置。合作模式的分数、点、梦、擦弹及其结算计数由全队共用，得分固定采用原版倍率；达到分数 Extend 阈值时，全队按 1UP 规则加命并复活幽灵。随附中／日文单机和合作四张游戏盘；多人 HUD 的 Power 使用原版小 P 图标，1UP、Bomb 和拾取规则保持原有实现。

默认 P1：方向键、Z 射击、X Bomb、Shift 低速；本地 P2：WASD、J 射击、L Bomb、K 低速。Esc／P 暂停，屏幕按钮亦可操作。键位和触屏布局通过“按键与触控”保存。

触屏保留单指拖动、第二指低速、开火切换、Bomb、双击 Bomb、限速／不限速、灵敏度、判定点、横竖屏独立布局及沉浸显示。独立单机保留跳关与无敌测试工具；单机、本地合作和联机都有“下载故障信息”。

网络使用 `th04-rollback/3` 输入同步协议。房主配置本局设置；各端落座、选机体、准备后开局。回滚由房主在开始前选择。开局会校验各端游戏盘、引擎和适配模块版本，所有玩家须使用同一版资源；DOSBox-X 版与 NP21 备份版不能混用。

磁盘导入／导出接口保留，运行时文件变更写回私有 FAT12 镜像；刷新或重启恢复初始资源。

多人美术按同一角色的重复次数自动分配：按 P1→P2→P3 顺序，该角色第一次出现保留原色，第二次使用蓝色，第三次使用绿色；灵梦和魔理沙分别计数，A/B 射击类型不影响配色。不同角色各自第一次出现都用原色。幽灵沿用相同分配，救援、换关和离线后不重新排色；玄爷、扫把、肤色、头发与透明区域保留原样。自机和幽灵配饰使用原作调色板中的蓝／绿渐层，幽灵其余颜色匹配当前关卡调色板。场内主弹、辅弹、命中特效和魔理沙激光按发射者及弹种使用独立色系，保留白色高光、暗色轮廓、弹形与动画。右侧机型图标使用灵梦符札／魔理沙星弹，并同步配色，旁边保留 A/B 标记。Bomb 保留原素材。此规则适用于中／日文本地双人与两／三人联机。

前轮分色优化采用相同游戏盘和输入，交替推进新旧核心各 3840 同步步；每批游戏状态以及结束时完整内存、原生回滚全局量一致。排除前 960 步预热后，三人第五关测试的整段耗时差约 0.03%，不构成可确认的帧率提升。独立 WASM 测量中，常态颜色转换与空标签清除约减少 45% 耗时，全 mask 激光标签约减少 68%；这些是局部微基准。普通 16×16 射弹标签没有测到稳定收益。原作 Slow 会按敌弹密度主动降低游戏推进速度，关闭回滚也会保留该行为。完整验证记录保存在本机 `reports/projectile-performance-2026-10-17.md`。

前轮68格修复曾测得隔离射击开销的三人原生指令减少约15%～26%，不属于本次204格扩容的性能数据。扩容会增加可同时存在的射弹及相应判定、绘制工作，当前不承诺低端设备60帧；完整内存恢复重放及三人房间共同确认状态已验证。详细记录在本机 `reports/full-fire-stability-2026-10-17.md`。

2026-10-16 加载优化：本地／局域网启动器对 WASM 和网页脚本启用 gzip，压缩结果在服务进程中复用；静态资源每次访问先校验版本，未变化时复用浏览器缓存。房间接口继续禁用缓存。单机、本地双人的磁盘与配置并行下载，独立音乐的曲库与解码改为游戏启动后按需加载。三种实际核心文件的离线压缩体积由 7.9／19.4／20.7 MB 降至 2.9／6.2／6.2 MB，约减少 63%～70% 传输量；这不是启动耗时实测。该轮只做构建摘要更新和静态检查，未启动浏览器／游戏或执行测试。重启服务并刷新页面后生效。

慢设备启动使用临时 `FASTBOOT.BAT`，以较低固定算力完成 BIOS／驱动等待，再在游戏入口前恢复正常配置；联机游戏阶段为 30000 cycles。启动过程中持续让出浏览器任务并更新进度，房间 HTTP 临时失败不会在 5 秒后直接停止仍有活动玩家通道的游戏。2026-10-13 同设置短测，桌面独立运行时启动约 15.2→6.8 秒，USB 平板约 256.5→136.0 秒；不同设备和加载范围的结果不能直接互比。

单机、本地合作使用 DOSBox-X Simple CPU 和自动 cycles，启动页不再显示标准／增强算力选择；游戏时钟保持原版。每次核心提交完整 RGB 画面后直接上传复用纹理并绘制，移除上游额外的刷新回调等待。本地合作可选独立浏览器音乐，减少 FM 音源在模拟线程中的工作；原声仍可保留。联机使用固定 30000 cycles 和虚拟时间；每批推进或回滚追赶完成后，先绘制最新底图，再在同一任务中合成个人 HUD，只向可见画布提交一次。60 Hz 输入／网络调度与游戏步数、WebGL 绘制次数、物理屏幕刷新均为不同指标。

2026-10-13 USB 三星 SM-T500（Chromium 157、Android 12）短测，后台 Worker 单机约 39.8 游戏帧／秒，本地双人持续射击约 31.9。50 帧目标尚未达到，瓶颈仍是 DOSBox-X Simple CPU 的解释执行，不能把 WebGL 绘制次数当作游戏帧率。联机回滚在该设备上更重；这些数字不代表完整通关或所有设备、弹幕场景的表现。

页面记录仅在开启回滚且浏览器支持 WebAssembly 多内存时启用。原生动态写入、批量复制／填充、浏览器包装器的内存写入及游戏输入均受覆盖，固定地址写入的页面保守扫描；恢复窗口、内存／文件／执行栈恢复和确认后音频提交保持原有规则。页面记录本身有执行开销，所以关闭回滚时不启用。旧浏览器继续使用原核心与完整复制回退。此轮未消除 Simple CPU 解释执行及完整 Asyncify 的开销，尚未重新连接手机／平板验证，不能宣称已解决慢设备低于 30 帧的问题。

## 重建

运行资源随本目录提供，普通游玩不需要 Node.js、NASM 或 Binaryen。以下命令仅用于保留开发文件的本地工作区，固定 npm 来源在 `vendor-source/emulators-8.5.2/`。

合作侧栏以原生整数显示火力，例如 `P 72/128`。上限保持 128 P，双人／三人拾取收益仍为原版的 1.5／2 倍；双人小 P 交替增加 1／2 点，各席位独立保留半点余量，大 P 分别增加 15／20 点。P 值固定占三格，右侧残机与 Bomb 上下对齐。

修改合作原生补丁后，依次运行 `python tools/build_lab.py --keep-vendor` 和 `python tools/build_lockstep_runtime.py`；后一步先刷新中／日文磁盘声音策略，再重建引擎包装器和版本摘要。只改运行时适配 JS 时也需更新摘要。

仅修改游戏盘或多人美术时，第二步使用 `python tools/build_lockstep_runtime.py --game-only`，更新磁盘声音元数据并保留当前优化核心。美术构建读取同级 `ghost-preview/th05-four-player-colors/` 中已审核的灵梦／魔理沙幽灵 PNG，生成文件和来源哈希保存在本机 `build/`、`reports/player-art.json`；原生配色回归运行 `python -B tools/test_player_art_cpu.py`，右侧机型图标回归运行 `python -B tools/test_hud_shot_art_cpu.py`，实际射弹／激光回归运行 `python -B tools/test_projectile_art_cpu.py`。

重建射弹分色核心使用 `python -B tools/build_projectile_runtime.py`，从本机固定的 `build/projectile-baseline/` 生成 fast／rollback／tracked 三核并更新版本摘要；该入口已接入本目录的 `projectile-perf.wat` 与 helper 优化。`build_projectile_performance.py` 是同一流程的兼容入口。不要直接用旧 TH05 构建器覆盖 TH04 分色优化。

完整回滚插桩需要 Binaryen 132，执行 `tools/build_asyncify.ps1 -WasmOpt <wasm-opt.exe路径>`；已有插桩中间文件时，`node tools/build_dosbox_runtime.cjs` 可重建包装器及摘要。编译工具和中间文件放在 `build/`，不使用上游不完整的 Asyncify PC-98 构建。迁移／小 P 完整性审计以本机 `../th04-np21/web/` 为原版对照；该备份仅用于开发审计。
