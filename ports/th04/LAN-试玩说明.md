# 局域网双人／三人试玩：输入同步版

**当前协议为 `th04-rollback/3`。** 房主可在开局前选择是否启用回滚，客机自动跟随；修改后全员重新准备，开局后锁定。主机掉线超时后结束本局；客机确认离线后其余玩家可继续，暂不支持重连。启动器直接运行随附资源，无需构建工具。更新后需重启服务、全员刷新并重建房间。本段优先于下方历史说明。

两台或三台电脑的浏览器分别运行 DOSBox-X 和 TH04，网络只传操作及同步消息，不传游戏画面或声音。各玩家通过可靠有序通道两两直连。客机打开页面会自动加载资源，不用安装软件或手动复制游戏文件。

RTT 包括浏览器调度时间，不等于纯 Wi-Fi 延迟。回滚不能消除模拟器执行成本；请结合推进速率、执行耗时、预测领先和重算步数判断实际体验。

当前主目录已采用 DOSBox-X。已完成本机多浏览器两／三人 WebSocket 回滚、日文两人 WebRTC 锁步，以及 USB 平板与桌面的 WebSocket 启动短测；这些结果不代表异地公网或全部弹幕场景的稳定性。引擎和版本状态见 [README](README.md)。

## 启动和加入

1. A 关闭旧的启动窗口，再双击 start-lan.bat。新版本使用 **9868** 端口，保持窗口开着。
2. A 打开 **http://localhost:9868/lan.html**，点击“创建房间”。
3. B 与 A 在同一个 Wi-Fi，打开 **http://A的局域网IP:9868/lan.html**，输入房间码并加入。A 的启动窗口会列出候选 IP；选择 Wi-Fi 网卡地址。
4. 房主选择人数：默认“双人（关闭 3P）”；需要三人时先选“三人（启用 3P）”，第三台电脑再用同一网址和房间码加入。每人选择开放的 P1 / P2 / P3，不可重复，房主可选任意座位。
5. 各玩家选择自己的机体；房主设置难度、生命、炸弹和回滚开关。所有人点击“准备”，房主再点“房主开始游戏”。三人模式必须三人全员加入并准备。修改设置会取消所有人的准备。
6. 等两边自动加载完游戏后共同启动。进入游戏后才后台加载浏览器音乐，游戏不等待音乐下载。双方各点下方“启用本机声音”，再点击游戏画面操作。

如果只输入主机 IP 和端口，新服务的根地址也会直接显示房间页。首页为 index.html；单机游戏使用 start-solo.bat，本地双人使用 start.bat。

## 操作

双方都可以用各自键盘或标准手柄，控制自己所选的座位：

- 键盘：方向键移动、Z 射击、X 炸弹、Shift 低速、Esc 暂停。
- 手柄：左摇杆 / 十字键移动、A / × 射击、B / ○ 炸弹、RB / R1 低速、Start / Options 暂停。连接后先按一下按钮；自动使用本机第一个标准映射手柄，不再固定给 P2。
- 暂停会冻结双方游戏；双方均可继续。房主可用上下选择、Z / Enter / A 确认，也可点击菜单按钮。客机只有“继续游戏”，不能选择退出；客机确认始终表示继续，不受房主选中项影响。房主选 P2 时权限不变。
- 房主在暂停菜单选退出，直接关闭双方当前游戏画面并停止音乐，不返回原版主菜单。浏览器房间页显示本局已关闭；需要重开时再点“结束并返回”。
- 原版对话、Game Over / Continue 菜单仍由 P1 使用 Enter、Z 和方向键操作。

手柄需要浏览器安全上下文。房主使用 `localhost` 通常可直接使用；客机通过普通 `http://局域网IP:9868` 访问时，新版 Chrome / Edge 会限制 Gamepad API。仅为自己的可信局域网试玩，可以在 Chrome 的 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`（Edge 对应 `edge://flags/#unsafely-treat-insecure-origin-as-secure`）中添加**准确的房主来源**，例如 `http://192.168.1.5:9868`，启用并重启浏览器；不添加其他网站，试玩结束可移除。也可以使用已配置可信证书的 HTTPS 入口。此项目默认服务器仍为 HTTP，不自动修改浏览器设置。页面诊断会显示手柄权限或连接状态；键盘无需这项设置。

救起幽灵时，复活者 Bomb 设为 1，施救者扣当前 Bomb 一半（扣除数向上取整，0 Bomb 也允许救）；给活着的队友命不扣 Bomb。过关复活也将 Bomb 设为 1，不扣队友资源。

P3 与 P2 规则相同，拥有独立机体、资源和键盘／手柄输入。所有客机的暂停菜单都只能继续。三人救援选择原范围内最近的有效队友，切换目标会清空连按进度。停火靠近队友，低速键连按 5 次，每两次最多间隔 24 个游戏帧；HUD 显示按键数与五格进度。给命和救活幽灵的资源惩罚保持原规则。只有全员退场才进入 Game Over。

Boss 每个可扣血阶段的有效耐久，双人为原版 ×1.5，三人为 ×2.2；按开局人数固定，玩家变幽灵不会降低倍率。原版血条比例与阶段计时保留，内部通过带余数的伤害比例结算实现。

## 请你手动检查

- 两边都进入同一关，双方看到相同角色位置、弹幕、资源变化。
- P1/P2 移动、射击、炸弹互不串位；房主选 P2 时也正确。
- 两边各自有声音，操作手感可接受。
- 观察“最近相同状态步”是否不断增加。同步步是网络的虚拟时钟步，和下面 TH04 的“游戏帧”不是同一个计数。
- 切换窗口后不粘键；隐藏其中一页后另一端等待，返回后能继续。
- 过关、暂停、继续后仍保持一致。
- 房主分别选 P1 / P2，确认客机 Esc / Start 能暂停且只能继续；房主退出后双方游戏画面和声音关闭。
- 分别用键盘、手柄及交替输入，检查移动、射击、Bomb、低速与暂停没有串位或粘键。
- 救人者有 0 / 1 / 2 / 3 Bomb 时，救人成功后分别剩 0 / 0 / 1 / 1；复活者均为 1。给活人命时库存不变，过关复活者也是 1。
- 幽灵附近的普通弹、Boss 自定义弹和激光是否显示在幽灵上方。

若出现“状态不一致”，本局会停止并显示同步步和两个摘要。请把**两边的诊断文字**反馈给我；若卡住，把页面提示和卡在哪一步告诉我即可。

## 当前边界

当前运行随附中／日文合作盘。DOSBox-X 使用实例私有的 `FASTBOOT.BAT` 加速 BIOS／驱动等待，在 MAIN／OP 入口恢复正常算力；原盘的 GAME.BAT 保留，临时脚本不写回导出磁盘。只在私有副本应用经版本校验的声音配置和 MAIN 音乐通知补丁；各端比对相同补丁策略后开局。

慢设备的模拟启动可能明显长于资源下载。进度按启动阶段展示；若黑屏、紫屏或运行停止，请在重启前点击“下载故障信息”，保留截图及两端的“启动进度”“本机同步步”“游戏帧”。STOP 警告也可能来自原生无效指令异常，目前偶发反馈尚未自然复现。

游戏内 BGM=0、SE=1，并同步更新 MIKO.CFG 的第 9 字节校验和。之前漏改校验和，导致 ZUN -S 判配置无效后重建默认值并重新打开 BGM；现已修正。浏览器在检测到实际游戏帧后才导入音乐模块、按需下载 Opus，由音频设备连续循环播放。当前 MAIN 的播放/停止/淡出事件和曲名驱动浏览器切曲。页面显示读取到的实际 BGM/SE 值与播放曲名。

更新后请所有玩家关闭旧游戏页，房主重启服务，Ctrl+F5 刷新并重新建房。音乐音量拉到 0 后应只剩游戏音效，再调高恢复音乐；声音需要各端在页面中主动启用。

- 启动及暂停阶段等待真实输入；进入正常游戏后，仅在房主开启回滚且满足运行条件时允许预测。最多领先已确认输入 12 步；达到窗口上限会等待。DOSBox-X 完整回滚窗口在桌面短测约 117～118 MiB，并有额外重算成本。
- 各端尽量保持页面可见。房间 HTTP 临时请求失败会重试，玩家通道掉线另由离线检测处理；状态不一致或房主离线仍会停止本局。
- 此版没有中途换人、自动重连、房主迁移或 P4。客机确认离线后其余玩家可继续；重开时退出旧局并重新建房。
- 服务器需要 A 的 Python；B 只需要新版 Chrome 或 Edge。
- 慢设备可能因模拟执行成本而卡顿；三星 SM-T500 的 50 游戏帧／秒目标尚未达到，回滚无法消除该计算压力。

## 打不开或连不上

出现整局变慢或声音断续时，请在游玩几秒后复制两边的诊断文字：网络往返、本机/对方步速、执行耗时、等输入比例，以及画面下方的音频缺块计数。目标是每秒 60 个同步步；这不是原版 TH04 的硬件刷新率。网络往返只是数据通道往返，不等于按键到显示的总延迟。若步速低且执行耗时高，优先排查模拟器计算压力；若计算快但等待比例高，优先排查链路和两端调度。缺块计数可能在启动或隐藏页面时增长，需要结合运行中的增长趋势判断。

- 确认网址端口是 **9868**，不是旧版的 9865。
- B 连网页都打不开：检查 A 的服务窗口、Wi-Fi IP、Windows 防火墙。如果弹出 Python 网络访问提示，在家庭/专用网络允许；不需要关闭整个防火墙。
- 房间能加入但 WebRTC 连接失败：检查访客 Wi-Fi / 设备隔离；可退出本局，所有玩家改用页面的 WebSocket 入口重新建房。公网 STUN／TURN 配置见 README-RELAY.md。
- 没声音：在各自游戏下方点击“启用本机声音”，检查标签页是否静音。
- 端口已占用：关闭之前的 LAN 服务窗口后重启；不需要关闭其他应用。

## 文件和交接

- lan_server.py：静态网页、房间、选座、准备、开局和 WebRTC 信令；WebSocket 入口由 relay_server.py 处理，使用 requirements-relay.txt 的依赖。
- web/lan.html、web/lan.js、web/netplay/room.js：房间页面和会话流程。
- web/netplay/rollback-queue.js：确认输入、预测及回滚队列。
- web/netplay/runtime.js：两端各自的游戏加载、P1/P2 输入适配和内存诊断。
- web/dosbox-adapter.js、web/dosbox-snapshots.js、web/dosbox-memory-diff.js：固定虚拟时间、原生执行栈与文件／内存恢复。
- web/netplay/local-bgm.js、web/bgm/：游戏帧开始后启用的独立音乐播放及 45 首/版本 Opus 曲目。

公网平台还需要部署 HTTPS、账号/房间管理及 ICE/TURN，并做公网链路验证。局域网服务不直接作为公网生产服务。

游戏语言可在房间“本局设置”选择汉化版或日文版，仅房主可修改，全员自动跟随；切换后需全员重新准备。两版均保留合作魔改，回滚以房主当前设置为准。
