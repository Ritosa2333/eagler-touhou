# 开发与兼容说明

GameState 统一持有游戏、菜单、录像和资源状态，CombinedGameHost 负责启动与逐帧调度。WindowsHost 实现平台调用、资源句柄、文件读写、键盘手柄和窗口。数值核心保持既有精度和随机数规则。

桌面默认采用原程序进入菜单后实测的 24 位有效数精度，对应原 x87 控制字 0x007f。显示运算同样在每次运算后按该精度舍入，正弦和余弦复用现有数值实现。

显示计算按背景、自机、弹幕、实体、对话和特效分组。当前显示层由原显示控制流展开成 C++，在当前帧的状态快照上生成绘制调用；持久状态仍由经过录像对照的核心推进，避免重复更新动画字段和随机数。显示浮点计算与平台绘图独立于游戏数值核心。该兼容层可在后续按功能逐步整理，构建和运行均无需原 EXE 或逆向工具。

Windows 后台将原参数位型转换为 DxLib 调用，分别处理浮点坐标、双精度缩放角度、字体、三维顶点和文字格式参数。绘图固定在 640×480 逻辑画布上，再按 4:3 比例缩放到设置的输出尺寸；图像旋转与缩放使用双线性过滤。弹图保持原加载方式，关闭透明色预处理，以兼容原有叠加绘制。WMV 使用 DirectShow 路径。窗口关闭由游戏接管，离开主循环后统一释放文件、声音、图形和 DxLib，防止库提前销毁窗口后重复清理。

Windows 适配层按原程序补齐显示快照中的三张只读索引表，分别控制弹型、机体武器和 bomb 的显示分支。表共 79 字节，来自两版原 EXE 中一致的数据，保存在 platform/windows/LegacyDisplayData.hpp；已生成的显示函数及数值核心保持原字节。后续浏览器适配也需要载入这些索引。

原版在部分混合绘制中仍使用图片本身的透明度，即使调用中的透明开关为 FALSE。WindowsHost 对带原生透明通道或独立 _a 遮罩的资源，在透明、加算和减算混合时保留该行为；普通不透明图像沿用调用参数。纹理加载、分图和删除同时维护透明信息，原始资源文件保持原样。

Windows 绘图使用与原作一致的 Direct3D 9 后端。当前运行环境下，新库默认后端会使游戏中的加算圆形重复叠加亮度；使用 Direct3D 9 后，早苗 B 的 bomb 恢复原作的混合结果。逻辑画布、双线性缩放和无边框全屏继续使用。

DisplaySettings 读取和保存原五位 config.txt，依次表示显示模式、窗口尺寸、输出分辨率、颜色位深和绘图方式。独立 thkkd-config.exe 和 thkkd.exe --settings 共用配置窗口；F11 与 Alt+Enter 在运行中切换并保存显示模式。全屏使用无边框桌面模式，保持系统分辨率和刷新率，切换时保留资源句柄。

录像保留原 .rpy 二进制格式。原扫描循环显示 13 个槽位，却尝试读取第 14 个文件名；该空指针在文件平台边界按 Win32 语义返回打开失败。原无效 VirtualFree 参数也保留失败行为。异常字段访问继续经过有界状态视图。Omniverse 对照样本中的 Matchless 设置只属于对应测试输入，普通游戏默认正常受击。

日常修改先运行 `tools/build.ps1`，再检查受影响的菜单或游戏流程。数学、随机数、状态布局和调度变化时，使用工程之外的精简采样档案进行相关回归。Windows 后台和显示接入的调整可直接使用桌面入口验证。

自动运行可使用 `--frames N --mute --secondary --userdata 路径 --screenshot 路径`，按指定帧数结束并保存末帧画面；`--keys 帧号:键码,...` 提供固定输入，`--fast` 跳过限速等待。正常双击运行沿用约 60 帧限速。运行错误写入 userdata/thkkd.log。

`--close-frame N` 在指定帧发送窗口关闭消息，`--toggle-frame N` 在指定帧切换全屏，可重复指定；`--fullscreen` 与 `--windowed` 临时覆盖启动显示模式。显示回归同时检查运行日志和实际画面。

`--capture-frame N` 可重复指定，在 `--screenshot screen.png` 旁生成 screen-N.png，便于对照同一录像的多个时刻。`--trace` 记录加载资源和这些帧的绘制参数；缩放为零的空绘制单独标记为 draw_empty。

tools/release.py 保留文件原字节、图片和音视频的原有信息以及文件修改时间。ZIP 使用相对路径；源码包包含完整构建与打包工作流，详细规则见 packaging.md。
