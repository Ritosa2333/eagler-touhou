# TH03《东方梦时空》· DOSBox-X 性能版

TH03《东方梦时空》的浏览器单机、本地双人和联机项目。当前主目录为 `th03-netplay-lab`，运行内核已从 NP21 更换为 DOSBox-X / PC-98，沿用原有游戏磁盘、按键、连发、蓄力和对战设计。

提供中日文游戏、键盘／手柄／触摸操作、低速与判定点、原生暂停／认输、存档导入／导出，以及可选回滚联机。每台设备独立运行游戏，联机交换输入与状态校验；实际帧率与设备、浏览器和网络有关。

## 快速启动

需要 Python 3；服务器转发推荐 Python 3.10+。单机和本地双人需要支持 WebAssembly JSPI 的新版 Chrome / Edge。随附运行资源可以直接使用，无需安装 Node 或重新构建模拟器。

下载并解压完整项目后运行对应启动器，通过 HTTP 页面访问，不要直接双击 HTML 文件。

| 模式 | 启动器 | 默认入口 |
|---|---|---|
| 首页、单机、本地双人 | `start.bat` | http://127.0.0.1:9876/index.html |
| 直接打开单机 | `start-solo.bat` | http://127.0.0.1:9876/solo.html |
| 局域网联机 | `start-lan.bat` | 使用窗口打印的局域网地址，默认端口 9877 |
| 公网联机 | `start-lan.bat` + `start-public-tunnel.bat`，或部署公网服务 | 双方打开同一公网入口 |

单机启动器的实际端口以窗口输出为准。局域网启动时若 9877 被占用，应先关闭旧服务，再重新启动，避免继续访问旧版本。

### 局域网对战

1. 在电脑运行 `start-lan.bat`，保持服务窗口开启。
2. 电脑和手机连接同一局域网，双方打开窗口打印的局域网地址。手机不能使用 `127.0.0.1` 访问电脑。
3. 房主创建房间，向客机提供四位房间号；客机输入房间号加入。
4. 房主设置语言、难度、左右席位、回滚与低速策略；双方准备后由房主开始。
5. 在原游戏中选择角色并进入对战。

联机页保留房间号加入方式；“日志”按钮可下载最近约 10 分钟的本地运行记录，便于排查手机与电脑两端的问题。

2026-10-19 新增联机独立线程试用：开局前在房间页的“本机运行方式”选择“独立线程（试用）”，模拟、快照和校验在后台线程执行，页面处理输入、网络和音频。选择仅影响本机并自动保存；默认仍为兼容模式。已补充真实原生恢复、双端 WebRTC 和性能对照测试，主要观察到页面响应改善，推进速度未显示稳定提升，仍需实体设备联测。更新后双方刷新并重新建房，试玩后下载两端“日志”；`executionThread` 为 `worker` 表示实际启用。遇到问题可结束本局，切回兼容模式后重新建房。

公网直连使用 WebRTC / STUN，可配置 TURN；服务器转发使用 WebSocket / WSS。需要转发时先运行 `install-relay.bat`，需要 TURN 时运行 `configure-turn.bat`。TURN 凭据只保存在本机。部署与排障见 [公网联机说明](README-PUBLIC.md)和 [Relay 说明](README-RELAY.md)。

## 操作设置

单机模式在“启动原版游戏”旁提供“启用低速（按住空格）”和“低速时显示判定点”，可以在启动前设置；设置会保存，并与游戏内操作菜单同步。

单机默认使用方向键移动，Z/J 连发、Shift/K 蓄力、X/L 攻击、Esc 暂停；启用低速后按住空格使用。

本地双人的默认按键：

| 操作 | 本地 1P | 本地 2P |
|---|---|---|
| 移动 | 方向键 | WASD |
| 连发 | Z | J |
| 蓄力 | 左 Shift | K |
| 攻击／取消 | X | L |
| 低速 | 空格 | 左 Ctrl |
| 暂停 | Esc | Backquote（反引号） |

联机双方使用各自的 1P 操作，系统映射到房间分配的左右席位。键盘、手柄和触摸布局可在操作设置中修改；房间设置决定双方低速策略与触摸不限速许可。

## 内核与版本兼容

- 单机、本地双人使用 DOSBox-X JSPI。本地双人在支持的浏览器默认使用 Worker，单机保留线程选择。
- 联机使用完整 Asyncify 构建、确定性虚拟时间和固定 16000 cycles，按 60 Hz 同步输入。网页绘制次数与原生游戏帧率分别统计。
- 回滚保留 12 帧输入窗口，每两帧保存完整状态检查点；关闭回滚时不创建快照差分副本。
- 2026-10-14 迁入 TH04 的回滚优化：原生内存写入页面记录、批量保存／恢复变化页、复用快照缓冲；暂停、低速和触摸写入也记录页面。支持 WebAssembly 多内存时，仅开启回滚的联机使用新核心，旧浏览器使用完整复制回退。
- 2026-10-15 已将两轮核心优化接入普通启动入口：联机启用原生帧内调度、受保护同步解释器与分块 memcmp；回滚使用按组跳过干净标记的脏页扫描。显存查表默认关闭，保留完整解释器回退。固定 16000 cycles、零时间协作等待、原 RGB 呈现器和输入／音频确认规则保持。
- 选人／程序切换的暂停标记搜索使用只读 SIMD 批量比较，保持原检测时机；不支持时使用 JS 搜索。联机“日志”包含核心开关、资源版本和原始 CPU 计数，便于区分核心执行、回滚与切换开销。
- 战斗核心已接入 TH03 专用刷新等待循环优化：普通和回滚联机均可批量处理重复等待指令，保留周期预算和中断边界。通过两种核心共 1,724 组指令状态对照及恢复重放检查；实际战斗帧率仍需手动试玩确认。
- 同时操作的预测策略参照 TH04 调整：直连／中继统一预测 6 步方向，新帧最多预测领先 6 步，保留 12 步回滚历史。日志包含回滚次数、补算步数、预测领先量及等待原因。网络输入迟到时会更早等待；实机改善幅度尚待确认。
- 2026-10-17 联机音效也改为浏览器独立播放：游戏的 PMD 音效指令进入与 BGM 共用的确认队列，确认后触发本地原版音效，网络等待和模拟器音频清空不会截断已开始的声音。回滚丢弃预测事件，已确认事件不会重播；沿用原游戏音效优先级与单 FM 音效通道的替换方式。网络仍会影响新事件的确认时间。单机、本地双人的音频路径保持原样。
- 2026-10-18 参照 TH02／TH04 优化回滚存储：撤销数据保留在 WASM 内复用，避免与 JS 来回复制；一次恢复中，同一页只写入所需的最早旧值。完整内存和宿主快照对照通过，稳定复用的合成保存／恢复成本下降，首次分配仍可能更慢；这些数据不代表游戏帧率。日志的 `snapshotStorage` 显示 `resident page undo + merged restore`，实机效果由试玩确认。
- 2026-10-18 回滚联机新增开局固定输入缓冲：资源加载、身份核对完成后，双方各重新测量 3 次 RTT，使用双方中位数的较大值。RTT≤20 ms 仍为零缓冲；更高时采用 `ceil(RTT/2/16.667ms)+1` 帧，最多 6 帧，开局共同确认后整局固定。例如 80 ms RTT 通常增加 4 帧（约 66.7 ms）本地输入缓冲，以减少补算；不保证按键总延迟降低。启动中性输入覆盖缓冲，回滚启用时不缺帧、不覆盖已采样输入。关闭回滚仍使用原来的 2 帧确认锁步启动。日志包含实际缓冲、开局 RTT 和原始样本。仅做虚拟链路与合成状态验证，实体设备效果由试玩确认。
- 游戏文件从原始 HDI 提取，在 DOSBox-X 内置 DOS 中运行；原 HDI 的系统 DOS、VEM486 和 NP21 不参与执行。
- 当前联机协议为 `th03-rollback/6`，不能与旧 NP21 版或旧 DOSBox-X 协议版本混用。双方必须加载相同版本与资源，并重启更新后的联机服务。

更新项目后，关闭旧游戏页面和旧服务，重新运行本目录启动器、刷新页面并重新建房。启动窗口会打印实际服务目录和联机版本，可据此确认访问的是新版。

“性能与音乐状态”可查看模拟步数、模拟耗时、快照和画面提交情况；单机另保留“记录性能（15 秒）”功能。反馈问题时附上模式、语言、浏览器、回滚设置和页面错误即可。

本次通过原生辅助函数差分、26,292 项脏页扫描对照、独立内存／文件／原生全局恢复及发行资源校验，未启动游戏或浏览器自动试玩。TH03 的实际提速和手机／PC 联机仍待试玩确认，不能套用 TH04 的性能数字；合成扫描数据也不等于游戏帧率。“日志”下载含 `writeJournal` 字段，可判断该端是否启用了页面记录。核心构建来源、版本与五个匹配运行文件的摘要保存在 `web/vendor/dosbox-x/core-build.json`。

## 缓存与存档

镜像与内核资源按 SHA-256 校验并保存在 IndexedDB 缓存中；缓存损坏或不可用时重新下载。首次访问需要加载资源，后续可复用本机缓存。

联机新增 22 个原版音效，来自中日文共用的 YUME.EFC，由原 PMD.COM 在 DOSBox-X 中离线生成，使用 44.1 kHz 单声道 WAV，总计约 4.16 MiB。开局前预载、校验并解码，播放时不下载；已校验的预载字节直接交给播放器。资源缺失会在启动时报告错误。音效日志包含就绪数、播放／替换次数与活动状态。原生事件桥、确认／回滚去重、中日文磁盘安装和资源检查已通过；离线生成只运行声音驱动，未自动运行游戏或浏览器联机试玩。

2026-10-16 优化启动准备：单机并行读取镜像、辅助补丁、独立音乐和内核，本地双人并行准备镜像与内核；内核包装器也与资源读取并行加载。普通 HTTP 局域网页面的 SHA-256 校验改为按耗时让出执行，并减少每个数据块的临时数组分配，仍完整校验资源。资源测试模拟浏览器嵌套定时器等待，约 21 MB 镜像和联机内核的单项校验由约 5 秒降至约 0.4–0.6 秒；这是校验阶段的本机对照，整段启动时间及手机效果仍需实机确认。中日文单机音乐补丁的安装／导出结果与优化前逐字节一致，未自动启动游戏或浏览器试玩。更新后刷新页面即可使用。

运行时修改独立的磁盘副本，随附中日文原始 HDI.gz 保持原样。DOSBox-X 版使用独立于旧 NP21 版的存档数据库，浏览器存档也与访问地址和端口有关。旧版进度可通过存档导入／导出迁移；单机导出时恢复原版 MAIN。更换地址、清除站点数据或覆盖部署前，可先导出已有进度。

## 仓库上传与发布

本仓库按可直接运行的发布包组织。上传时必须保留：

- 完整网页与运行模块、资源版本清单。
- `web/disks/` 游戏镜像、`web/native/` 补丁、`web/bgm/` 音乐和 `web/sfx/` 音效。
- `web/vendor/dosbox-x/` 的 JS、WASM、许可证和来源说明。
- Python 服务、启动器、依赖清单与使用说明。

`.gitignore` 排除本地开发目录 `tools/`、`patches/`、`reports/`、`build/`、`vendor-source/` 和 `DEVELOPMENT.md`，以及虚拟环境、缓存、日志、备份、TURN 凭据和临时隧道地址。不要忽略所有 `.wasm`、`.gz`、`.com`、`.exe` 或 `.json` 文件，这些扩展名包含必要运行资源。

忽略规则只作用于未跟踪文件。若旧主分支已跟踪开发文件，可在项目目录执行以下命令，仅解除这些开发文件的 Git 跟踪，保留本机文件：

```powershell
git rm -r --cached --ignore-unmatch -- tools patches reports build vendor-source DEVELOPMENT.md
```

上传前用 `git status --short` 和 `git diff --cached --stat` 检查待提交内容，确认新的 DOSBox-X 运行资源已加入。主分支已包含本次优化，推送 GitHub 由维护者自行执行。

网页文本通过 `.gitattributes` 固定为 LF，原生 DOS 文件保持原始字节，确保 GitHub 下载包与 SHA-256 清单一致。不要用编辑器批量转换发布资源的换行符。

旧 `web/vendor/np2/` 为历史资源，当前入口使用 DOSBox-X；本次文档更新不删除历史文件。迁移记录见 [MIGRATION.md](MIGRATION.md)，其中独立目录的描述记录的是覆盖到主目录之前的状态。

本地开发与重建说明保存在 `DEVELOPMENT.md`；下载的发布包不包含开发工具和构建源码，普通游玩无需这些文件。
