# 原生移植版 UDP 联机

沿用 `../th01-multiorb-lab` 的浏览器联机方法：四位房间号、WebRTC DataChannel／ICE／STUN 打洞、可配置 TURN、备用 WebSocket 转发、双人／三人确认锁步。运行部分替换成当前 C++ 编译的 WASM 核心，不加载 DOS、磁盘镜像或模拟器。Windows EXE 仍为本地游戏；本轮联机入口在网页。

## 局域网

1. 在本目录运行 `start-lan.bat`。默认端口 **9874**，服务窗口会打印本机和局域网网址。
2. 所有设备打开同一个 `http://电脑局域网IP:9874/lan.html`。电脑测试可用 `http://127.0.0.1:9874/lan.html`。
3. 房主选择人数、难度、玉数、起始关卡、生命补偿、UDP 和输入缓冲，创建房间；队友输入四位房间号加入。
4. 全员准备后房主开始。自动校验版本并测量缓冲，进入所选关卡。普通关由任意玩家按射击开球。

“起始关卡”默认正常流程，从第一关开始；也可选择两条路线的普通关和全部 Boss，作为选关练习。大厅显示房主所选关卡，修改设置会取消全员准备。选关后以新开局的分数、残机和 Bomb 播放该关登场演出，之后照常推进；练习成绩不保存到正式联机排行榜。

需要 Python 3.10+ 和新版 Edge／Chrome。UDP 房间及信令服务仅需 Python 标准库。使用备用 TCP 转发时，先安装 `python -m pip install -r requirements-relay.txt`。手机可使用页面触屏按钮；网络允许设备访问服务端 TCP 9874，并允许浏览器建立 WebRTC 连接。

命令行：`python lan_server.py --port 9874 --no-browser`。默认绑定 `0.0.0.0`；仅在本机测试可附加 `--bind 127.0.0.1`。`server.py`／`start-web.bat` 仍是本地游戏静态服务，不能单独创建房间；本地页的“UDP联机”会指向默认房间服务。

## 操作

每台设备都使用 P1 键位控制自己的座位：←／→移动、Z射击、X御币、C Bomb。触屏同样自动对应本机座位。房主可在大厅轮换座位；角色颜色、独立残机／Bomb和幽灵救援沿用当前移植版。

网页联机额外启用两条规则，单人和本机合作保持原规则：

- 幽灵移速降低 50%，由每逻辑步 4 像素降为 2 像素；仍按全员确认的输入移动。
- 被 X 御币实际反弹过的白弹可以伤害玩家，最多再用 X 弹回一次；之后再次被 X 挡住就消除，不再反弹。接弹时御币判定优先；刚弹开的弹在离开出手者挥动范围前不会伤到他，离开后返回则可以。普通未反弹白弹保持原受击范围；幽灵仍不受伤。

任意玩家可按 Esc 请求暂停；只有房主可以操作菜单、恢复、选择路线、跳结算、续关、结尾快进和姓名登记。全员阵亡时房主可点击“全员续关”。所有普通关均等待任意玩家射击后同时开球和倒计时。

房间内不读取设备的单机成绩作为初始数据，保证入榜资格与菜单相同。完成登记后在每台设备的同站点 `localStorage` 中保存 `th01-native-net-scores-v1`，与单机的 `th01-native-scores-v1` 分开；联机登记可在本局结束后的成绩表查看。声音和音量只影响本机，点击“启用声音”后播放。

## 公网与 TURN

所有人访问同一个 HTTPS 网页／房间服务，入口为 `/lan.html?network=public`。自动模式使用默认 `stun:stun.cloudflare.com:3478`；LAN 默认仅收集本地候选。配置自己的 STUN 可重复使用服务端 `--stun stun:地址:端口`。

TURN 沿用旧版 Cloudflare 配置方式：在新工程目录运行 `configure-turn.bat`，配置写入本目录的 `turn-config.local.json`。旧工程的凭据不会自动复制。永久 API 凭据不放在 `web/`；浏览器在开始连接时通过经过房间身份认证的 `/api/ice` 获取临时 ICE 配置。未配置 TURN 时自动模式仍尝试 STUN 打洞，强制 TURN 会明确报错。

可使用已有 `cloudflared` 配合 `start-public-tunnel.bat` 为本地 9874 服务提供临时 HTTPS／WSS 地址；所有玩家使用它打印的同一个网址。隧道提供网页和信令，不提供 UDP 或 TURN。工具不会安装软件、配置路由器或修改防火墙。

固定部署时，把整个站点代理到同一个 `lan_server.py` 进程，保留外部 `Host`／`Origin`，为 `/relay` 开启 WebSocket Upgrade。房间存于内存，重启需重新建房；不做多实例负载均衡。公网可选择 `&ice=relay` 强制 TURN，或 `&transport=ws` 使用服务器转发。

## 同步与版本

三人采用房主连接两位队友的星形拓扑。可靠、有序的 DataChannel 承载输入；全员输入到齐才推进，不预测、不回滚。节拍为核心原游戏逻辑的 `440000 / 24830` 毫秒（约56.4步／秒）。自动缓冲实测至少5次探测后选择1～12步，三人计入经房主转发路径；测量超时采用LAN至少3步／公网至少6步。

仅当完整传输路径、抖动与4毫秒调度余量合计不超过一个逻辑步时，自动选择1步，比原来的最低2步少约17.7毫秒固定缓冲；其他连接保留原缓冲算法。推荐保留“自动”；也可手动指定1步，网络波动时会等待缺失输入，局中不会自动改变缓冲。

每120步核对战斗、菜单、结尾和成绩状态；最多允许240步未完成核对。版本或摘要不一致停止全局，不悄悄重置或改用本地模式。暂时 ICE disconnected 最多等待10秒恢复原连接；明确失败／通道关闭立即停局，缺失输入超过30秒停止。没有断线重新加入、主机迁移或局中换传输。

联机不再按负载主动降帧。支持的浏览器使用两个独立绘图线程，将软件绘图和画面生成移出输入／收包线程；保持原游戏约56.4步／秒，尽快显示每个已确认的新状态。绘图线程只接收状态副本，不推进游戏，也不改变弹幕或碰撞。浏览器不支持相关功能时使用主线程绘图，连接信息会显示实际绘图方式。

连接信息每5秒显示实际逻辑速度（正常约56.4步／秒）、本机画面FPS和绘图平均耗时，并分别列出输入／校验等待比例。逻辑速度正常但FPS偏低时，可先检查本机显示负载；逻辑也变慢、输入等待升高时，需要结合各端性能与连接延迟排查。同步等待也可能由队友设备忙碌造成，不单指网络线路。后台限速时段不计作活跃游玩的性能样本。

`tools/build.py` 会生成 `web/netplay/runtime.json`，将核心与同步适配器的SHA-256绑定。只修改联机JS时可运行 `python tools/prepare_netplay.py` 更新清单；发布时一起替换完整`web/`与服务端，全员刷新后重新建房。协议独立命名为 `th01-native-lockstep/1`，不能与旧DOS版混房。

`--qa` 仅用于开发验证，允许房主把诊断命令发送进同一输入队列；普通启动器默认关闭。源文件复用记录和详细测试报告保留在完整本地开发工作区的 `reports/` 中，不纳入发行白名单。

已在同机独立 Edge 进程验证真实双人／三人 UDP、三人 WebSocket、换座位、开球、暂停、独立 Bomb、普通换关、全灭续关、版本拒绝和失步全停。尚未验证跨路由器 NAT、真实公网 TURN、实体手机和长时间公网对局。
