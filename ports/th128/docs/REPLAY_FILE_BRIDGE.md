# 启动器的原录像文件接口

当前入口的list/read/write/remove/sync已连接游戏实际使用的OwnedReplayStore和原RPY codec。接口仅覆盖25个录像槽，路径为 `replay/th128_00.rpy` 至 `replay/th128_24.rpy`，按数字直接对应0至24槽。这是本适配器的确定路径映射，不是原版文件命名的考证，也不支持任意文件系统、重命名或无限数量的ud录像别名。

list返回上游要求的files数组，行含path/size及完整sha256；read返回原压缩文件的bytes数字数组。没有录像数据库时，list不打开或创建数据库；已有库先核全25槽的摘要和codec。任一损坏记录会使操作明确失败，避免把坏槽悄悄当空槽覆盖。缺少indexedDB.databases的环境当前报告不可用，不伪造空列表。

write在真正的目标槽进行摘要和原字节双重比较交换。文件经原codec及已有普通Replay兼容检查后，使用浏览器授予的strict事务，完整读取文件和元信息后才返回成功。相同文件不会重复写；明确的旧摘要可以替换目标，竞争更新失败不写到其他槽。remove同样经过CAS及strict事务，并读取确认目标已不存在。外部写入和删除只允许在启动游戏前；运行中可读取、列出和检查已提交录像。

sync核对实际已提交Replay记录，桥内每个写操作本来就等待严格事务和完整回读。返回明确的storeOnly:true、appliesToRunningGame:false；它不代表正在运行的原生游戏、分数、配置或姓名所有者已全部刷盘。页面继续报告fileBridge:false，并单独声明25槽Replay能力。其它存档和原二进制配置没有被JSON文件或空ACK代替。
