# 暂停回调的会话归属保护（618–620）

暂停菜单进入录像列表、保存姓名/录像或载入帮助图片时，会等待异步结果。原控制器只在回调之外检查是否关闭；回调已进入等待后，即使页面换了会话，仍可能调用新的原生模块、覆盖新的槽位/姓名状态，或上传过期帮助纹理。

618通过真实OriginalPauseController.step进入完整生产originalPauseConsumer，显式等待“已进入→仍挂起→更换/关闭→释放”，41项中复现25项失败、16项正常基线通过。另用完整生产帮助页加载函数复现：图片解码结束时旧会话已失效，仍尝试创建和上传纹理。

619的修改仅在三个前端源文件：

- 暂停消费者捕获原生模块、音频队列、动作、关卡选择和控制器身份；每次等待返回后复核归属，再绑定数据或确认保存。录像与姓名存储对象、槽位集合和姓名档案也必须仍是同一对象。
- OriginalPauseController支持可选的当前会话检查，在异步等待后、提交原生菜单动作前再次判断。默认行为保留；旧会话错误不再传到新页面，当前会话错误仍按原规则报告。
- 帮助图片载入器在纹理分配/上传之前检查当前会话；取消时仍在finally中关闭已解码位图。暂停消费者传入具体身份判断。

已提交到旧存储的事务可以完成；本修复不撤销已经写入的旧数据。它阻止失效回调继续确认原生状态或覆盖接替它的页面。

619同组41项全部通过。620在实际Git源码上验证新增41项、原生动作1/2/3/6前的8项归属检查，以及既有74项暂停、音频、EX、主菜单回归，共123项通过，0跳过、0stderr。

测试使用真实生产JavaScript，但原生接口、存储、DOM、图形接口和位图解码边界明确模拟；没有World、浏览器或物理GPU运行。不据此宣称整个音频生命周期、原生暂停对象退休、完整浏览器终局或设备验收完成。已成功的核心101和公开运行目录保持原样。

早期DSH回调测试遗漏了held Promise，且结果字段固定为false；其“3项RED”不作为验收证据。MAIN618原始失败与619/620结果分别封存。
