# 暂停音频资源交接（603–610）

旧菜单音频仍在等待 suspend/resume 时退出，可能让迟到的旧操作把声音队列重新指向已关闭的菜单上下文，或覆盖下一份菜单的音频。新的 MenuAudioGate 为每个声音队列保留独立交接身份，退休立即使旧入口失效，随后完成本次资源清理，新入口等待清理完成后才取得队列。

实现还覆盖“入口尚在等待上一份资源关闭、因此还没有 entry”的取消窗口。等待中的请求会被 leave 的代次变化取消，不再创建新菜单。

菜单 resume 另有独立的取消信号：即使它一直未完成，退出也能终止等待、关闭本次菜单并恢复游戏上下文。游戏 suspend 仍按顺序等待，防止它迟到完成后再次暂停已经交接出去的基础音频；真实设备上尚未完成的底层操作仍需另行验证。

## 清理规则与边界

- 每份菜单上下文只关闭一次，只停止属于它的声音通道。
- 只恢复当前仍由本次交接持有的队列，不用旧游戏上下文覆盖后继状态。
- 已关闭的游戏上下文不再调用resume；当前对象的真实错误仍保留。
- 已进入的Replay/画面消费者回调内部身份检查，以及遗留原生暂停菜单的退休证明，仍是独立待办。
- 如果游戏suspend本身不结束，交接仍等待它；本项只解除菜单resume阻塞，不假称所有设备Promise都有完成保证。

候选609继承600，产品只改 `site/runtime/sound.mjs` 的 MenuAudioGate。原生private100、其他已验收源码和公开运行目录不变。独立DSH只读审阅未发现本次范围内的阻塞问题，保留上述实际设备限制。
