# stage1 事件契约（oracle 对拍合同）

本文定义 wasi harness（移植侧）与 unicorn oracle（原版侧）共同产出的事件流格式。
**契约一旦合入，字段名、取值域、顺序与精度不得单侧变更**；需要扩字段时新增可选键并升版本号，
不得改写既有键语义。两侧产出按行全文比对：字节一致即通过。

依据：`docs/plans/ecl-vm.md`（VM/指令语义与锚点）、Ghidra 导出 `artifacts/decomp/jp/functions/*.c`
（0x41b260 分发器各处理块、0x40ffe0/0x40e840 弹幕生成、0x419450/0x4736a0/0x473780/0x419950 运动积分、
0x41fcc0/0x4183f0 建敌、0x420380/0x420d00 全局变量取值）、`oracle/machine.py` 直读验证记录。
本文所有「原版行为」结论均出自上述出处；标注【待校准】的条目是移植侧首版实现按反编译推定、
尚缺原版数值验证的部分，首轮对拍的预期差异点。

---

## 1. 载体与总则

- 文件：JSONL（UTF-8、LF 换行、每行一个 JSON 对象、行尾无多余空白）。
  移植侧路径 `web/artifacts/wasi/stage1-events.jsonl`；oracle 侧路径由 oracle 脚本自定，
  比对时以内容为准。
- 事件顺序：按 `(frame, seq)` 严格递增。`seq` 在每帧内从 0 重新计数，按事件产生顺序递增。
  同帧内 oracle 与移植侧的事件产生顺序必须一致（由下文各指令的执行顺序定义保证）。
- 比对：`diff` 逐行。浮点域见 §5；首轮允许的容差策略只存在于比对工具侧，不进入本契约。

## 3. 敌机身份与帧定义

### 3.1 敌机 id

- `enemy` = 原版 mgr 序号（DAT_004c2188+0xBC 计数器，0x418f40:96-99 逐次 +1）。
  stage root 敌机（承载 `main` 的隐形敌机）固定为 **0**，不由任何事件产生（它不是 enmCreate 造的）。
- 之后每次 enmCreate 族成功创建，`enemy` 取下一个序号（1, 2, 3…）。
- 脚本可寻址 id（gvar -9914 ID，字段 enemy+0x11E4）初值即该序号；`enemy_spawn` 事件不携带它，
  两侧如需可另行对拍。enemy+0x11E8（-9909）= 创建者的 +0x11E4（0x41fcc0:72 → 0x4183f0:61），
  moveEnm(432/433) 按 +0x11E4 寻址（0x417f40 链表线性查找，id 0 直接判空）。

### 3.2 帧定义

- `frame` = 敌机更新趟序号，从 0 计，共 3600。
- 第 0 帧 = stage 装载（root 创建）+ root 创建时的同步首趟更新（0x4183f0:65 在构造内直调
  0x41a8a0）。此后每帧为一趟 mgr 全量更新（0x418e00）。
- 趟内顺序（0x41a8a0，§3.1 of ecl-vm）：先运动积分后 ECL；对每台敌机执行
  「积分 → ECL 线程组 step(1.0f)」，按创建序遍历当帧开始时存活的敌机快照。
- 趟中途建出的敌机：在创建时刻同步执行一次完整首趟更新（构造内 0x41a8a0，含其 ECL 首步），
  其事件计入当前帧；下一趟起进入常规遍历。
- 敌机死亡（主线程结束 / 1 delete / 525 / 561 / 出界）当趟移出遍历表；不产生事件
  （本契约不含 despawn 事件），但其缺席影响后续事件。

## 4. 事件类型

通用字段：`frame`（u32）、`seq`（u32）、`type`（string）。以下按类型列出专有字段。
字段顺序即 JSON 键序（两侧一致）。

### 4.1 `enemy_spawn` —— enmCreate 族（opcode 300/301/304/305/309-312/321）

| 字段 | 类型 | 语义 |
|---|---|---|
| `enemy` | u32 | 新敌机序号（§3.1） |
| `routine` | string | 子程序名（指令名区原样，NUL 截断） |
| `x` `y` `z` | f32 | 出生坐标（游戏坐标系：x∈[-192,192] 以 0 为场地中心，y 向下为正，原点场地左上） |
| `life` | f32 | 解析后的第 3 参（life）；score/drop 不入事件 |
| `parent` | u32 | 创建者 enemy 序号 |

出生坐标规则（0x41fcc0）：opcode ∈ {300,309,321,311,304} 为相对（加创建者当前坐标），
其余绝对；创建者镜像位（0x100000）置位时 x 取负并翻转继承标志。
mgr 敌机数上限（+0xC4=99999）不构成窗口内约束。
309-312（enmCreateF 族）仅在 BOSS 槽 0 为空时创建；槽被占时**不产生事件也不建敌**。

### 4.2 `enemy_move` —— 400 族运动指令（opcode 400-439 命中已实现集）

| 字段 | 类型 | 语义 |
|---|---|---|
| `enemy` | u32 | 执行指令的敌机序号 |
| `op` | u16 | opcode 原值 |
| `args` | number[] | 指令参数**解析后**的值，指令序，个数为指令参数计数 |

- `args` 元素：浮点参数按 §5 精度输出（含 -999999 哨兵原样）；整型参数按整数输出。
  参数的 int/float 划分按 ecl-vm.md §4.2 各指令签名（405/429 = {int 时长, int 模式, float 角度,
  float 速率}，404/428 = {float, float}，…）。
- **参数取值时刻 = 指令执行时刻**（表达式栈已求值、镜像改写**之前**的解析结果）；
  404/405/406/407 的镜像翻转只作用于敌机内部速度状态，不反映在事件里。
- 已实现集：400/401/402/403/404/405/406/407/408/409/410/411/412/424/425/427/428/429/430/431/432/433。
  其中 425（moveBezier，模式 8）与缓动表 0x473a40 已对 0x422f80/0x4230d4 逐指令反汇编核对；
  412（moveRand）的象限分支按 0x41cdc2 反编译推定（RNG 次序：先 0x472e10，中段分支再 0x472c20）。
  出现集外 opcode（如 434-439 moveCurve）时 harness 以非零退出码失败（不静默），
  失败即契约缺口，先补实现再对拍。

### 4.3 `bullet_spawn` —— etOn（601）逐弹

| 字段 | 类型 | 语义 |
|---|---|---|
| `enemy` | u32 | 发射敌机序号 |
| `slot` | u32 | et 槽号（etNew 选定，0..7） |
| `way` `idx` | u32 | 双层循环下标：外层 way（+0x366 路数），内层 idx（+0x364 每路弹数） |
| `x` `y` `z` | f32 | 出生点（0x41d6b1：相对模式 = 偏移 + 敌机坐标；绝对模式 = f9c 三元组 + 偏移） |
| `angle` | f32 | 存入弹体的角度（0x40e840 经 0x472f30 归一到 [-π,π] **之后**的值） |
| `speed` | f32 | 弹速（路间线性插值后） |
| `sprite` `subtype` | u32 | et 槽 +0x15C/+0x15D（602 etSprite 设定的两元） |

- 每发一事件，循环序固定：`for way in [0, ways)` 外、`for idx in [0, count)` 内（0x40ffe0）。
  `count ≤ 0` 或 `ways ≤ 0` 时不发。
- 角度公式按 et 模式（0x40e840 的 sVar5 = et+0x368，607 etAim 设定）：
  - 0/1：扇形。count 偶：`a = angle2*0.5 + (idx/2)*angle2`；count 奇：`a = ((idx+1)/2)*angle2`
    （整数除法）；idx 为奇数时 a 取负；模式 0 再加 aim；最终 `a = angle1 + a`。
    模式 0=aim（aim = 自出生点指向玩家的 atan2，重合时 π/2），模式 1 不 aim。
  - 2/3：整圆。`a = angle2*way + angle1 + idx*2π/count`；模式 2 先置 a = aim，模式 4 同 2 但再加
    `π/count`，模式 5 同 3 加 `π/count`（模式 4/5 不在 st01 窗口内，实现同公式）。
  - 6：`a = angle2 + RANDF()*(angle1 - angle2)`。
  - 7：速率随机 `speed = RANDF()*(speed1 - speed2) + speed2`，角度同模式 3。
  - 8：两者都随机。
  - 9/10：环形扇。`a = angle2*0.5 + (way/2)*angle2`（ways 偶）/`((way+1)/2)*angle2`（奇），
    加 `idx*2π/count`，way 奇数时取负，模式 9 加 aim，最终 `a = angle1 + a`。
- 速率：ways < 2 时 = speed1；否则 `speed = speed1 - (speed1-speed2)*way/(ways-1)`。
- RANDF() = GameRandom 下一值按无符号 × 2^-32（0x472de0）。
- etNew（600）后槽默认：angle1=0、speed1=2.0、count=0、ways=1、offset=(0,0)、模式 0。
- 出 生点含自旋偏移（et[9]≠0 时位置加 polar(角度, et[9])）：窗口内 st01 未用，公式备而未验【待校准】。
- 弹体后续行为（etEx 609-612 的角速度/加速度块）不属于出生事件；etEx 的「类型 2」出生反偏
  （0x40e840 位置减 4×速度）未实现【待校准：字段定位未定，st01 dump 审计未见其触发】。
- 激光（700-714 族）产生的弹不在本事件集：激光指令（含 702/703 laserOn）在 harness 中放行
  脚本流程但不产生事件，oracle 侧同样不导出激光弹。激光弹纳入事件集时需双方同步升版本。

## 5. 数值精度

- 坐标/角度/速率一律 **IEEE754 binary32**，序列化为 9 位有效十进制数字（C `% .9g`，
  即 `%.9g`；float32 往返无损，FLT_DECIMAL_DIG=9）。例：`1.57079637`、`-0`、`192`。
- 整数字段（frame/seq/enemy/op/slot/way/idx/sprite/subtype/整型 args）按十进制整数输出。
- 三角/反三角内部以 double 计算后舍入到 f32（对齐 x87 long-double 中间精度；
  与原版可能存在 ≤1ulp 的尾差，是首轮对拍的预期噪声源，见 §6）。
- 每帧积分后坐标按 `floor(x*100)/100`（向负无穷，0x497690 SSE2 主路径 + 0x473780 尾部）量化到 0.01；
  实测 -163.783264 → -163.79。

## 6. 首轮对拍预期差异点（【待校准】汇总）

1. GameRandom 种子（§2）：未知原版关卡起始种子，先取 0；种子不符将导致所有含随机的
   `args`/角度整体错位。
2. 弹幕近距剔除（§2）：未实现。
3. etEx 类型 2 出生反偏（§4.3）：未实现。
4. movePosTime/moveVelTime 的 delta(7)/decel(17) 特殊模式未实现（harness 显式失败）；
   st01 窗口内仅用到缓动 0/1/4（0x473a40 表，已逐 case 对照）与贝塞尔模式 8（已对
   0x4230d4 反汇编核对权重与累加次序）。
5. moveRand(412) 的象限选择分支与近垂直修正按 0x41cdc2 反编译推定，未经数值验证；
   moveCurve(434-439) 未实现（窗口外，命中即失败退出）。
6. 525 enmKillAll（及 518 dialogRead 共享的清场尾块）：0x41ac70 的 flags 门控销毁——
   `(bit5/7 全清 且 0x400/0x800000/0x1000000 全清) 或 bit8 置位` 者当帧 0x41aad0 销毁
   （0x417b10 抽 1 次 GameRandom）并标 0x4000000 待摘；main/MapleEnemy/EtBreak 的
   ins_502(32)（bit5）与 BOSS 位（512 置 0x1000000）豁免。首轮曾按「514 标签 restart」
   近似，已被 oracle RNG 逐帧对拍推翻。
7. 309-312（enmCreateF）仅在 BOSS 槽 0 为空时创建（0x41b2dd）；BOSS 槽管理按 512 的
   set/clear 近似（负参清除指向自身的槽）。

### 7.2 自机模型（两侧同式实现；移植 C++ / oracle python 孪生）

全部整数运算，两侧无浮点舍入差：

- 位置定点 1/128（原版 player+0x5c4/+0x5c8，0x442960）：`pos += speed128 × dir`，
  `dir` 为 0x4abc30 单位向量表（斜向不归一，8 方向），speed128 按 (focus, 斜向)
  四选一（0x442960:96/0x441eae）。钳制 x∈[-23552,23552]、y∈[4096,55296]
  （±184.0 / [32.0,432.0]）。对外浮点 x/y = 定点 × 0.0078125（2 的幂，无损）。
- 自机弹【待校准——弹型表 pl02a.sht 定义域未完全接入，参数为定标值】：
  Z 按住时每 4 帧一轮 3 发（x 偏移 -8/0/+8，y-12 起步，垂直向上速度 12，
  伤害 12/发，弹体半宽高 4）。敌机 hurtbox（500 指令，+0x110/+0x114）与弹体
  做 AABB 重叠判定（0x446870 同式：|dx| ≤ (ew+sw)/2 且 |dy| ≤ (eh+sh)/2）。
- 击破：敌机 life（+0x3f4c，整型）逐击扣减；<1 即死。移植侧标 dead 并清
  boss_slot 指向；oracle 侧写 +0x4030 |= 0x4000000 并清 mgr+0x5c[slot]
  （slot = 敌机 +0x4040）——两侧摘链都发生在下一趟 mgr 遍历。
  击破不抽 GameRandom【待校准：原版 0x419a90 掉落路径的 RNG 消耗未建模】。
- 中弹（移植侧内部实现，不进入事件流）：自机判定半径 3，与敌弹（半径 4）/
  敌机本体（半径 20 近似）圆测；中弹后原地复活 + 240 帧无敌、清屏内敌弹
  实体。两侧内部近似独立——中弹只影响不落事件的内部状态（灵力/命数/弹体
  实体），玩家位置与射击节奏不受影响，事件流不受中弹影响；oracle 侧无弹体
  推进故不做此测。死亡同样不影响关卡时间线（main 纯时间推进）。

### 7.3 新事件类型（键序固定）

- `player`：每帧一条。`{"frame","seq","type":"player","x","y","state"}`
  —— x/y 为 f32（§5 精度），state = 该帧回放输入 u16 原值。
- `kill`：`{"frame","seq","type":"kill","enemy","x","y"}` —— 自机弹击破
  （bomb 击破同型，bomb 本窗口未使用）。
- `boss_op`：敌机执行 511/512/513/514/521 时逐条。
  `{"frame","seq","type":"boss_op","enemy","op","args":[…],"name":"…"}`
  —— args 为指令整型参数解析值；name 仅 514/521（指令名区尾串，NUL 截断），
  其余为空串。Boss 第一非符开始帧 = Boss 敌机（512 置槽者）创建后首条
  op=513 的 frame。

### 7.4 已知保真缺口（回放模式【待校准】汇总）

1. 对话时长（§7.1）：真实回放中 518/519 对话按输入推进，模型里为 0 帧。
   Boss 出现帧 = 真实帧 − 对话帧数；两侧一致但相对原版整体前移。
2. 自机弹型/伤害（§7.2）：非 .sht 定义域；击破帧随模型定标漂移（含中 Boss
   击破 → main 的 520 释放时机），两侧同漂移。
3. 击破 RNG 消耗（§7.2）：掉落（神霊/道具）事件与 RNG 序列未建模——含
   掉落数量、灵力增长、威力升级链。0x419a90 全路径（计分/掉落/符卡结算）为
   oracle 空转桩，后续轮次接入。
4. 514/521 符卡计时器（0x4218f0 引擎）不步进：本窗口中 Boss 在计时器到期前
   必然被击破（录像 Z 持续按住，实测 10420/11064 帧），超时跳转未触发。
5. ~~残余 1 ulp 分歧~~（第 2 轮已闭合）：首轮归因于 async 首步可见性是
   误判——e77/e78/e80 三点复验表明 ins_86 输入两侧恒为各自量化出生点，
   偏差全部出自 SquareSumRoot 的舍入链（见 §7.5）。修正后全窗（10662 帧/
