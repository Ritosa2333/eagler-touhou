## 0. 结论先行

「自机孪生模型分歧」实为**两层问题的叠加**，都不是 10553 帧才发生：

- **层一（S4 直接拦路虎，本轮新发现）**：移植侧提交 `74f54c1a`（10-22，
  「自机弹弹型域接入」）把 StageBattle 的出膛模型从「三发 ±8/-12」换成
  「.sht 主弹 ±10/-8」，**oracle 侧 python 孪生未同步** → 双孪生从**帧 105** 起
  事件流失配（th13_01）；udSr01 基线同样回归（首分歧帧 124）——HANDOFF 所载
  「10662 帧一致」是 74f54c1a 之前的旧状态（旧产物 th13_01-events.jsonl 63541 行
  与今 oracle 逐字节一致可证）。
- **层二（孪生对原版的系统性偏差，HANDOFF「10553 才击杀 MBoss」的真相）**：
  原版 ReimuA 主弹 = **每 3 帧 2×24 伤**（≈16.0 伤/帧，sht 记录 +0x18 伤害域直读，
  0x446000/0x445c40 字节级），双孪生均为**每 4 帧 36 伤**（9.0 伤/帧）——
  **欠 DPS 约 44%**，故无论哪侧孪生击杀 MBoss 都显著晚于真机。MBoss（enemy 75，
  帧 2381 出生）击杀帧三方：python 孪生 **10553**（=HANDOFF 数字）、port 新模型
  **9849**、真机更早（真机值待视频锚定，见 §5 待解）。

## 3. 原版自机更新/发射语义（反汇编直读，对照孪生差异）

### 3.1 sht 弹型域布局（pl00a.sht 字节实证，0x443e40 解析）

- 头：+0x02 u16 块数（11）；+0x20 i32 聚焦块偏移（4 → 聚焦块 = power 块+1+4）；
  +0x24 被运行时改写为 **100**（0x441dd0:52）= 每档功率步长；
  `DAT_004be7f0 = 100`、`DAT_004be7ec = 100×4 = 400`（功率上限内部值）。
- 指针表 +0xc8（块数项，相对 +0xf4 基准）；记录 0x38 步、首字节 i8<0 终止：
  `+0 u8 间隔(=类别)`、`+1 u8 相位`、`+2 u16 plXX.anm 脚本`、`+4/+8 f32 x/y 偏移`、
  `+0xc/+0x10 f32 速度域(48/16)`、`+0x14 f32 角度`、`+0x18 f32 伤害`、
  `+0x20 i8 卫星锚位(0=自机)`、`+0x21 u8 类别复核(2=特殊)`、`+0x28/2c/30/34 id→指针`。
- pl00a 实值：块0/5（功率<100 非焦/焦）= 2 主弹 ±10/-8 伤24 角-90°；
  块1/6 起加类别 8 卫星弹；块10 = 特殊（类别 2）。

### 3.2 发射链（0x4460d0 → 0x446000 → 0x445c40）

- **0x446000:12-26**：块号 = `DAT_004be7e8(功率) / 100`；聚焦再 `+1+4`；
  `be830&0x100`（特殊态）恒用块 10。每记录：**`帧计数 % rec[0] == rec[1]` 才出膛**
  ——帧计数源 = 玩家 ctx+0x146cc（0x4460d0:88 传参；0x441dd0:60 初始化 0，
  复位时机待 oracle）。类别 2 需对应卫星槽空闲。
- **0x445c40（出膛）**：伤害 = rec+0x18（:55）；速度域 rec+0xc/+0x10 →
  0x4457e0 弹体运动构造（:114；垂直弹近似下的实际速度=48 还是 48/4 待 oracle）；
  位置 = 玩家 + (rec.x, rec.y) − **ANM 精灵锚点**(shot vm+0x60/100, :79-80)；
  角度 ≥995/1000 = 卫星/敌瞄准特殊（:56-70，伤害翻计算 :68）。
- **0x442960（移动）**：方向表 0x4abc30（8 字节/项 dx,dy，斜向不归一）；
  聚焦 = held bit3（:81）；速度 = sht+0x10..0x1c 四浮点 ×128 截断 → +0x5cc/
  +0x5d0/+0x5d4/+0x5d8（0x441dd0:45-52 链式解包，**python 字段序正确**）；
  **魔理沙（be7b8==1）且 be830&0x100 时速度×1.5**（:139-146）；**速度乘
  DAT_004c0a28（游戏速率）**（:262-263）后经 64 位除法入定点累加（:269-271），
  钳制 ±0x5c00 / [0x1000,0xd800]（:272-283）；+0x5b8/+0x5bc = 定点×0.0078125。
  初态 (0,400)（0x441dd0:40-43）——孪生正确。
- **0x448200（回放输入）**：u16 三元组（态/按下/释放，6 字节/帧）→ 0x4e4c08；
  0xffff×3 终止符 → 清输入并 **FUN_0043e5a0（结算A！）**（:20-25）；每 30 帧
  推进慢速字节指针 → 玩家回放 ctx+0x20c（:34-37，消费方待锚）。

## 4. 修复建议（不动手，按优先序）

1. **恢复双孪生一致（S4 解锁最小改动）**：两侧统一到任一口径。
   - 快路：`oracle/replay_model.py` `PlayerModel` 增加 sht 弹型域解析（0xc8 指针表/
     0xf4 基准/0x38 记录/终止符），出膛 = 主弹列（类别 3）× `36/mains` 伤、
     位置 rec.x/rec.y、间隔仍 4——与 `StageBattle::fire_shots`（StageBattle.cpp:
     140-183）逐语义对齐；`stage1_oracle.run_replay` 的 `apply_shots` 同步弹几何。
   - 回退路：port 恢复三发近似直至方案 2 落地（不推荐，几何已更接近真机）。
2. **对齐原版语义（正确修，消除层二）**：两侧同时改——间隔改「帧%rec[0]==rec[1]」
   （帧计数=对局帧，自 0 起的相位对齐需 oracle watch 0x446000 入口实证）；
   伤害改 rec+0x18；块公式改 `power/100`（孪生功率演化未建模前固定块 1 =
   初始功率 1.00 的真机状态，并在契约文档标注「块1 口径」）；速度域 48/16 的
   垂直等效值待 oracle 实证后替换定速 12；卫星弹/特殊块分期。
3. **孪生退役（长线，随 hud-capture-plan 落地）**：battle_oracle（真场景机
   驱动）下直接跑原版 0x442960+0x446000+0x445c40+真实碰撞（0x448200 注入
   回放输入），python 孪生降级为交叉检查——层二问题自然消失，MBoss 击杀帧
   可直接与真机视频锚点核对。
4. **契约/回归件**：①把 th13_01 st01 双跑比对纳入回归（当前只有 udSr01 旧产物，
   且已失效——本轮证明了「绿基线」会因单侧改动静默腐烂）；②stage1_compare
   对「事件数不同」的窗应显式报 total 差（本轮 58190 vs 63541 差 5351 行，
   首分歧后即失配——工具行为正确，报告里补充总量差更醒目）；③udSr01 的
   7 段慢速窗（帧 30-11010，≤50/60）登记入覆盖矩阵「未建模」清单。
5. **修后验证门**：th13_01/udSr01 双窗 `first_divergence_frame=none` + MBoss
   击杀帧两侧一致且**早于 10553**（DPS 修正后应显著提前，具体帧待跑）。
