# 界面语言与消息编译

界面词库使用 Paraglide，提供 `zh-CN`、`en`、`ja`。React 通过 `LocaleProvider` 传递语言，服务通过 `translateUi(locale, key, params)` 显式指定语言，共用编译后的消息与插值。

## 新增和修改文案

在 `messages/keys.json` 登记语义键、编译标识和参数，并补齐三份语言文件。标识和参数声明必须唯一；各语言使用相同参数。作品名、用户输入和协议标识由各自数据来源提供。

组件使用 `useLocale().t`，服务使用显式语言入口。兼容接口 `UI_MESSAGES` 供检查词库使用。新增控件的正文、提示、空状态和可访问名称一起进入词库。

## 页面地址

中文主页为 `/`，英文为 `/en.html`，日语为 `/ja.html`。共用页面通过 `lang` 参数表达语言。语言切换使用替换历史操作，并保留当前作品、其余查询参数的编码和片段。

`localeHome` 选择主页地址，`uiLocaleSearch` 更新语言参数，`withUiLanguage` 为共用页面和帮助链接传递语言。界面语言与游戏资源语言分别维护。

## 帮助正文与错误

FAQ、首次使用须知、联机说明和关于页的三语正文也来自词库。修改中文 Markdown 或静态正文后，先运行 `build:content`，再更新三份正文消息。检查器核对生成正文与中文词库的一致性。

富文本经过共用清洗器，再为站内帮助链接补充语言。运行时发现运营者修改过正文时，展示实际内容。关于页的徽标由站点品牌模块管理。

兼容说明提供独立的中文、英文和日文 HTML，诊断脚本保持 ES5。构建器读取词库中的无参数文本，并校验它们与 Paraglide 编译结果相同；页面可以独立加载。LF 与 CRLF 输入共用相同的解析偏移。

已知运行错误在展示处显式传入翻译函数。服务判断和诊断记录使用原始错误，复制的堆栈与上下文保留实际文本。

## 构建与开发

在 `launcher/` 运行：

```sh
bun run i18n:compile
bun run i18n:check
bun run typecheck
bun run build:launcher
```

开发服务器、类型检查、服务编译和发布构建共用生成入口。编译器和消息格式插件来自锁文件管理的本地依赖。

生成版本按输入与产物哈希校验。新版本完整生成后，原子切换消息入口；失败时继续使用上一完整版本。不可变生成目录允许已有模块完成执行，也适用于 Windows 目录监听。三语词库、消息映射、编译配置和依赖版本都参与服务缓存身份。

生成文件由工具维护。当前按语言生成模块，并显式传递语言。将来引入运行时 SSR 时，服务端继续沿请求传递语言，使用与请求隔离要求匹配的编译配置。

## 验证

`i18n:check` 检查键、参数和错误映射。迁移期间另外运行 `bun run i18n:check:migration`，核对原有中英文文案；日常文案修改使用常规检查。

文案审计覆盖用户界面的正文、反馈和可访问标签，跳过脚本和样式代码。游戏原生按键、图表缩写与作品标记按文件登记理由。开发用 UI 手册固定中文，独立声明语言，不计入三语界面。已登记错误保留原始诊断，在显示边界翻译。

语言入口与离线图通过冷构建验证。浏览器验收覆盖语言菜单、刷新、单机与大厅往返、带查询参数的选项栏、输入设置及帮助链接。长文和窄屏布局按实际渲染结果核对。

接口参考：[Paraglide 编译](https://paraglidejs.com/compiling-messages)、[编译选项](https://paraglidejs.com/compiler-options)。
