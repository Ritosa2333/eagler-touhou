## 方法

基线为网页对应提交 `85941f0d56` 的当前 Flutter 验收稿。工作副本对本机记录的 origin/main 落后 8 个提交，本轮不包含那 8 个提交。SDK 3.50.1 与锁定依赖不变。

测量运行真实 Windows 窗口、生产 main 入口、完整打包目录和本机现有游客状态。原始两轮未连续记录前台焦点，测量应按显示窗口条件理解。Release AOT 使用 FrameTiming，动作时间窗外的帧被排除，并等待发布模式分批回报。桌面客户区为 1898 × 1069 物理像素，竖屏为 563 × 1255，DPR 1.5。165 Hz 的单阶段预算约 6.061 ms。这些是构建、渲染及流水线耗时，不等于屏幕实际呈现 FPS。两轮最终运行同一可执行文件。

Skia Profile 使用完整轨迹归因，Release 独立运行并比较耗时。原版整轮在竖屏抽屉测试定位器处中止，表中只使用此前完整结束的操作；最终定位器通过实际 DrawerButton，两轮均完成 32 类操作。

## 启动与内存

预热把编译工作移到首次交互前，高性能 GPU 也可能增加耗电及初始化等待。最终两轮 app.main 耗时分别为 945.648 / 192.942 ms；整改前一次样本为 54.789 ms。前后 await 的绘制工作不同，缓存及驱动状态也不同，这组数不代表整个进程到首屏可用时间的差值。

完整回归中工作集峰值为 634.7 / 626.8 MiB，结尾图片缓存约 19–21 MiB。此处包含驱动共享映射和测试入口，不能把它当 Dart 堆大小或常规应用的净内存，也不能凭两轮记录判定长期无泄漏。末尾回到书架后 2.5 秒窗口两轮均为零界面帧。普通入口的独立空闲测量分开记录在 normal-idle.json、normal-idle-disconnected.json 和 normal-idle-foreground.json。静止书架曾测得约 0.35–0.41 个 CPU 核心；断开检查后一个样本为 0.0042 个核心，但它没有同步记录焦点，不能单独归因于检查连接。明确激活窗口后的对照约占 0.29–0.40 个核心，最后一轮 10 次窗口状态采样均确认处于前台。消息计数的 10 秒窗口收到 10,518 次 WM_GETOBJECT，而 WM_NULL 为 84 次，开销集中于 Windows 主消息线程及 UIAutomationCore 工作线程。查询发起进程尚未确认，系统跟踪因权限不足未能启用。没有禁用无障碍功能或加入消息延时。零界面帧不等于低 CPU 开销。

## 回归与画面

最终静态分析通过。新增及受影响功能 70 项通过，1 项真实 th09 存档样本检查因未提供环境输入而跳过。此前完整 UI 回归 216 项通过，覆盖返回、中断、排序、hover、设置、房间、导入、语言与竖屏。最终另重跑大厅及生命周期场景并重采大厅图。

## 范围与后续验收

首次详情仍有约 23–25 ms 的孤立慢帧，竖屏第一次切栏也有约 40–49 ms 的渲染峰值。滚动与快速反向切栏在本机 Windows 呈现链路上存在波动。本轮改善了已定位的绘制和计算开销。显示窗口的高频无障碍查询来源及相关 CPU 开销仍待定位，尚不能表述为全场景无卡顿。

[逐职责开销清单](cost-inventory.json)区分实际测量和源码核对。真实登录后的大响应、繁忙房间、持续语音、浏览器子进程长期内存、耗电、其他 GPU 与平台设备帧率，需要对应真实输入继续测量。游戏本体为原生占位，未纳入启动器帧率。
