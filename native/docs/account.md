# 账号统一使用正式站网页

个人主页和全部账号界面由 `https://touhouonline.com` 提供。原生启动器负责入口，停止维护第二套 Flutter 表单、资料页、裁切器和关系列表。

| 功能 | 正式站地址 |
| --- | --- |
| 登录 | `/login.html` |
| 注册 | `/login.html?mode=register` |
| 找回密码 | `/login.html?mode=reset` |
| 当前账号资料 | `/profile.html` |
| 公开个人主页 | `/u/:username` |
| 账号安全 | `/u/:username#security` |
| 资料编辑、头像和封面裁切 | `/u/:username#edit` |
| 关注 | `/u/:username?social=following` |
| 粉丝 | `/u/:username?social=followers` |
| 好友 | `/u/:username?social=friends` |

地址以现有网页路由及账户组件为依据。入口携带启动器当前语言，保留合法的查询和片段。账号页面只向正式站请求。

## 迁移验收

- 从账号菜单、手机主页、单作好友、玩家卡和需要登录的动作进入，均到达对应网页。
- 网页关闭或返回后，原生书架、大厅、详情和设置的状态不发生跳变。
- 登录、退出和会话失效必须核对网页与原生功能的实际身份。系统浏览器与原生网络客户端不会自动共享 Cookie。
- 云存档、消息和房间依赖的身份衔接单独验证，不能把打开登录页视为登录完成。

已接入应用内网页路由，并归档旧 Flutter 页面、专用测试、工具和资源。网页与原生通过系统 Cookie 接口传递会话，再调用正式站现有 get-session 接口验证身份。登录和退出后刷新原生身份；Cookie 不经页面 JavaScript 读取。

容器采用 [InAppWebView](https://inappwebview.dev/docs/webview/in-app-webview/)，锁定包含官方 Linux 实现的 6.2.0-beta.3。Windows 使用 WebView2，macOS、Android 和 iOS 复用系统引擎，Linux 使用 WPE WebKit。Windows 的数据目录位于应用支持目录，不写到安装目录。其他平台沿用引擎的默认会话，使网页与 Cookie 管理器指向同一存储。Linux 系统依赖见[平台配置](platforms.md)。网页文件上传、头像／封面裁切、实际登录退出和设备返回仍需真实 WebView 验收。

原生会话初始化到网页时，Cookie 写入必须成功才显示网页。初始化失败可重试；关闭失败页面不会以空 Cookie 清除原生登录态。

## 原生容器

| 编号 | 行为与布局 | 验证边界 |
| --- | --- | --- |
| AUTH-WEB-01 | 账号入口携带当前语言，保留查询与片段；旧原生账号地址映射到上述正式站地址。历史与加载通知合并 100 ms 后核对当前网页地址，后续事件取消旧结果；主框架的直接导航即时处理。 | 已验证地址、来源、旧路由，以及网页请求、加载和历史地址变化三种入口，覆盖初始化、响应式更新和晚到地址读取。 |
| AUTH-WEB-02 | 48 px 标题行左侧返回、右侧关闭。返回先走网页历史，无历史时恢复发起页面；关闭直接恢复发起页面。退出前若被另一页覆盖，恢复可操作状态，返回后可以再次关闭。网页进入原生页面时先关闭账号覆盖页，再执行原页面的离开检查；取消离开后原页面继续可用。 | 按钮和系统返回有五个平台样式检查。iOS 路由侧滑的取消、完成及减少动画已通过控件检查；有网页历史时交由系统 WebView 手势，仍待真机验收。 |
| AUTH-WEB-03 | 标题下固定 2 px 进度区；初始化显示等待，失败显示重试。正文避开系统安全区。 | 控件检查覆盖等待、初始化失败和关闭。普通 Release 已核对 320、375.33 和 1265.33 逻辑像素的实际登录表单与内容尺寸；网页驻留时关闭整个窗口出现原生异常，列为未通过。[实窗与关闭记录](../archive/performance-audit-20261128/report.md#最终-release-账号页与关闭异常) |
| AUTH-WEB-04 | 从系统 Cookie 存储读取会话并由现有服务确认。服务轮换的凭据回写网页；同账号返回也刷新关系与存档订阅。 | 已验证安全属性、轮换、晚到响应、存储失败和同账号刷新。 |
| AUTH-WEB-05 | 网页及 Cookie 管理器共用平台会话。外部地址交给系统浏览器，凭据只用于正式站。 | 已验证其他来源不创建账号引擎。书架、作品、大厅和邀请地址复用原生路由，账号资料、社交及其他网页栏目继续留在网页。Windows 已实测隐私链接的新窗口回退及 History API 事件；其他系统引擎继续按平台表验收。 |
| AUTH-WEB-06 | 登录、资料、裁切、关系列表和账号安全全部由正式站实现；原生不另设表单或裁切器。 | 旧实现已归档。文件选择、上传、登录退出仍待真实引擎验收。 |

本次没有新增后端或登录协议。旧注册、验证码、改密、资料编辑及关注操作的原生客户端已归档，活动客户端只保留核心和配套功能实际使用的身份、头像、消息、云存档及房间请求。

本轮 85 项账号与链接专项、41 项主导航、10 项主界面、31 项云存档与进度及 91 项截图检查通过，共 258 项。该轮因缺输入跳过的 th09 真实文件往返，现已使用与原记录校验值一致的样本单独补验通过，见[原档复核](cloud-saves.md#th09-原档往返复核)。六部作品的真实存档已核对原文件校验值。Windows 实窗验收另验证三种窗口宽度下的返回布局，以及正式站注册页隐私链接和浏览器历史事件。[验收记录](evidence/account-web.json)

原生地址复用现有作品、邀请解析。网页的 `index.html`、`en.html`、`ja.html` 与根地址统一进入书架；`lobby` 和 `lobby.html` 进入大厅。资料编辑与关系列表继续使用正式站。插件负责新窗口链接的单窗口回退，容器共用现有外链入口。实际登录退出、上传、裁切和其他系统设备行为按验收记录继续核对。
