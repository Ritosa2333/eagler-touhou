# Flutter 界面修改

- 修改前读取对应页面规格，核对固定版网页与 Pencil。明确本次采用的参考、状态和视口。
- 评估当前 Flutter 界面前，查看 `docs/evidence/current/README.md` 并运行 `node tools/check-specs.mjs --current` 核对截图与源码。历史图只作历史对照，缺少当前图时先重拍。
- 既有分组、信息层级、元素位置和操作含义属于设计约束。组件替换沿用这些约束；调整约束须先向用户展示具体方案并取得明确同意。
- 优先组合现有公共组件。第三方组件承接交互行为，页面大小、间距和对齐按页面规格配置。
- 视觉修改交付同视口、语言、主题和数据的整改前后图。先检查整页层级，再检查元素大小、间距与可见字形对齐。逐项说明与参考的差异。
- 截图回归基准须来自用户认可的设计；不得因为测试通过，就把当前实现自行升级为新设计基准。新要求与旧稿冲突时说明具体冲突。
- 回归该页的窄屏、长文本、滚动、返回、键盘和减少动画。测试结果与视觉审查分别记录。
